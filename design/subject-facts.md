## 三、⚠️ 判准：不是「有没有状态写入」

跟 GPT 定的，这一句是这一族最要紧的判准：

```
✗ 是否存在状态写入？
✓ 【结果事实是否存在与其语义相称的承接？】
```

后者比「主体身上有东西」强得多，**而且不会把「亡」「杳」这种离散状态
误判成缺少程度值**。

### 承接至少有四型（`debt` 那条链一次给全了）

```
程度型          health 42 —— 他还活着，而此后每年更可能走
状态型          fate '殁'
状态 + 标记型   fate '杳' + flag father-missing
状态 + 认知型   编年「父亲再也没有消息了」
```

**一个完整的承接可以终止于 `fate`，也可以终止于 `doing`、关系、`flag`、编年。**
所以**不能拿「可量化的 health」当模板**。

## 四、「链」是什么：三层分开记，不揉成一条

```
事件因果链   天旱 → 借债 → 出外做工 → 归来／亡／杳
状态承接     归来 → health 42 → frailty 每年现读
认知承接     正文怎么表达这些事实
```

**发现某条链只有事件承接、没有状态消费时，能精确说出缺的是哪一层，
而不是笼统地判「链断了」。**

### 连接件是两种，而两种都不是机器可查的

```
旗标        共享状态证据      drought / father-in-debt / father-away
分路键      一次掷出来的      father-fate：归 62 / 亡 24 / 杳 14
```

**链不能只靠旗标，也不能只靠同一承受者**——旗标是共享状态证据，
同一承受者是主体一致性证据，两者都要跟明确的承接关系结合。

## 八、⚠️ A 不是标准答案，是校准案例

审完 A（`debt` 那条链）之后，我手上是一个正例、三个负例、一条判准。
而正例只有一条——按「n=1 时什么都对」，拿 A 当标尺量出来的「相称」，
很可能只是「像 A」。

跟 GPT 定的转向，这是这把尺子从「感觉」走向「审计工具」的一步：

```
✗ A 是唯一正例，所以这个看起来不像 A
✓ 它不像 A 无所谓；请告诉我它【违反了哪个不变量】
```

> **A 不是「标准答案」，而是一组校准案例——
> 证明同一个纵向承接原则可以接受【不同形状】。**

A 内部三路的承接形状就各不相同（程度型 / 状态型 / 状态+标记型），
正文的重量也各写一件不同的事：

```
归  「他瘦了一圈，脸是黑的，手上多了几道口子」   ← 写身体
亡  「尸首没有运回来。太远了。」                  ← 写距离
杳  「钱也不捎了。」「{dam}托人去打听过一次。」   ← 写等待
```

**三路各自跟它那一路的状态相称，而相称的方式三路都不一样。**

## 九、真正可复用的那把标尺：六问

```
结果事实
  → 谁承受？
  → 它是什么事实？
  → 最低承诺是什么？
  → 承接是否表达了这个最低承诺？
  → 有没有越过它的语义边界？
  → 如果声明会继续影响世界，后续是否真的消费？
```

**前五项可以逐渐机械化**；最后的「相称」如果暂时机械不了，就留给人工判，
**但必须要求人工说出具体违反了哪条语义不变量**，不能只说「看着不像」。

### 而配套一条硬规则

> **凡是设计已经声明存在的承接层，都必须有对应证据；
> 不能凭「通常应该有」补出一层。**

因为承接本来就不必三层齐全：

```
事实 → 状态          就结束了，它没有玩家可见后果
事实 → 认知          而没有持久状态
```

**这跟拒绝给 `bearing` 强行补 `health` 是同一个原则。**

## 十二、⚠️ 第七问：字段是事实表达，还是字段驱动

B 链逼出来的。上一轮我据「`doing` 条件层问不了」**否掉了给配偶写换营生那一卷**，
而 B 链干的正是那件事——**同一个机制，一次判成「不够」，一次判成「够」**。

区别说得出来：

```
配偶那一卷   为了让 doing 从 1 变 2 而写   ← 拿【字段当目的】
B 链         处境变了所以做活的人换了      ← 字段是【后果】
```

> **同样是写入 `doing`，必须区分「世界事实要求这个字段表达自己」
> 和「设计为了制造字段变化而写这个字段」。**

### 所以尺子加到七问

```
事实产生
 ↓ 谁／什么承受？
 ↓ 产生了什么最低语义承诺？
 ↓ 状态或正文有没有表达这个承诺？
 ↓ 表达是否越界？
 ↓ 如果设计声明它还会继续影响世界，是否存在后续消费？
 ↓ 【字段本身是事实表达，还是字段驱动？】
```

⚠️ **最后一问目前可以问，不能自动判。**
而那不是这把尺子不成熟，是**正确的边界**：

> 凡是还无法从一手结构证据推出的，就保留为人工语义审查项，
> **不伪装成机器事实**。

## 十五、⚠️ 先判【承诺边界】，再判承接

名册补全带来 66 条新候选，而它们大多来自配偶、儿子、嫂子、侄儿
——正是这一族在追的那批人，也正是**内容写得最新最薄**的那批。

我原本想的分法是「刚写的 vs 老内容」。GPT 换掉了：

> **不应该让时间新旧成为判据，而应该让「承诺边界」成为判据。**
> **先判承诺边界，再判承接。**

```
这条候选究竟是「没有承接」，还是【根本没有开放过那个承诺】？
                                    ↓
                        只有后者才进入真正的链审计
```

**新写的卷不是「还没长出承接」，是「它没有声明过后续」。**
一卷只声明「这件事发生了」，那它没承诺过什么；
一卷声明了「此后他就……」而没人读，那才是漏。

所以纵向承接审计正式加一层，排在最前：

```
先判承诺边界
  ↓ 这一卷开放了什么承诺？（可能是零）
再判承接
  ↓ 正确对象 / 正确事实类型 / 正确强度 / 正确时间 / 必要时后续机制消费
```

**这不是给新内容开后门，是给尺子补上一个它原本缺失的语义维度**
——否则直接拿「结果 → 后续状态」去扫，会把**尚未声明后续的内容**
误报成**已声明而未实现的内容**。

## 十六、⚠️ 陶仲那一族：零效果不等于零承接

「先判承诺边界」头一次实战，**当场把一族 11 条从「可疑」变成「清白」，
而理由跟旧尺子会给的完全不同。**

药庐那位（`herbalist-at-the-shed`）独占新增 24 条里的 11 条。
旧尺子会说：**他被点名 11 次，而身上一笔效果也没有**——看着像大缺口。

一手核：

```
全库 id: 'herbalist-at-the-shed' 六处
  五处是【条件】（alive: true）
  一处是【立人】
person 效果：【零】
```

### 而按承诺边界判，答案反过来

```
mountain:unaged   「你头一回进这扇门的时候，他也是这个样子。」
                  → 声明的是【他不老】，而那【已经实现了】
                  → ⚠️【他身上什么都不变，才是这一卷的内容】
                    给他落一笔「变化」反而是错的

mountain:shut     「药庐那位不再让你去了。」
                  → 声明了后续：此后他不再理你
                  → 落 flag shut-out-by-the-shed
                  → 读取端【三个】（going-up.ts:411、mountain.ts:806 等）✓ 兑现
```

⚠️ **GPT 澄清了一处我说得不准的**：让 `mountain:unaged` 清白的是
**正文语义**，不是 `alive: true` 这个条件。条件只说「他得活着」，
而「他不老」是正文说的。

### 定性（可以固定进方法论）

> **零效果不等于零承接。**
> 承接可以表现为状态产生、状态持续、状态保持、关系成立、认知兑现
> 或后续机制消费。**对「保持不变」的稳定性承诺，制造变化反而违反承诺。**

> **承诺边界不是第八种角色，而是与角色【正交】的语义维度**
> ——同一人物可以同时具有角色身份和承诺状态。

### 所以判定流程是这样，中间层不能跳

```
点名
 ↓ 条件需要谁
 ↓ 【事件声明什么】        ← 正文语义，不是条件
 ↓ 【声明是否已经闭合】     ← 闭合了就到此为止（陶仲的「不老」）
 ↓ 如果开放，才追承接
```

**后面 66 条新候选不能简单继续问「有没有效果」**，
要先问「**这条候选对应的对象，在该卷中到底被声明了什么**」——
**然后才知道什么叫「落点」。**

我本来要判「关系解析」，读注释才发现是**设计结论**：

> 从前这一卷的 `requires` 里挂着 `{ family: { id: steward, alive: true } }`
> ——理由充分：他在正文里说了两句话，而这一卷的决定就是他做的。
> 可他比玩家大 42–60 岁，而窗口是玩家九到十三岁……
> **一半以上的府里孩子读不到这一卷，而没有任何东西会报错。**
> 所以不是放宽那条 `requires`，是**给「他没了」写一支**。

**「没被点名」在这儿不是疏漏，是被 `doors.ts` 逼着去掉的。**

⚠️ 这是这一族**第三次**「库里的注释比我判得准」
（前两次：`birth:*` 取名那 13 条、`son:heard-of-a-place` 的承诺边界）。

### 「承诺边界内」那一档收了三族，而三族都是明文写过的

```
herbalist-at-the-shed          承诺「他不老」——给他落变化反而是错的
son:heard-of-a-place           承诺「第一次听见外部去处」，不承诺后续

```

**那一档不是为了让候选变少发明的，是内容自己声明的。**

### ⚠️ 顺带修了一处尺子自己的报表缺陷

```
  ↓

  ├─ 已知故障   → 按现有尺子处理
```

```
              如果开放，后续事实有没有兑现？
```

## 十九、头一次拿尺子撞真实世界：邻居那条线

### 先量【观察机会基线】，防止「零候选」被读成「零问题」

跟 GPT 定的名字：**opportunity baseline**。它不判结论，只回答
「这把尺子在这儿有没有东西可量」。

```
全库提到邻居   29 处，分布 6 卷（census · dearth · house · playmate · regard · unrest）

拆开：
  事件入场里    1 件
  节点分流里    2 条
  落效果给他   【0 处】   ← 全库一次也没往邻居身上落过任何东西
  正文点名      6 处
```

**基线不是零**——所以沉默不能解释成「这儿没问题」，而要解释成别的。

### 而基线本身就是答案

```
配偶   被点名 16 次，落效果 1 次（而那一次是旗标）   ——她进得来，只是不被记
邻居   被点名  3 次，落效果 0 次                      ——他们【几乎进不来】
```

**配偶那一族是「主体事实出口缺失」；邻居这一族是「他们根本不是任何事件的主体」。**

那 6 处正文里承受者全是玩家：

```
「{hail:east-wife}你可算回来了。」        她来搭话，玩家被搭话
「腊月里的一夜，有人敲门。是隔壁那户的」   他来报信，玩家听信
```

**他们全是执行者**——而尺子早判过这两条（`east-wife` / `east-head` 各 1 条，
都判成执行者）。**判对了，只是当时我没意识到那是全库的全部。**

### 定性：越过了承接尺子的职责边界

```
判定链
  这个人是不是该事件的结果主体？
    是 → 承接尺继续审
    否 → 执行者／关系方／背景等合法角色 → 承接尺【停止】
         ↓
         如果设计认为他本应成为主体
         ↓
         这是【事件设计缺口】，不是【承接故障】
```

### ⚠️ 而旧结论要订正，两道

```
旧  「不是缺事件，是缺社会交叉」
```

**一、「缺社会交叉」说反了。** 数据说的是就是缺事件。

**二、而「缺事件」仍然太宽**（GPT 再收一档）：

```
事件存在性        有
邻居相关事件      有（29 处挂点）
邻居作为主体的事件  【0】
```

> **正式写法：缺少【以邻居为主体】的事件。**

⚠️ 而**还不能进一步说「该给邻居加哪一种事件」**——
互助、冲突、借贷、婚姻牵线、土地纠纷、灾害联动、邻里评价，
已经证明的只是「当前内容没有社会交叉结果」，没有证明该是哪一种。

## 二十、这个游戏里的「邻居」已经被世界写成了什么

按 GPT 定的顺序做的 C：**不假装拥有历史证据，而用已经拥有的一手世界事实**。

> C 的产出不是「找到一个邻居事件」，而是先回答
> **「这个游戏里的邻居，到底已经被世界写成了什么」**。

### 全库六句话，一句不漏

```
dearth:price          傍晚，{call:east-wife}站在门外，没像往常一样进来，
                      只在门口低声问{dam}：「你家……还有没有余粮」
house:divide          中人请的是{call:east-head}，和族里的一位长辈
house:divide-younger  中人请的是{call:east-head}
unrest:word           {hail:east-head}后山那边，你听见没有？
regard:homecoming     {hail:east-wife}你可算回来了
regard:homecoming     {hail:east-head}回来啦
```

### 形状出奇一致

```
荒年   她来【求】       站在门外，没像往常一样进来
分家   他来【做见证】   中人
兵祸   他来【报信】     后山那边你听见没有
归来   他们来【招呼】   你可算回来了
```

**四种事，全是「他来到你家门口」。** 一次也没有反过来。

```
他【知道你家的事】        荒年知道你家有没有余粮，分家时能当见证
他【会主动来】            求粮、报信、招呼，都是他迈的步
他【自己的日子没有一笔】  29 处挂点，零处落效果
```

⚠️ 而「**没像往常一样进来**」那一句最说明问题：**那四个字里藏着一整套
从没被写过的日常**——正文默认了两户之间有来往，而那个来往一次也没正面出现过。

### ⚠️ 而我从这儿推出的「反向」思路被驳回了，理由值得记

我提的是把已有四种各做一个镜像（求→被求、见证→被见证……）。GPT 的反驳：

> **「玩家该去邻居家」跟「邻居该成为主体」是两件事。**
> 前者已被当前世界事实支持为结构缺口；**后者只是设计选择，
> 不能让前者替它背书。**

而真正的形状是：

```
邻居家发生 X
      ↓
邻居【自身状态】发生变化
      ↓
玩家因为「隔壁」而知道 / 受影响 / 被卷入
```

**这才是从「执行者」向「主体」跨了一格。**

### 结论的正式写法（不要写成「缺少反向互动」）

> 现有邻居事件长期呈现为「邻居主动进入玩家生活」的单向结构。
> 正文还通过「往常一样进来」等措辞**预设了更广泛的日常往来，
> 而这些往来没有被正面呈现**。
> 下一步**不应机械补齐互动镜像**，而应优先寻找
> **「邻居自己的事情先发生，玩家随后因邻里关系而知晓、参与或受影响」**的事件。

四个镜像只作候选池，其中：

```
优先   邻居家自己的事情 → 玩家被请去见证
其次   玩家陷入荒年困境 → 去邻居家求助
暂弱   报信、招呼
```

### ⚠️ 而第一条新增邻居事件要证明的是这一句

> **不是「玩家终于能去邻居家了」，而是
> 「即使玩家什么都没做，邻居的人生也会自己往前走，
> 而玩家只是第一次撞见它」。**

## 二十一、⚠️ 「纯玩家视角」不是障碍——而我差点据此撤回整族结论

写第一卷之前，我提了个更根本的疑问：

> 这个库的每一行正文都是玩家看见的，**没有任何一处是「镜头切到别人家」**。
> 那么「邻居成为主体」会不会天然只能表现为「玩家看见他家变了」，
> **而那跟「他是执行者」的区别，只在我心里？**

GPT 撤掉了这一条，而给的判据比我那个疑问准：

```
✗ 玩家只能看见 Y，所以无法证明 X
✓ 【Y 是不是 X 在玩家视角下的可观察投影，而不是 Y 本身冒充了 X】
```

### 所以这一族的结论要改写成这样

> 「邻居缺少主体事件」仍然成立，**但主体事件不应被定义成
> 「玩家直接看见邻居发生了什么」**。**纯玩家视角不是障碍。**
>
> 真正的判定标准是：**邻居是否存在【独立于玩家行为】的世界状态变化，
> 并产生属于邻居自身的后果；玩家看到的只是这些事实的可观察投影。**

⚠️ 而这意味着以后审「主体事件」要**同时看世界事实层和玩家认知层**，
**不能拿正文镜头直接代替世界状态**。

## 二十四、「不被写成主体」有第二种代价

第一卷写完之后建了一支静态走查（`scripts/absent.ts`），
问的是一个很窄的问题：**正文里点了名的那个人，有没有任何一处保证过他还在？**

扫完全库，真问题**五条里五条都在同一册**（老屋那一族）：

```

「他没跟{call:brother-wife}说」                侄儿瞒着他娘
「{call:brother-wife}多了个帮手」              儿媳进门
「头七那晚哥跟{call:brother-wife}吵了一架」    ⚠️ 死人吵不了架
「老人家没了的时候，是嫂子在跟前」            她可能比老人家先走
```

```
kindred-newyear    问【侄儿】活着且 ≥3 岁
kindred-mourning   问【娘】殁了
kindred-nephew-*   问【侄儿】
────────────────────────────
嫂子                【从头到尾没有人问过】
```

她不是被漏掉的。她是**那个一直在那儿的人**——
所有卷都默认她在，因为她从来不是任何一卷的主题。
而这一册开到玩家七十岁。

> **「不被写成主体」的代价，我原以为是「他没有戏」。
> 而这五处说明还有第二种：【别人的戏默认他在场】。**
>
> 第二种更隐蔽——它不表现为缺失，表现为**一句读起来很自然的话**。

```
东邻添丁    补【世界生产】     没有玩家参与，别人的生活也会继续发生

```

## 二十五、第二卷不写了——「东邻」是个未完成对齐的复合概念

原打算写「东邻搬走」。动笔前查了一手，发现它撞在一个错配上：

```
绑【人】   { family: { id: 'east-head', alive: true } } + {call:east-head}
           dearth · house ×2 · regard · neighbour        ← 全库几乎都是

绑【户】   { house: { id: 'east' } }
           mountain 一处，注释写着「要有东邻那一户，【谁当家都行】」
```

而引擎那一头判方位读的是 `houses['east'].members.includes(id)`。

```
引擎层   东邻是一个【位置】
内容层   东邻是【那两个人】
```

### ⚠️ 所以「搬走」现在没法发生

不是没写，是**一写就会把全库五处点名的内容变成悬空**。

而它照出四层之外的第五层：

```
存在 / 活着 / 在场 / 可接触      这四层都有
还是不是邻居                     ← 一格也没有
```

### 定性（GPT 给的措辞，比我原来的准）

> 「东邻」当前是一个**未完成对齐的复合概念**：引擎把它建模为位置，
> 内容把它主要建模为固定人物。**任何涉及搬迁、换户、分家或户主变化的事件，
> 都会暴露这一错配。**

**所以它从内容候选升级为模型对齐候选。** 在「户」和「位置」是否分离
定下来之前写搬走，只是用文本掩盖模型缺口——
而那正是这一族一直在防的东西。

## 二十六、第一卷不是挑得准，是撞对了唯一通着的那一格

第二卷搁下之后，我把东邻那一户六格逐格问了一遍「动它会怎样」：

```
members      添丁那一卷用的                    ✓ 通
livelihood   东邻改行                          ✗ 全库 family.livelihood 只问过
                                                 brother 和 nephew，【一处也没问过东邻】
residence    东邻搬走                          ✗ 模型错配（内容当人，引擎当位置）
head         户主换人                          ✗ 同上
surname / id 不会变
```

### ⚠️ `members` 为什么通

**它恰好有引擎级的读取端**：

```
live()      每年遍历整个 roster 推时间，【不问户口】
方位判定     houses['east'].members.includes(id) → 「东」
houseOf / 邻居判定 / 条件层 / 正文插值
```

> **不是我挑得好，是这个库只有那一格对邻居是活的。**
> 第一卷之所以「干净」，是因为那一格本来就通着——
> 我当时以为那是设计选得准，实际是**别的格子根本走不通，撞对了唯一一条路**。

### 定性

> 这个库对邻居只有**生产**，没有**持续**。
>
> 「东邻家新增一个人」通着，因为人口生命周期是全局的；
> 而「东邻家变成什么样」一格也不通——
> **营生变了没人问，住处变了模型不认，当家的换了内容还点着旧名字。**

---

## 二十七、⚠️ 一条从此该先问的话

GPT 定的，而它比这一族任何一条具体结论都通用：

> **不要从「对象有这个字段」推导「这个字段可以成为这个对象的剧情状态」。**
>
> 一个字段只有在它**参与真实世界判定**、或者存在**明确的下游消费契约**时，
> 才算这个对象当前可用的动态事实。**否则它只是结构上的储存位置。**

东邻那一户是最干净的反例：从类型定义看 `livelihood` / `residence` / `head`
三个字段都「存在」，而从世界模型看它们对东邻**全是死的**。

### 所以顺序要倒过来

```
✗ 这个人还能发生什么故事 → 需要哪些字段 → 逼世界模型补
✓ 这个人的哪些世界事实【目前是真的活着】 → 故事候选从那里长出来
```

⚠️ 这一条对任何新 NPC、新家庭、新社会关系都适用，
**而它可以做成一支走查**：给定一个对象，列出它哪些格有真实的下游消费。

---

## 二十八、审计自己的三层，和一个「互相印证」的环

这一族查到最后，走到了**审计系统自身**。三层结构（GPT 定的）：

```
第一层   判据有没有看对地方？          来源完整性
第二层   判据拿到的证据是不是自己造的？ 来源独立性
第三层   证据在证明它声称的那个语义吗？ 语义有效性
```

### 第二层：一个环，而它让两支门禁一起绿了两年

```
school:threshold#hall（宫里出身 0.82%）
  onEnter   id: 'tutor'  who: { surname: '沈', given: '一贯' }
  正文      「侍讲姓周，翰林出身」      ← 姓周的是【王府那位教授】
  对白      speaker: '周侍讲'
```

而 `presence.ts` 的 `SPEAKER_IDS` 里写着 `周侍讲 → tutor`
——**那张表是照这处错正文抄的**（照纪律办的：「关键词表要照库里真写的字抄」）。

```
正文说   「周侍讲」在说话
判据问   「周侍讲」开口了吗
         ↓  绿。两者互相印证着对方是对的。
```

> ⚠️ **一处错正文加一张跟着它抄的表，谁也不会红。**
>
> **判据表的校准源，不能是它要判的那个东西。**
> **证据数量不能代替证据独立性。**

打破环要第三方：`scripts/surname.ts` 拿 `onEnter` 里的 `who.surname`
这个**世界事实**去对正文，不读正文的自洽性。

⚠️ **修的顺序有讲究**：先修正文、再修判据表。反过来先改表，
正文那处穿帮就永远留着了——**而表会立刻变绿，看着像修好了。**

### 第一层：新走查头一版报 13 句，13 句全是误报

`scripts/quoting.ts` 问「判据里抄的那句正文，库里还在吗」。
头一版干草堆只收 `lifeScenes`，而那 13 句住在认知库 `summary`、
日常 `BEATS`/`DOINGS`、倾向 `LEANINGS`、日录 `tags` 里。

**玩家读得到的字，不止住在一处。**

> 13 → 4 **不是「误报率从 16% 降到 5%」**。
> 是第一版先测出了**审计器自己的「内容全集」假设不成立**；
> 修正之后，剩下的 4 条才重新成为值得判断的候选。

而那正是这一族一直在坚持的：**先证明尺子确实量到了目标，再用尺子量目标。**

## 二十九、审判据要按【命题】审，不按写法审

这一族查到最后，撞出一条元判据，而它第一次用就用错了方向。

### 那条元判据

> 这条对照证明的是「**存在一种说得通的解释**」，还是
> 「**我要的那个解释唯一成立**」？

它咬出过两处真问题：

```
surname.ts 的表校验   「这个 id 造过的姓里有没有它」
                       tutor 造过沈/周两个姓 → 把当年那个错改回去，判据照样绿
quoting.ts 的还在吗   「整个 src/content 里有没有这些字」
                       82 句里 20 句在不止一个文件里出现
```

### ⚠️ 而拿它扫全库，头一个数是「133 处可疑」——真实数目是 2

```
否定式   71 处   if (!x.some(…))  「该有而没有」→ 存在型判定是【对的】
肯定式   43 处
其中「认短词认人」的   只有 2 处
```

**方向反过来的那 71 处全部正当。**
要证明「一次也没有」，存在型判定恰恰是正确写法。

> **过弱的谓词危险，过强的谓词同样危险。**
> `!some()` 被改成唯一匹配 → 假阴性；
> `includes()` 被拿去证明唯一身份 → 假阳性。

### 所以按命题审，别按 API 审

```
命题「至少存在一个 X」   所需证明强度   存在性
命题「不存在 X」                        全称否定
命题「这个 X 就是 Y」                   身份绑定 + 排除竞争解释
```

**这比建一张「危险 API 清单」稳得多**——清单会把 71 处正确写法拖进来，
而按命题分，一眼看得出哪一类需要高强度辨识力。

⚠️ 而全库只有 2 处属于第三类，**那是个好结果**：
真正需要身份绑定的地方非常少，可以窄打这两个点，不必把 133 处全拖进来。

## 三十、先量故障族，再定判据

这一整族审计工作最后收在一条流程上：

> **先量故障族，再定判据；先证明射程，再扩大射程。
> 候选数量不是规则覆盖范围的依据，真实语义形状才是。**

### 它是被两次栽跤逼出来的

```
133 → 2    元判据扫出「133 处可疑」，分类之后真实数目 2
  8 → 1    建议「豁免表每个词各写一行断言」，八个词里只有一格在射程内
```

两次都是**判准对，而没问它对哪一类成立**。
而两次的纠正方式相同：**先量分布，分布本身就告诉你这一族有多大。**

### 第三次先量了，于是省掉一次无用功

要补「引用类型识别」（这个词指的是不是一个人）之前，
先量八个称呼在正文里**后面紧跟什么字**：

```
「长史」→ 司×8   在×2   来×2      ← 八次里八次跟着「司」
「管事」→ 的×21  、×7             ← 「管事的」是称呼，不是官名
其余     跟的都是标点、动词、引号 —— 指人
```

**只有「长史」被机构名吃掉。** 判据因此窄成
「称呼后面紧跟【司／局／房／院】→ 那是衙门」，一处就够。

### ⚠️ 而那一个实例的意义不在「多」

> `chancellor` 不是拿来证明「中文称呼普遍有歧义」，
> 而是证明**引用类型识别确实存在一种真实、可复现、可被窄规则阻断的错误形状**。

这一族每一层的真实缺陷都只有一两处：
引用类型识别 1 处、语义有效性 3 条里判得了 1 条、事件主体 5 处。

**它们能活很久，不是因为难，是因为那一层根本没有判据存在。**
