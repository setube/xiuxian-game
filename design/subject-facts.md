# 事件的另一半：主体事实的承接（2026-09-13）

> 这一族跨了三轮：配偶那一册查出形状 → `scripts/subject.ts` 把查法钉成走查 →
> 纵向承接审计。跟 GPT 逐条过出来的口径记在这儿。
>
> **每一条都是一手核的。**

---

## 一句话

**不是「这个人没写完」，是「事件发生在这个人身上，而世界只记录了
事件最容易被继续使用的那一半」。**

## 二、七种角色，只有最后一种要承接

判完 83 条候选（`requires` 28 + `branches` 55）之后长出来的：

```
背景      存在条件     有他，这件事才成立        要有个哥才有嫂子
岔口      路径选择     有他，这件事走这一支      哥今年没回来
约束      可行性边界   有他，这件事走不成        那一趟你没有去成
记录者    编年落在玩家名下                      玩家视角的游戏，本来就该这样
执行者    他做了那件事，而事落在别人身上        产婆、取名的爹、来敲门报信的邻居
关系双方  tie 的两头                            重逢、上山同行、荒年催租
【真正经历者】                                  ← 只有这一格该问「世界记下了吗」
```

⚠️ **「约束」这一档不是预先设计的，是判到第九族时它自己冒出来的。**
要是一开始就写死五档、把装不下的塞进最近那一格（它最像「岔口」），
这一层就读丢了。

> **角色分类用于解释候选，不用于预先淘汰候选。**

## 三、⚠️ 判准：不是「有没有状态写入」

跟 GPT 定的，这一句是这一族最要紧的判准：

```
✗ 是否存在状态写入？
✓ 【结果事实是否存在与其语义相称的承接？】
```

后者比「主体身上有东西」强得多，**而且不会把「亡」「杳」这种离散状态
误判成缺少程度值**。

### 承接至少有四型（`debt` 那条链一次给全了）

```
程度型          health 42 —— 他还活着，而此后每年更可能走
状态型          fate '殁'
状态 + 标记型   fate '杳' + flag father-missing
状态 + 认知型   编年「父亲再也没有消息了」
```

**一个完整的承接可以终止于 `fate`，也可以终止于 `doing`、关系、`flag`、编年。**
所以**不能拿「可量化的 health」当模板**。

---

## 四、「链」是什么：三层分开记，不揉成一条

```
事件因果链   天旱 → 借债 → 出外做工 → 归来／亡／杳
状态承接     归来 → health 42 → frailty 每年现读
认知承接     正文怎么表达这些事实
```

**发现某条链只有事件承接、没有状态消费时，能精确说出缺的是哪一层，
而不是笼统地判「链断了」。**

### 连接件是两种，而两种都不是机器可查的

```
旗标        共享状态证据      drought / father-in-debt / father-away
分路键      一次掷出来的      father-fate：归 62 / 亡 24 / 杳 14
```

**链不能只靠旗标，也不能只靠同一承受者**——旗标是共享状态证据，
同一承受者是主体一致性证据，两者都要跟明确的承接关系结合。

## 五、三颗真候选，同一个形状

```
bearing-await     妻子生    落在 son/daughter 和编年上
child-sibling     娘生      落在新弟妹和这一户上
wife-that-winter  娘病      落在配偶的照料上
```

**三颗都是「生育／病痛发生在一个女人身上，而世界记的是别人」。**

而 `child-sibling`（玩家小时候家里添了个弟妹）证明**这不是配偶一个人的事**
——它落的是 `family: sibling`、`household`、`chronicle`，
**而生这个孩子的娘身上一笔也没有**。

### ⚠️ 三颗卡在同一处，而那一处是【依据】不是【设计】

要落 `health` 得先定义「生育存在母体身体风险」这条世界规则，而史料
支撑得起「农村家庭分娩的母体死亡风险显著」，**支撑不起「有 X% 的
幸存妇女留下足以缩短余寿的长期身体损害」**。

> **`alive = false` 和 `health ↓` 是两个不同的世界事实，证据也必须分别对应。**

**三个用例说明这条规则该存在，而它们一个也没告诉我那个率是多少。**
用例多不等于依据有了。口径和状态在 `the-wife.md` 第八、九节。

## 六、`subject.ts` 的三个盲点（都写在它自己的注释里）

```
只看同一卷      主体事实由别的生产者落下的，它报成缺席
对不上角色记号   条件问 bond:抚养，效果落 id: elder
只数四种效果    flag 和 knowledge 同样是「这个人身上留下了什么」的出口
```

**盲点写下来，比把它消掉更要紧**——消掉要判「这面旗说的是谁」，
那又回到语义层，而**尺子不该替设计者做语义判断**。

## 七、这一族踩过的方法论坑（都在别处有长期记忆）

```
统计单位错   拿 grep 行数当语义条目数（报 22 处，实为 16 处）
破坏单位错   一行的记号是多条候选的合取，砍一条不动
审计单位错   想按「卷 × 人」归并，而那会把「一支是岔口一支是主体」压没
证据读取错   grep 截断：先看见 chronicle 就以为没有 fate
措辞污染     「她改变了结局」→ 下一句长出「她拦住了玩家」，而正文没这么说
```

最后一条 GPT 归纳得最准：

> **在宣布「没有」之前，必须先证明观察范围覆盖了「应该存在的位置」。**

## 八、⚠️ A 不是标准答案，是校准案例

审完 A（`debt` 那条链）之后，我手上是一个正例、三个负例、一条判准。
而正例只有一条——按「n=1 时什么都对」，拿 A 当标尺量出来的「相称」，
很可能只是「像 A」。

跟 GPT 定的转向，这是这把尺子从「感觉」走向「审计工具」的一步：

```
✗ A 是唯一正例，所以这个看起来不像 A
✓ 它不像 A 无所谓；请告诉我它【违反了哪个不变量】
```

> **A 不是「标准答案」，而是一组校准案例——
> 证明同一个纵向承接原则可以接受【不同形状】。**

A 内部三路的承接形状就各不相同（程度型 / 状态型 / 状态+标记型），
正文的重量也各写一件不同的事：

```
归  「他瘦了一圈，脸是黑的，手上多了几道口子」   ← 写身体
亡  「尸首没有运回来。太远了。」                  ← 写距离
杳  「钱也不捎了。」「{dam}托人去打听过一次。」   ← 写等待
```

**三路各自跟它那一路的状态相称，而相称的方式三路都不一样。**

## 九、真正可复用的那把标尺：六问

```
结果事实
  → 谁承受？
  → 它是什么事实？
  → 最低承诺是什么？
  → 承接是否表达了这个最低承诺？
  → 有没有越过它的语义边界？
  → 如果声明会继续影响世界，后续是否真的消费？
```

**前五项可以逐渐机械化**；最后的「相称」如果暂时机械不了，就留给人工判，
**但必须要求人工说出具体违反了哪条语义不变量**，不能只说「看着不像」。

### 而配套一条硬规则

> **凡是设计已经声明存在的承接层，都必须有对应证据；
> 不能凭「通常应该有」补出一层。**

因为承接本来就不必三层齐全：

```
事实 → 状态          就结束了，它没有玩家可见后果
事实 → 认知          而没有持久状态
```

**这跟拒绝给 `bearing` 强行补 `health` 是同一个原则。**
