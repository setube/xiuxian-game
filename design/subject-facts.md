## 三、⚠️ 判准：不是「有没有状态写入」

跟 GPT 定的，这一句是这一族最要紧的判准：

```
✗ 是否存在状态写入？
✓ 【结果事实是否存在与其语义相称的承接？】
```

后者比「主体身上有东西」强得多，**而且不会把「亡」「杳」这种离散状态
误判成缺少程度值**。

### 承接至少有四型（`debt` 那条链一次给全了）

```
程度型          health 42 —— 他还活着，而此后每年更可能走
状态型          fate '殁'
状态 + 标记型   fate '杳' + flag father-missing
状态 + 认知型   编年「父亲再也没有消息了」
```

**一个完整的承接可以终止于 `fate`，也可以终止于 `doing`、关系、`flag`、编年。**
所以**不能拿「可量化的 health」当模板**。

## 四、「链」是什么：三层分开记，不揉成一条

```
事件因果链   天旱 → 借债 → 出外做工 → 归来／亡／杳
状态承接     归来 → health 42 → frailty 每年现读
认知承接     正文怎么表达这些事实
```

**发现某条链只有事件承接、没有状态消费时，能精确说出缺的是哪一层，
而不是笼统地判「链断了」。**

### 连接件是两种，而两种都不是机器可查的

```
旗标        共享状态证据      drought / father-in-debt / father-away
分路键      一次掷出来的      father-fate：归 62 / 亡 24 / 杳 14
```

**链不能只靠旗标，也不能只靠同一承受者**——旗标是共享状态证据，
同一承受者是主体一致性证据，两者都要跟明确的承接关系结合。

## 八、⚠️ A 不是标准答案，是校准案例

审完 A（`debt` 那条链）之后，我手上是一个正例、三个负例、一条判准。
而正例只有一条——按「n=1 时什么都对」，拿 A 当标尺量出来的「相称」，
很可能只是「像 A」。

跟 GPT 定的转向，这是这把尺子从「感觉」走向「审计工具」的一步：

```
✗ A 是唯一正例，所以这个看起来不像 A
✓ 它不像 A 无所谓；请告诉我它【违反了哪个不变量】
```

> **A 不是「标准答案」，而是一组校准案例——
> 证明同一个纵向承接原则可以接受【不同形状】。**

A 内部三路的承接形状就各不相同（程度型 / 状态型 / 状态+标记型），
正文的重量也各写一件不同的事：

```
归  「他瘦了一圈，脸是黑的，手上多了几道口子」   ← 写身体
亡  「尸首没有运回来。太远了。」                  ← 写距离
杳  「钱也不捎了。」「{dam}托人去打听过一次。」   ← 写等待
```

**三路各自跟它那一路的状态相称，而相称的方式三路都不一样。**

## 九、真正可复用的那把标尺：六问

```
结果事实
  → 谁承受？
  → 它是什么事实？
  → 最低承诺是什么？
  → 承接是否表达了这个最低承诺？
  → 有没有越过它的语义边界？
  → 如果声明会继续影响世界，后续是否真的消费？
```

**前五项可以逐渐机械化**；最后的「相称」如果暂时机械不了，就留给人工判，
**但必须要求人工说出具体违反了哪条语义不变量**，不能只说「看着不像」。

### 而配套一条硬规则

> **凡是设计已经声明存在的承接层，都必须有对应证据；
> 不能凭「通常应该有」补出一层。**

因为承接本来就不必三层齐全：

```
事实 → 状态          就结束了，它没有玩家可见后果
事实 → 认知          而没有持久状态
```

**这跟拒绝给 `bearing` 强行补 `health` 是同一个原则。**

## 十二、⚠️ 第七问：字段是事实表达，还是字段驱动

B 链逼出来的。上一轮我据「`doing` 条件层问不了」**否掉了给配偶写换营生那一卷**，
而 B 链干的正是那件事——**同一个机制，一次判成「不够」，一次判成「够」**。

区别说得出来：

```
配偶那一卷   为了让 doing 从 1 变 2 而写   ← 拿【字段当目的】
B 链         处境变了所以做活的人换了      ← 字段是【后果】
```

> **同样是写入 `doing`，必须区分「世界事实要求这个字段表达自己」
> 和「设计为了制造字段变化而写这个字段」。**

### 所以尺子加到七问

```
事实产生
 ↓ 谁／什么承受？
 ↓ 产生了什么最低语义承诺？
 ↓ 状态或正文有没有表达这个承诺？
 ↓ 表达是否越界？
 ↓ 如果设计声明它还会继续影响世界，是否存在后续消费？
 ↓ 【字段本身是事实表达，还是字段驱动？】
```

⚠️ **最后一问目前可以问，不能自动判。**
而那不是这把尺子不成熟，是**正确的边界**：

> 凡是还无法从一手结构证据推出的，就保留为人工语义审查项，
> **不伪装成机器事实**。

## 十五、⚠️ 先判【承诺边界】，再判承接

名册补全带来 66 条新候选，而它们大多来自配偶、儿子、嫂子、侄儿
——正是这一族在追的那批人，也正是**内容写得最新最薄**的那批。

我原本想的分法是「刚写的 vs 老内容」。GPT 换掉了：

> **不应该让时间新旧成为判据，而应该让「承诺边界」成为判据。**
> **先判承诺边界，再判承接。**

```
这条候选究竟是「没有承接」，还是【根本没有开放过那个承诺】？
                                    ↓
                        只有后者才进入真正的链审计
```

**新写的卷不是「还没长出承接」，是「它没有声明过后续」。**
一卷只声明「这件事发生了」，那它没承诺过什么；
一卷声明了「此后他就……」而没人读，那才是漏。

所以纵向承接审计正式加一层，排在最前：

```
先判承诺边界
  ↓ 这一卷开放了什么承诺？（可能是零）
再判承接
  ↓ 正确对象 / 正确事实类型 / 正确强度 / 正确时间 / 必要时后续机制消费
```

**这不是给新内容开后门，是给尺子补上一个它原本缺失的语义维度**
——否则直接拿「结果 → 后续状态」去扫，会把**尚未声明后续的内容**
误报成**已声明而未实现的内容**。

## 十六、⚠️ 陶仲那一族：零效果不等于零承接

「先判承诺边界」头一次实战，**当场把一族 11 条从「可疑」变成「清白」，
而理由跟旧尺子会给的完全不同。**

药庐那位（`herbalist-at-the-shed`）独占新增 24 条里的 11 条。
旧尺子会说：**他被点名 11 次，而身上一笔效果也没有**——看着像大缺口。

一手核：

```
全库 id: 'herbalist-at-the-shed' 六处
  五处是【条件】（alive: true）
  一处是【立人】
person 效果：【零】
```

### 而按承诺边界判，答案反过来

```
mountain:unaged   「你头一回进这扇门的时候，他也是这个样子。」
                  → 声明的是【他不老】，而那【已经实现了】
                  → ⚠️【他身上什么都不变，才是这一卷的内容】
                    给他落一笔「变化」反而是错的

mountain:shut     「药庐那位不再让你去了。」
                  → 声明了后续：此后他不再理你
                  → 落 flag shut-out-by-the-shed
                  → 读取端【三个】（going-up.ts:411、mountain.ts:806 等）✓ 兑现
```

⚠️ **GPT 澄清了一处我说得不准的**：让 `mountain:unaged` 清白的是
**正文语义**，不是 `alive: true` 这个条件。条件只说「他得活着」，
而「他不老」是正文说的。

### 定性（可以固定进方法论）

> **零效果不等于零承接。**
> 承接可以表现为状态产生、状态持续、状态保持、关系成立、认知兑现
> 或后续机制消费。**对「保持不变」的稳定性承诺，制造变化反而违反承诺。**

> **承诺边界不是第八种角色，而是与角色【正交】的语义维度**
> ——同一人物可以同时具有角色身份和承诺状态。

### 所以判定流程是这样，中间层不能跳

```
点名
 ↓ 条件需要谁
 ↓ 【事件声明什么】        ← 正文语义，不是条件
 ↓ 【声明是否已经闭合】     ← 闭合了就到此为止（陶仲的「不老」）
 ↓ 如果开放，才追承接
```

**后面 66 条新候选不能简单继续问「有没有效果」**，
要先问「**这条候选对应的对象，在该卷中到底被声明了什么**」——
**然后才知道什么叫「落点」。**

### ⚠️ 第三栏那四条「府里的人」，答案在库里的注释里

`royal-demote`（抄家那一卷）落效果给管家、门房、丫鬟、书童，**一个也没被点名**。
我本来要判「关系解析」，读注释才发现是**设计结论**：

> 从前这一卷的 `requires` 里挂着 `{ family: { id: steward, alive: true } }`
> ——理由充分：他在正文里说了两句话，而这一卷的决定就是他做的。
> 可他比玩家大 42–60 岁，而窗口是玩家九到十三岁……
> **一半以上的府里孩子读不到这一卷，而没有任何东西会报错。**
> 所以不是放宽那条 `requires`，是**给「他没了」写一支**。

**「没被点名」在这儿不是疏漏，是被 `doors.ts` 逼着去掉的。**

⚠️ 这是这一族**第三次**「库里的注释比我判得准」
（前两次：`birth:*` 取名那 13 条、`son:heard-of-a-place` 的承诺边界）。

### 「承诺边界内」那一档收了三族，而三族都是明文写过的

```
herbalist-at-the-shed          承诺「他不老」——给他落变化反而是错的
son:heard-of-a-place           承诺「第一次听见外部去处」，不承诺后续
son:grown / wife:her-own-way   认知节点，明写着不落状态
```

**那一档不是为了让候选变少发明的，是内容自己声明的。**

### ⚠️ 顺带修了一处尺子自己的报表缺陷

第二栏一律只印前十二名，于是「还没判的 11 条」写着，**而是哪 11 条印不出来**
——排在十二名之外的六族在输出里根本看不见。

> **报表把待办藏起来，比不报还坏。**

## 十八、这把尺子从此是【生产工具】，不是研究对象

跟 GPT 定的收尾：

> **让尺子去撞真实世界，而不是继续让真实世界只存在于尺子的校准样本里。**

审链**从主线降级成回归测试**：

```
写新内容
  ↓
跑现有七问
  ↓
抓到东西
  ├─ 已知故障   → 按现有尺子处理
  └─ 新型故障   → 再回来扩尺子
```

**现在最值得做的不是把尺子磨成理论上无懈可击，而是拿它去量下一批真要写的内容。**

### 而前三栏和承诺边界回答的是两组不同的问题

```
前三栏        人从哪里来？谁被点名？谁承受了结果？
承诺边界之后   这一卷到底承诺了什么？这个承诺在哪里闭合？
              如果开放，后续事实有没有兑现？
```

**下一轮不是继续堆候选数量，是给「纵向承接审计」建立真正的语义判据。**

## 十九、头一次拿尺子撞真实世界：邻居那条线

### 先量【观察机会基线】，防止「零候选」被读成「零问题」

跟 GPT 定的名字：**opportunity baseline**。它不判结论，只回答
「这把尺子在这儿有没有东西可量」。

```
全库提到邻居   29 处，分布 6 卷（census · dearth · house · playmate · regard · unrest）

拆开：
  事件入场里    1 件
  节点分流里    2 条
  落效果给他   【0 处】   ← 全库一次也没往邻居身上落过任何东西
  正文点名      6 处
```

**基线不是零**——所以沉默不能解释成「这儿没问题」，而要解释成别的。

### 而基线本身就是答案

```
配偶   被点名 16 次，落效果 1 次（而那一次是旗标）   ——她进得来，只是不被记
邻居   被点名  3 次，落效果 0 次                      ——他们【几乎进不来】
```

**配偶那一族是「主体事实出口缺失」；邻居这一族是「他们根本不是任何事件的主体」。**

那 6 处正文里承受者全是玩家：

```
「{hail:east-wife}你可算回来了。」        她来搭话，玩家被搭话
「腊月里的一夜，有人敲门。是隔壁那户的」   他来报信，玩家听信
```

**他们全是执行者**——而尺子早判过这两条（`east-wife` / `east-head` 各 1 条，
都判成执行者）。**判对了，只是当时我没意识到那是全库的全部。**

### 定性：越过了承接尺子的职责边界

```
判定链
  这个人是不是该事件的结果主体？
    是 → 承接尺继续审
    否 → 执行者／关系方／背景等合法角色 → 承接尺【停止】
         ↓
         如果设计认为他本应成为主体
         ↓
         这是【事件设计缺口】，不是【承接故障】
```

### ⚠️ 而旧结论要订正，两道

```
旧  「不是缺事件，是缺社会交叉」
```

**一、「缺社会交叉」说反了。** 数据说的是就是缺事件。

**二、而「缺事件」仍然太宽**（GPT 再收一档）：

```
事件存在性        有
邻居相关事件      有（29 处挂点）
邻居作为主体的事件  【0】
```

> **正式写法：缺少【以邻居为主体】的事件。**

⚠️ 而**还不能进一步说「该给邻居加哪一种事件」**——
互助、冲突、借贷、婚姻牵线、土地纠纷、灾害联动、邻里评价，
已经证明的只是「当前内容没有社会交叉结果」，没有证明该是哪一种。

## 二十、这个游戏里的「邻居」已经被世界写成了什么

按 GPT 定的顺序做的 C：**不假装拥有历史证据，而用已经拥有的一手世界事实**。

> C 的产出不是「找到一个邻居事件」，而是先回答
> **「这个游戏里的邻居，到底已经被世界写成了什么」**。

### 全库六句话，一句不漏

```
dearth:price          傍晚，{call:east-wife}站在门外，没像往常一样进来，
                      只在门口低声问{dam}：「你家……还有没有余粮」
house:divide          中人请的是{call:east-head}，和族里的一位长辈
house:divide-younger  中人请的是{call:east-head}
unrest:word           {hail:east-head}后山那边，你听见没有？
regard:homecoming     {hail:east-wife}你可算回来了
regard:homecoming     {hail:east-head}回来啦
```

### 形状出奇一致

```
荒年   她来【求】       站在门外，没像往常一样进来
分家   他来【做见证】   中人
兵祸   他来【报信】     后山那边你听见没有
归来   他们来【招呼】   你可算回来了
```

**四种事，全是「他来到你家门口」。** 一次也没有反过来。

```
他【知道你家的事】        荒年知道你家有没有余粮，分家时能当见证
他【会主动来】            求粮、报信、招呼，都是他迈的步
他【自己的日子没有一笔】  29 处挂点，零处落效果
```

⚠️ 而「**没像往常一样进来**」那一句最说明问题：**那四个字里藏着一整套
从没被写过的日常**——正文默认了两户之间有来往，而那个来往一次也没正面出现过。

### ⚠️ 而我从这儿推出的「反向」思路被驳回了，理由值得记

我提的是把已有四种各做一个镜像（求→被求、见证→被见证……）。GPT 的反驳：

> **「玩家该去邻居家」跟「邻居该成为主体」是两件事。**
> 前者已被当前世界事实支持为结构缺口；**后者只是设计选择，
> 不能让前者替它背书。**

而真正的形状是：

```
邻居家发生 X
      ↓
邻居【自身状态】发生变化
      ↓
玩家因为「隔壁」而知道 / 受影响 / 被卷入
```

**这才是从「执行者」向「主体」跨了一格。**

### 结论的正式写法（不要写成「缺少反向互动」）

> 现有邻居事件长期呈现为「邻居主动进入玩家生活」的单向结构。
> 正文还通过「往常一样进来」等措辞**预设了更广泛的日常往来，
> 而这些往来没有被正面呈现**。
> 下一步**不应机械补齐互动镜像**，而应优先寻找
> **「邻居自己的事情先发生，玩家随后因邻里关系而知晓、参与或受影响」**的事件。

四个镜像只作候选池，其中：

```
优先   邻居家自己的事情 → 玩家被请去见证
其次   玩家陷入荒年困境 → 去邻居家求助
暂弱   报信、招呼
```

### ⚠️ 而第一条新增邻居事件要证明的是这一句

> **不是「玩家终于能去邻居家了」，而是
> 「即使玩家什么都没做，邻居的人生也会自己往前走，
> 而玩家只是第一次撞见它」。**
