## 二、七种角色，只有最后一种要承接

判完 83 条候选（`requires` 28 + `branches` 55）之后长出来的：

⚠️ **「约束」这一档不是预先设计的，是判到第九族时它自己冒出来的。**

## 三、⚠️ 判准：不是「有没有状态写入」

跟 GPT 定的，这一句是这一族最要紧的判准：

```
✗ 是否存在状态写入？
✓ 【结果事实是否存在与其语义相称的承接？】
```

后者比「主体身上有东西」强得多，**而且不会把「亡」「杳」这种离散状态
误判成缺少程度值**。

### 承接至少有四型（`debt` 那条链一次给全了）

```
程度型          health 42 —— 他还活着，而此后每年更可能走
状态型          fate '殁'
状态 + 标记型   fate '杳' + flag father-missing
状态 + 认知型   编年「父亲再也没有消息了」
```

**一个完整的承接可以终止于 `fate`，也可以终止于 `doing`、关系、`flag`、编年。**
所以**不能拿「可量化的 health」当模板**。

## 四、「链」是什么：三层分开记，不揉成一条

```
事件因果链   天旱 → 借债 → 出外做工 → 归来／亡／杳
状态承接     归来 → health 42 → frailty 每年现读
认知承接     正文怎么表达这些事实
```

**发现某条链只有事件承接、没有状态消费时，能精确说出缺的是哪一层，
而不是笼统地判「链断了」。**

### 连接件是两种，而两种都不是机器可查的

```
旗标        共享状态证据      drought / father-in-debt / father-away
分路键      一次掷出来的      father-fate：归 62 / 亡 24 / 杳 14
```

**链不能只靠旗标，也不能只靠同一承受者**——旗标是共享状态证据，
同一承受者是主体一致性证据，两者都要跟明确的承接关系结合。

## 五、三颗真候选，同一个形状

```
bearing-await     妻子生    落在 son/daughter 和编年上
child-sibling     娘生      落在新弟妹和这一户上
wife-that-winter  娘病      落在配偶的照料上
```

**三颗都是「生育／病痛发生在一个女人身上，而世界记的是别人」。**

而 `child-sibling`（玩家小时候家里添了个弟妹）证明**这不是配偶一个人的事**
——它落的是 `family: sibling`、`household`、`chronicle`，
**而生这个孩子的娘身上一笔也没有**。

### ⚠️ 三颗卡在同一处，而那一处是【依据】不是【设计】

要落 `health` 得先定义「生育存在母体身体风险」这条世界规则，而史料
支撑得起「农村家庭分娩的母体死亡风险显著」，**支撑不起「有 X% 的
幸存妇女留下足以缩短余寿的长期身体损害」**。

> **`alive = false` 和 `health ↓` 是两个不同的世界事实，证据也必须分别对应。**

**三个用例说明这条规则该存在，而它们一个也没告诉我那个率是多少。**
用例多不等于依据有了。口径和状态在 `the-wife.md` 第八、九节。

## 八、⚠️ A 不是标准答案，是校准案例

审完 A（`debt` 那条链）之后，我手上是一个正例、三个负例、一条判准。
而正例只有一条——按「n=1 时什么都对」，拿 A 当标尺量出来的「相称」，
很可能只是「像 A」。

跟 GPT 定的转向，这是这把尺子从「感觉」走向「审计工具」的一步：

```
✗ A 是唯一正例，所以这个看起来不像 A
✓ 它不像 A 无所谓；请告诉我它【违反了哪个不变量】
```

> **A 不是「标准答案」，而是一组校准案例——
> 证明同一个纵向承接原则可以接受【不同形状】。**

A 内部三路的承接形状就各不相同（程度型 / 状态型 / 状态+标记型），
正文的重量也各写一件不同的事：

```
归  「他瘦了一圈，脸是黑的，手上多了几道口子」   ← 写身体
亡  「尸首没有运回来。太远了。」                  ← 写距离
杳  「钱也不捎了。」「{dam}托人去打听过一次。」   ← 写等待
```

**三路各自跟它那一路的状态相称，而相称的方式三路都不一样。**

## 九、真正可复用的那把标尺：六问

```
结果事实
  → 谁承受？
  → 它是什么事实？
  → 最低承诺是什么？
  → 承接是否表达了这个最低承诺？
  → 有没有越过它的语义边界？
  → 如果声明会继续影响世界，后续是否真的消费？
```

**前五项可以逐渐机械化**；最后的「相称」如果暂时机械不了，就留给人工判，
**但必须要求人工说出具体违反了哪条语义不变量**，不能只说「看着不像」。

### 而配套一条硬规则

> **凡是设计已经声明存在的承接层，都必须有对应证据；
> 不能凭「通常应该有」补出一层。**

因为承接本来就不必三层齐全：

```
事实 → 状态          就结束了，它没有玩家可见后果
事实 → 认知          而没有持久状态
```

**这跟拒绝给 `bearing` 强行补 `health` 是同一个原则。**

## 十一、B 链（侄儿那条）：承接在，而承接的【类型】不一样

```

           → 哥老了种不动地 → 侄儿回不回来，两支

状态承接   哥      doing '老了，种不动地了' + flag brother-home-for-good

           「{call:nephew}从镇上回来了。地不能荒。」
           「{call:nephew}没回来。老屋那几亩地，如今是{call:brother-wife}种着。」

```

### ⚠️ 承受者不是单数（GPT 指出的，我没看清）

```
A   事实 → 【同一主体】的状态变化 → 后续机制／认知
B   事实 → 哥的状态变化 → 家庭分流 → 【不同的人】承接后续处境
```

「地不能荒，所以有人接过来了」，**而那件事在正文里兑现了**。
它的终点本来就在认知层。

## 十二、⚠️ 第七问：字段是事实表达，还是字段驱动

B 链逼出来的。上一轮我据「`doing` 条件层问不了」**否掉了给配偶写换营生那一卷**，
而 B 链干的正是那件事——**同一个机制，一次判成「不够」，一次判成「够」**。

区别说得出来：

```
配偶那一卷   为了让 doing 从 1 变 2 而写   ← 拿【字段当目的】
B 链         处境变了所以做活的人换了      ← 字段是【后果】
```

> **同样是写入 `doing`，必须区分「世界事实要求这个字段表达自己」
> 和「设计为了制造字段变化而写这个字段」。**

### 所以尺子加到七问

```
事实产生
 ↓ 谁／什么承受？
 ↓ 产生了什么最低语义承诺？
 ↓ 状态或正文有没有表达这个承诺？
 ↓ 表达是否越界？
 ↓ 如果设计声明它还会继续影响世界，是否存在后续消费？
 ↓ 【字段本身是事实表达，还是字段驱动？】
```

⚠️ **最后一问目前可以问，不能自动判。**
而那不是这把尺子不成熟，是**正确的边界**：

> 凡是还无法从一手结构证据推出的，就保留为人工语义审查项，
> **不伪装成机器事实**。

## 十四、⚠️ 观察宇宙：尺子的取样【时刻】决定了它能看见谁

建第三栏时数对不上（它报 7 条，摸底量的是 23），查下去不是滤条件的事：

```ts
setActivePinia(createPinia())
const people = usePeopleStore()
for (const one of Object.values(people.roster)) PEOPLE.add(one.id)   // ← 一世也没演
```

收到 **24 人**——全是出生那一刻在册的。

```
在里头   father · mother · brother · sister · uncle · 邻家六个孩子 · 产婆 · 门房
不在里头 【嫂子 · 侄儿 · 儿子 · 女儿 · 配偶】——人生【中途才立起来】的人
```

**而被滤掉的恰恰是这一族最关心的那批**——B 链的分流承受者就是嫂子，
我正是因为她才建的第三栏，**而她被这把尺子自己滤掉了**。

改成演完再收：`24 人 → 45 人`，三栏候选 `28 / 55 / 7 → 52 / 97 / 20`。

### 正反两侧证据，两条不合并

```
完备性验收   拿【内容层写过的 id】去对名册      证明「收得全」
             对不上的只有两类：角色记号（恒定）、稀有出身（会飘）
依赖性打断   注释掉 story.begin() 看谁消失       证明「收的确实是演化后的」
```

⚠️ **而打断验头一版只证明了「这 15 个不在名册」——那不够。**
GPT 指出：某个人本来就不该在出生名册里的话，删掉演化后他继续不在，
**并不能证明打断打中了**。

改成两份名册直接对照，差集才是证据：

```
spouse / son / daughter / brother-wife / nephew   演完：在　不演：不在
只在【演完】那份里出现的：21 个
```

**这 21 个全是人生演化才产生的**——「它们原本在，而删掉演化就消失了」。

### 定性

> **采样点也是判据。尺子的取样点决定它能看见谁。**
> 此次故障是**人物全集在出生时采样**，而审计对象要求的是
> **本世完整演化后的世界人物全集**。

⚠️ 名册这类东西要定义清楚是哪一种，三者不能混：
**当前活着的人 / 本世曾存在过的人 / 世界实体全集**。这一支要的是第二种。

## 十五、⚠️ 先判【承诺边界】，再判承接

名册补全带来 66 条新候选，而它们大多来自配偶、儿子、嫂子、侄儿
——正是这一族在追的那批人，也正是**内容写得最新最薄**的那批。

我原本想的分法是「刚写的 vs 老内容」。GPT 换掉了：

> **不应该让时间新旧成为判据，而应该让「承诺边界」成为判据。**
> **先判承诺边界，再判承接。**

```
这条候选究竟是「没有承接」，还是【根本没有开放过那个承诺】？
                                    ↓
                        只有后者才进入真正的链审计
```

**新写的卷不是「还没长出承接」，是「它没有声明过后续」。**
一卷只声明「这件事发生了」，那它没承诺过什么；
一卷声明了「此后他就……」而没人读，那才是漏。

所以纵向承接审计正式加一层，排在最前：

```
先判承诺边界
  ↓ 这一卷开放了什么承诺？（可能是零）
再判承接
  ↓ 正确对象 / 正确事实类型 / 正确强度 / 正确时间 / 必要时后续机制消费
```

**这不是给新内容开后门，是给尺子补上一个它原本缺失的语义维度**
——否则直接拿「结果 → 后续状态」去扫，会把**尚未声明后续的内容**
误报成**已声明而未实现的内容**。
