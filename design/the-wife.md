# 配偶：一个天天在场而从未被看见的人（调查，2026-09-13）

> 这份是**动笔之前的调查**，照儿子那一册的做法：
> 先摊开「她身上有哪些事实、由谁生产、婚后变不变」，再谈写什么。
>
> **每一条都是一手量的。**

## 一句话

**「天天在场」被等价成了「没有生命周期」。**

儿子那一册验的是「一个人离开玩家视野之后仍然在生活」。
配偶要验的是**更基础的那一条**：一个**始终在你身边**的人，
是不是真的作为一个独立的人在持续变化。

## 她身上有哪些事实（成亲那一刻立的，全库四处）

```
who: { surname:'秦', given:'娘', gender:'女', age:20, doing:'操持家务' }
who: { surname:'陈', given:'娘', gender:'女', age:17, doing:'操持家务' }
who: { surname:'秦', given:'娘', gender:'女', age:18, doing:'操持家务' }
who: { surname:'林', given:'娘', gender:'女', age:18, doing:'管着家里的账' }
```

**姓氏会变，名字永远是「娘」。** 第五处是女玩家的丈夫
（`given:'大'`、`doing:'做工'`）。

## 而引擎给了她性情——六种都出

实测 40 次：温和 12 / 木讷 8 / 精明 6 / 刚硬 6 / 谨慎 4 / 暴躁 4。

跟儿子一样，立人那一刻引擎随机给的。**我一开始判她「连性情都没有」，
那是错的。**

## ⚠️ 而没有任何内容读它——这张对照表是这次调查的结论

```
全库读性情的处数：
  娘     10
  哥      8
  儿子    7      ← 这一天刚加的
  侄儿    4
  田主    2
  嫂子    2      ← 隔着一户、一年见几面
  配偶    0      ← 天天在场的那个人
```

**连嫂子都有两处，而配偶一处也没有。**

## 她一辈子说过六句话，全在同一个晚上

```
「夜里熄了灯，{call:spouse}忽然问你。」
「山上的事，你跟{call:spouse}说了。」
「{call:spouse}问起过药庐那边。你没说。」
「{call:spouse}听完很久没有说话。」
「此后{call:spouse}再没有问过。」
「{call:spouse}『嗯』了一声，翻过身去了。」
```

全部来自 `mountain` 那一卷「守不守得住那个秘密」——**而那一族的分母是 0.37%**。

> 98% 的人生里她在场，而她一辈子只有一个晚上有戏，
> 那个晚上还只有千分之三的人过得上。

## 婚后她的事实变不变——量完是【不变】

```
800 世，成过亲的 354 世
她一辈子的 doing 变过几种：【1 种，354 世全部】
```

**从成亲那天到死，一个字没变过。**

（终值：做工 167 / 操持家务 163 / 管着家里的账 24
——「做工」是女玩家的丈夫，各占一半。）

## 完整的一张表

```
配偶
├─ 姓名/身份       已有（而名字永远是「娘」）
├─ doing           已有，【一辈子一种】
├─ 年龄            引擎会推
├─ 性情            已有，六种都能产生，【零处内容读它】
└─ 婚后独立变化    【没有】——不是「没找到」，是量出来确实没有
```

---

## ⚠️ 不从「嫂子有 tie 所以妻子也该有」出发

跟 GPT 过完定的。**`tie` 是状态表达，不是内容生产者。**

一手核验：

```
妻子在正文里出现  9 处
其中跟娘同在一句  0 处     ← 她们之间【没有任何交互事实】
```

而嫂子那条边**是从事里长出来的**：

```
「娘跟嫂子一顿饭没说一句话。哥低着头吃。」
「嫂子给娘添饭，娘拉着她的手说话。」
「哥送你到巷口，压着声说了镯子的事——娘陪嫁的那副……」
```

**先有那顿饭、那副镯子，才有那条边。顺序不能反。**

现在建 `tie` 就是凭空造一个关系状态。

## 第一卷该写什么（还没定，等 GPT）

三个方向，性质不同：

```
A. 一件家务上的分歧      天天发生，不需要特殊条件
                        ⚠️ 容易写成「婆媳矛盾」套路
B. 一件她做对了而你没看见  娘病了那几天是她守的
                        ⚠️ 同时验证「你不在场时世界仍在发生」
                        ⚠️ 但要求娘病，那是另一卷的事
C. 先写【她被看见】       像 son:grown 那样：某一天你忽然看见她
                        ⚠️ 认知节点，不落状态
                        ⚠️ 而它能让「性情」那一格第一次有人读
```

**倾向 C 打头**：她现在缺的不是「一件事」，
是**这个世界从来没有看见过她**。先让她被看见，
再谈她跟谁之间发生了什么。

# 第二卷：过门那天（2026-09-13 定稿，已落地）

> 上面那份是动笔前的调查。这一段是第二卷的口径，跟 GPT 逐条过完定的。

## 一、第一卷立住了什么，又没立住什么

`wife:her-own-way` 让「性情」那一格第一次有人读。**而它是单向的**：
玩家在看，她在做，两个人之间没有发生任何事。
严格说，第一卷证明的是「她有自己的做法」，**不是「你们之间有关系」**。

## 二、⚠️ 「让她换个营生」这条路走不通——查证之后否掉的

原打算写「她的 doing 变一次」，理由是它可量（基线恒等于 1）。
**而那个理由本身有毛病：我是因为可量在选它，不是因为该写。**

GPT 要求先分四种诊断，不许从「数值没变」跳到「必须让她换职业」。查完：

```
机制成熟吗    成熟。{ type: 'person', id: X, doing: '…' } 用在九种人身上：
              侄儿 6 · 儿子 4 · 书童 3 · 管家 1 · 丫鬟 1 · 门房 1 · 爹 1 · 嫂子 1 · 哥 1
              【配偶 0】——连嫂子都有一次
她进过链吗    没有。全库内容里配偶只出现 11 处：
              match.ts 六处立人、wife.ts 五处（第一卷读性情）、ending.ts 一处
              而 ending 那处是【节点 id】，不是效果 → 人物效果是零
```

**她被造出来、被读一次性情、然后死。**

而真正否掉这条路的是第三问：

```
doing 有现实后果吗    只有一个，而且是展示层：
                      note.ts:135-137 人际面板那行字 `${称呼}${说的}${doing}`
                      条件层【根本问不了】一个人的 doing
                     （conditions.ts 里两处 character.doing 是【玩家的 undertaking】，另一回事）
```

**改她的 doing，改的是人际面板末尾几个字。** 那不是生命周期，是展示字段。

## 三、第三条路：年龄当因，已有世界事实当果

先例就在库里——「娘老了」：

```
kindred-mend   requires 娘活着且 ≥55、嫂子活着、她俩 tie 是【不睦】
               「娘老了病了一冬，是嫂子伺候的。你不在场。」
               → 那条 tie 从不睦变好
```

年龄当因、`tie` 当果、玩家不在场。**不新造任何东西。**

而配偶跟谁都没有边。所以查那条边当初怎么立的——**过门头一天**，
按两人性情分四档（`kindred.ts:206-228`）。

## 四、⚠️ 而这一天，玩家自己娶妻的时候没有

```
哥娶妻   有过门那一幕，娘在场，立下一条边，此后二十年那条边一直在被读
我娶妻   match.ts 立个人，就完了
```

**这不是「配偶缺一格」，是她少了别人都有的那一天。**

而且——`match.ts` 那句「过门那天，家里把压箱底的布拿出来让她做了件新衣」
压着一段注释，说原话是「**你娘**把家里压箱底的布拿出来」，后来把娘去掉了，
因为那一节无条件触发、在娘已经不在的人生里同样会演。

> **接触那件事一直在场，被刻意抽掉的是「娘」这个主语。**

那个抽象是为了让没有娘的人生也说得通；**而一个有条件的卷不需要它**。

## 五、射程（600 世一手量）

```
成过亲            47.5%
· 娘还活着        65.3%（占成过亲的）
· 娘跟我【同户】  37.9%   ← 这一节的分母
· 娘在【别的户】  27.4%
· 有一边查不到户   0.0%   ← 拆出来才说得清 37.9% 没被漏测压低
```

⚠️ **那 27.4% 不写分支，也不要补偿性内容。** `match` 那三档已经覆盖了
过门当天的普遍事实。这一节只在娘仍与你同户时把那件事**具体归给她**。

## 六、写的不是打招呼，也不是谁当家

哥那三句写的是照面，而**那一节玩家是旁观者**。这儿不一样：
娘的屋里从此多一个人过日子，**共同生活的边界头一回要商量**。

⚠️ GPT 的校正：别说「分权」，那会滑成「家庭权力结构」——
降级成「**共同生活边界的第一次协商／让步**」。

四支（实测 12 / 19 / 16 / 50，兜底占一半，跟哥那边同一个结构）：

```
两个都硬 → 不睦   屋里有两处地方各收拾了一遍，收的是同几样东西
她温和   → 亲厚   东西原先放在哪，她问过一遍才动；第三处娘没说，她就没动
娘温和   → 亲厚   她摆错了两样，娘没说自己挪回去；过两天娘摆到她顺手的地方
兜底     → 平常   屋里的事她做一半，娘做一半，谁也没说该怎么分
```

条件只有一条，现成的：`{ house: { with: '生母' } }`——一条顶「娘活着 + 同户」两问。

## 七、⚠️ 欠着的：这条边【还没有读取端】

全库读 `tie` 的条件五处：`brother-wife → mother` 四处、
`nephew → brother` 一处、**`spouse → mother` 零处**。

**写入端有、读取端零**——这个库记了一整族这种毛病，而这一卷刚造了一个。

嫂子那条边有四个消费端作对照：

```
kindred.ts:403-405   一幕按它分流
kindred.ts:1332-1333 娘的丧事按它分流
kindred-quarrel      要【亲厚或平常】——处得来的才有得翻
kindred-mend         要【不睦】
```

下一卷必须补读取端，而 GPT 定了它的形状：

> 后续消费的应该只是「她们之间已经存在怎样的关系」，
> 而不是系统认为「亲厚所以必须伺候」。

所以打算写成：**娘病的那阵子她都在跟前——因为同住一屋，这不由关系决定；
关系决定的是那段日子是什么样子。** 三支里她都照应，差别在质地。
