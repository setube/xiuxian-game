# 配偶：一个天天在场而从未被看见的人（调查，2026-09-13）

> 这份是**动笔之前的调查**，照儿子那一册的做法：
> 先摊开「她身上有哪些事实、由谁生产、婚后变不变」，再谈写什么。
>
> **每一条都是一手量的。**

## 一句话

**「天天在场」被等价成了「没有生命周期」。**

儿子那一册验的是「一个人离开玩家视野之后仍然在生活」。
配偶要验的是**更基础的那一条**：一个**始终在你身边**的人，
是不是真的作为一个独立的人在持续变化。

## 她身上有哪些事实（成亲那一刻立的，全库四处）

```
who: { surname:'秦', given:'娘', gender:'女', age:20, doing:'操持家务' }
who: { surname:'陈', given:'娘', gender:'女', age:17, doing:'操持家务' }
who: { surname:'秦', given:'娘', gender:'女', age:18, doing:'操持家务' }
who: { surname:'林', given:'娘', gender:'女', age:18, doing:'管着家里的账' }
```

**姓氏会变，名字永远是「娘」。** 第五处是女玩家的丈夫
（`given:'大'`、`doing:'做工'`）。

## 而引擎给了她性情——六种都出

实测 40 次：温和 12 / 木讷 8 / 精明 6 / 刚硬 6 / 谨慎 4 / 暴躁 4。

跟儿子一样，立人那一刻引擎随机给的。**我一开始判她「连性情都没有」，
那是错的。**

## ⚠️ 而没有任何内容读它——这张对照表是这次调查的结论

```
全库读性情的处数：
  娘     10
  哥      8
  儿子    7      ← 这一天刚加的
  侄儿    4
  田主    2
  嫂子    2      ← 隔着一户、一年见几面
  配偶    0      ← 天天在场的那个人
```

**连嫂子都有两处，而配偶一处也没有。**

## 她一辈子说过六句话，全在同一个晚上

```
「夜里熄了灯，{call:spouse}忽然问你。」
「山上的事，你跟{call:spouse}说了。」
「{call:spouse}问起过药庐那边。你没说。」
「{call:spouse}听完很久没有说话。」
「此后{call:spouse}再没有问过。」
「{call:spouse}『嗯』了一声，翻过身去了。」
```

全部来自 `mountain` 那一卷「守不守得住那个秘密」——**而那一族的分母是 0.37%**。

> 98% 的人生里她在场，而她一辈子只有一个晚上有戏，
> 那个晚上还只有千分之三的人过得上。

## 婚后她的事实变不变——量完是【不变】

```
800 世，成过亲的 354 世
她一辈子的 doing 变过几种：【1 种，354 世全部】
```

**从成亲那天到死，一个字没变过。**

（终值：做工 167 / 操持家务 163 / 管着家里的账 24
——「做工」是女玩家的丈夫，各占一半。）

## 完整的一张表

```
配偶
├─ 姓名/身份       已有（而名字永远是「娘」）
├─ doing           已有，【一辈子一种】
├─ 年龄            引擎会推
├─ 性情            已有，六种都能产生，【零处内容读它】
└─ 婚后独立变化    【没有】——不是「没找到」，是量出来确实没有
```

## ⚠️ 不从「嫂子有 tie 所以妻子也该有」出发

跟 GPT 过完定的。**`tie` 是状态表达，不是内容生产者。**

一手核验：

```
妻子在正文里出现  9 处
其中跟娘同在一句  0 处     ← 她们之间【没有任何交互事实】
```

而嫂子那条边**是从事里长出来的**：

```
「娘跟嫂子一顿饭没说一句话。哥低着头吃。」
「嫂子给娘添饭，娘拉着她的手说话。」
「哥送你到巷口，压着声说了镯子的事——娘陪嫁的那副……」
```

**先有那顿饭、那副镯子，才有那条边。顺序不能反。**

现在建 `tie` 就是凭空造一个关系状态。

# 第二卷：过门那天（2026-09-13 定稿，已落地）

> 上面那份是动笔前的调查。这一段是第二卷的口径，跟 GPT 逐条过完定的。

## 一、第一卷立住了什么，又没立住什么

`wife:her-own-way` 让「性情」那一格第一次有人读。**而它是单向的**：
玩家在看，她在做，两个人之间没有发生任何事。
严格说，第一卷证明的是「她有自己的做法」，**不是「你们之间有关系」**。

## 二、⚠️ 「让她换个营生」这条路走不通——查证之后否掉的

原打算写「她的 doing 变一次」，理由是它可量（基线恒等于 1）。
**而那个理由本身有毛病：我是因为可量在选它，不是因为该写。**

GPT 要求先分四种诊断，不许从「数值没变」跳到「必须让她换职业」。查完：

```
机制成熟吗    成熟。{ type: 'person', id: X, doing: '…' } 用在九种人身上：
              侄儿 6 · 儿子 4 · 书童 3 · 管家 1 · 丫鬟 1 · 门房 1 · 爹 1 · 嫂子 1 · 哥 1
              【配偶 0】——连嫂子都有一次
她进过链吗    没有。全库内容里配偶只出现 11 处：
              match.ts 六处立人、wife.ts 五处（第一卷读性情）、ending.ts 一处
              而 ending 那处是【节点 id】，不是效果 → 人物效果是零
```

**她被造出来、被读一次性情、然后死。**

而真正否掉这条路的是第三问：

```
doing 有现实后果吗    只有一个，而且是展示层：
                      note.ts:135-137 人际面板那行字 `${称呼}${说的}${doing}`
                      条件层【根本问不了】一个人的 doing
                     （conditions.ts 里两处 character.doing 是【玩家的 undertaking】，另一回事）
```

**改她的 doing，改的是人际面板末尾几个字。** 那不是生命周期，是展示字段。

## 三、第三条路：年龄当因，已有世界事实当果

先例就在库里——「娘老了」：

```
kindred-mend   requires 娘活着且 ≥55、嫂子活着、她俩 tie 是【不睦】
               「娘老了病了一冬，是嫂子伺候的。你不在场。」
               → 那条 tie 从不睦变好
```

年龄当因、`tie` 当果、玩家不在场。**不新造任何东西。**

而配偶跟谁都没有边。所以查那条边当初怎么立的——**过门头一天**，
按两人性情分四档（`kindred.ts:206-228`）。

## 四、⚠️ 而这一天，玩家自己娶妻的时候没有

```
哥娶妻   有过门那一幕，娘在场，立下一条边，此后二十年那条边一直在被读
我娶妻   match.ts 立个人，就完了
```

**这不是「配偶缺一格」，是她少了别人都有的那一天。**

而且——`match.ts` 那句「过门那天，家里把压箱底的布拿出来让她做了件新衣」
压着一段注释，说原话是「**你娘**把家里压箱底的布拿出来」，后来把娘去掉了，
因为那一节无条件触发、在娘已经不在的人生里同样会演。

> **接触那件事一直在场，被刻意抽掉的是「娘」这个主语。**

那个抽象是为了让没有娘的人生也说得通；**而一个有条件的卷不需要它**。

## 五、射程（600 世一手量）

```
成过亲            47.5%
· 娘还活着        65.3%（占成过亲的）
· 娘跟我【同户】  37.9%   ← 这一节的分母
· 娘在【别的户】  27.4%
· 有一边查不到户   0.0%   ← 拆出来才说得清 37.9% 没被漏测压低
```

⚠️ **那 27.4% 不写分支，也不要补偿性内容。** `match` 那三档已经覆盖了
过门当天的普遍事实。这一节只在娘仍与你同户时把那件事**具体归给她**。

## 六、写的不是打招呼，也不是谁当家

哥那三句写的是照面，而**那一节玩家是旁观者**。这儿不一样：
娘的屋里从此多一个人过日子，**共同生活的边界头一回要商量**。

⚠️ GPT 的校正：别说「分权」，那会滑成「家庭权力结构」——
降级成「**共同生活边界的第一次协商／让步**」。

四支（实测 12 / 19 / 16 / 50，兜底占一半，跟哥那边同一个结构）：

```
两个都硬 → 不睦   屋里有两处地方各收拾了一遍，收的是同几样东西
她温和   → 亲厚   东西原先放在哪，她问过一遍才动；第三处娘没说，她就没动
娘温和   → 亲厚   她摆错了两样，娘没说自己挪回去；过两天娘摆到她顺手的地方
兜底     → 平常   屋里的事她做一半，娘做一半，谁也没说该怎么分
```

条件只有一条，现成的：`{ house: { with: '生母' } }`——一条顶「娘活着 + 同户」两问。

## 七、⚠️ 欠着的：这条边【还没有读取端】

全库读 `tie` 的条件五处：`brother-wife → mother` 四处、
`nephew → brother` 一处、**`spouse → mother` 零处**。

**写入端有、读取端零**——这个库记了一整族这种毛病，而这一卷刚造了一个。

嫂子那条边有四个消费端作对照：

```
kindred.ts:403-405   一幕按它分流
kindred.ts:1332-1333 娘的丧事按它分流
kindred-quarrel      要【亲厚或平常】——处得来的才有得翻
kindred-mend         要【不睦】
```

下一卷必须补读取端，而 GPT 定了它的形状：

> 后续消费的应该只是「她们之间已经存在怎样的关系」，
> 而不是系统认为「亲厚所以必须伺候」。

所以打算写成：**娘病的那阵子她都在跟前——因为同住一屋，这不由关系决定；
关系决定的是那段日子是什么样子。** 三支里她都照应，差别在质地。

## 八、这一卷没接的两支，各有理由

# 第三卷：娘病的那半个月（读取端）

上一卷造了一条 `spouse → mother` 的 `tie`，而交付时**读它的条件是零处**。
这一卷补的就是那一头——写入端有、读取端零，是这个库记了一整族的毛病。

## ⚠️ 关系不决定她做不做，只决定那段日子是什么样子

跟 GPT 过时定死的，它挡的是一种很容易滑进去的写法：

```
✗ 亲厚 → 她伺候；不睦 → 她不伺候      从 tie 直接推行为，那是游戏规则
✓ 同住一屋，娘病了她都在跟前——【这不由关系决定】
  关系决定的是：那半个月是什么样子
```

```
亲厚   「夜里是她守着。」「有一夜娘迷糊，叫了她的名字。」
平常   「药是她煎的，饭是她端的。」「两个人话不多。」
不睦   「药是她煎的，一顿没落下。」「娘不肯让她喂，自己端着碗。
        她就把碗放下，站在一边等娘喝完。」
```

**三支里她都没少做。不睦那一支尤其：不是她不肯做，是娘不肯受。**
少了这一层，这一卷就成了「关系好的媳妇孝顺」，而那是标签不是世界。

门槛四条：`gender 男`、`house.with 生母`、配偶活着在身边、娘 ≥58 岁。
窗口 22–78（章的目录同步改成 20–78——`verify` 会查这两者对不对得上）。

# ⚠️ 这一册交付过一个缺陷：正文写「她」，而玩家 48.5% 是女的

`wife:her-own-way` 头一版入场只问 `{ bond: { kind: '配偶' } }`。
而女玩家的配偶是男的（`match.ts` 的 `husband` 那一支，`given: '大'`），
于是「过了一会儿**她**才回来」落在一个男人身上。

```
2000 世实测   household.gender === '女'   971 / 2000 = 48.5%
```

**十一支门禁全绿，没有一支抓得到它**——那是「内容措辞 ↔ 玩家收到的事实」
那一层，机器够不着。

## 而它不是查出来的，是另一个数的偏斜供出来的

量第三卷分流时看见比例对不上：

```
立边时   亲厚 29 次、平常 48 次
读边时   winter-fond 5 次、winter-plain 35 次   ← 亲厚只有 5 次被读到
```

追下去，那 35 次里大半是女玩家——她们没走过立边那一节，全落进兜底。
加上 `{ gender: '男' }` 之后三支比例当场正常（3 / 3 / 13）。

> **缺陷本身不会红，是它在另一个数上留下的偏斜把它供出来的。**

## 判法（跟 GPT 定的三分）

```
A 路不通          Hits == 0                      → 生产者/条件/分流
B 路通但【人错】   Hits > 0 而违反语义不变量        ← 这一次
C 人对但分布异常   满足不变量，而某支严重偏斜       → 生产链/世界生成
```

**不必每卷全面分布对账。建立「命中者语义不变量」就够了；
分布量保留为异常探测器，不是证明器。**

写完一卷，除了问「三支都非零吗」，再问一句：
**走到这一卷的那批人，有没有一条该恒成立而我没写进 `requires` 的？**
正文写「她」就得问性别；正文写「你爹说」就得问爹在不在。

# 第四卷：查到一个机制缺口，而不是写了一卷（2026-09-13）

跟 GPT 过完之后的结论是**先别写**。这一段记的是查到了什么、为什么停。

## 一、先否掉的那条路：「她自己老了」

引擎里确实有一条衰老曲线，非玩家触发、真的在推进：

```
span    = rollSpan(health)                        天年，掷一次【存回去冻住】
pivot   = max(45, span - 45)                      多数人落在 45
frailty = (age-pivot)*0.004 + max(0, 50-health)*0.0016   每年的死亡概率
```

⚠️ **而那条曲线没有任何人看得见。**

```
frailty   算出来当场用掉，不存、不落、条件层问不了
span      存在人身上，条件层也问不了
age       算出来的，条件层【问得了】
health    条件层【问得了】（conditions.ts:207）
```

**从「好好的」到「殁」之间，世界里只有一个概率在暗处走。**
没有「病了」「弱了」「起不来了」这样的事实。

所以「她老了」这件事在这个世界里落不下来——**衰老作为独立中间状态是机制缺口。**

## 二、health 跟 doing 不一样，但全库只有一处在读

```
doing     条件层【问不了】   → 上一轮据此否掉了「让她换营生」
health    条件层【问得了】   → 而全库只有 refuge.ts:169 一处在读（craft-master）
```

而它有 `doing` 没有的性质：

```
写入端    birth ×3、people:1151 默认、meeting:111、effects:483（person 效果可改）
          内容层【真的改过】：hardship.ts:251  health: 42
读取端    span（冻住）、frailty（每年现读）、conditions、refuge 一处
```

**改 health 不是展示**——`frailty` 每年现读，改了就一直起作用。
⚠️ 细节：`max(0, 50 - health)` ——**只有掉到 50 以下才起作用**，60 降到 55 什么也没发生。

## 三、已有的「身体损伤」生产者只有一条，而她够不着

```
hardship.ts  debt:return   出外做工还债 → 「瘦了一圈，手上多了几道口子」
                           doing: '{livelihood}，腰不太好'   health: 42
```

**重活／远行 → 身子骨垮了。** 而她不出门。

## 四、⚠️ 而 `bearing` 是一件真发生在她身上、世界却记在别人名下的事

```
入场      bond 配偶 alive
落的效果  chronicle 5 · time 3 · roll 3 · undertake 2 · meet 2 · household 1 · flag 1
落到谁    son 2 · daughter 2 · spouse 【0】
三次掷    怀上没有 70/30 · 孩子活不活 80/20 · 男女 50/50 ——【没有一次掷她】
```

三支的原文里她一个字也没有：

```
生女   「是个女孩。」「头三天她一直闭着眼。{elder}守了三夜没敢睡。」
lost   「孩子没有哭。」「产婆没说话，把东西收了收就走了。」
```

**`{elder}` 是长辈，`产婆` 是外人，「她一直闭着眼」那个「她」是婴儿。**

### ⚠️ 我在这儿过度宣称过一次，记下来

我先写的是「库里已经写到了她最接近死的那一刻」——**那是我读进去的**。
库里写的是「孩子没留住」，而那一刻**她在不在场、出没出事，正文一个字也没说**。

```
✗ 现有正文已经表达了她的身体受损，只是没落到字段上   ← 不实
✓ 现有正文表达了这件事发生过，而【关于她的那一半从没写过】
```

## 五、所以停在这儿：这是机制缺口，不是内容补丁

GPT 的裁决：

> 「补一半」足够支持第四卷继续调查 `bearing`，**但不足以直接授权 health 效果**。
> 如果建立「生育存在母体身体风险」的机制，顺产和 `lost` 都该进入，
> 而**两者不应该简单按照孩子死没死来决定母体伤害**。
> **如果补，就应该把它作为机制补，而不是内容补丁。**

而它拦住的那个写法确实是我差点要写的：

```
✗ 生一次孩子 = 永久扣 X health          那是剧情伤害值，不是身体条件
✓ 生育是一件有身体风险的重大事件，多数情况平稳过去，
  一部分情况留下长期后果
```

### 那一节压着一条【用户定的护栏】，它先定死了一件事

```
掷的是孩子有没有活下来。**这一掷玩家看不见，也没得选**——

```

**所以「生育风险」不管怎么定，玩家面前不能有按钮。**
不能有「请更好的产婆」「多花点钱」这种选项。

而「八成活」那个数的出处同样写在那儿：

```
八成活。这个数照的是「多数孩子活下来了」这个事实，
而那两成不是为了让玩家难过，是因为这个时代的人
谈起自己有几个孩子时，说的往往是「生了五个，活了三个」。
```

**数的出处是「那个时代的人怎么说话」，不是难度曲线。**

    理由：库里那一掷叫 newborn-lives，名字就说了它判的是孩子。

四、可不可能完全没有长期后果     【绝大多数情况必须是「没有」】

### ⚠️ 而卡在最后一步：那个数没有出处

第四条一旦成立，这个机制就**极其稀有**——多数世界里它什么也不做。
而这个库有一条硬纪律：**零次比稀有要紧**。

于是问题变成：一个「绝大多数时候什么也不做」的机制，怎么定它的率？

GPT 的裁决，我接受：

> 先找史料能支撑什么层级的事实，再决定抽象到什么程度。
> 而不是「我希望每 500 世至少出现几次，所以设 0.2%」。
> **这两者必须绝对分开。**

而史料（GPT 引的 PubMed：1984–85 中国大规模资料、后续农村监测）支持的是
**农村家庭分娩的母体死亡风险显著，产科出血是主要死因**
——**而它支撑不了「有 X% 的幸存妇女留下足以缩短余寿的长期身体损害」**。

### 最要紧的那一句：两个世界事实，证据要分别对应

> **不要把「死亡」偷换成 `health` 下降。**
> `alive = false` 和 `health ↓` 是两个不同的世界事实，证据也必须分别对应。

这正是我差点做的事：手上只有死亡那一侧的依据，而想写的是身体损伤那一侧。

那比为了让第四卷跑出来硬塞一个 0.3% 更符合这个库的纪律。
