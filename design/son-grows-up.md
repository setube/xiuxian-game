# 儿子长大以后（地基，2026-09-13）

> 起因不是「想加内容」，是全库扫条件挖出来的一个洞：
> `festival:midautumn` 的 `CHILD_AWAY`（「孩子今年没回来」）
> **被问 665 次，一次也没成立**——而一手核验发现，
> 全库提到玩家儿子的只有 `bearing.ts` 三处，**全在出生那一刻**。
>
> 此后整个世界对他是空白。而已经有三处内容在等他长大。
>
> 这份文档是动笔之前先立的口径。**每一条都标了出处。**

## 一句话

**他从「你的孩子」变成「一个人」。**

父亲的意见很重要，**但不是世界规则**。这一卷不是「儿子想去哪 →
玩家允许/拒绝 → 产生收益」——那会把他做成玩家的第二个角色面板。

最值得写出来的两种情形恰恰是：

```
你不同意，他还是去了。
你催他出去，他反而不想走。
```

## 硬事实（动笔前量的，600 世）

| 量 | 数 |
| --- | --- |
| 有过儿子 | 88 世（14.7%） |
| 儿子长到 16 岁 | 83 世（94% 都活到成年） |
| 那一年玩家岁数 | 中位 **37**（人生正中段，往后还有二三十年） |
| 那一年玩家还活着 | **83/83——他一定在场** |
| 那一年家境 | 中位 57 |
| 那时家里过的日子 | farm 36 · shop 16 · craft 10 · yamen 7 · hunt 7 · clinic 5 · office 2 |

⚠️ **最后一行是硬约束**：家里过的日子分散在七种，
**不能只写「农家的儿子去镇上」**。

## 三条路，第一版只写这三条

| 路 | 是不是「离家」 | 出处 |
| --- | --- | --- |
| ① 留在家中／继续本户生计 | 否 | 跟 GPT 过完定的 |
| ② 去镇上做工／学艺 | **是** | 同上；库里基础设施最全 |
| ③ 读书 | 看情形 | 同上；接 `schooling` 那一册 |

**分家、入赘、从军先不做**——不是不合理，是**它们改变的东西太多**。

### ① 留下不是「什么也没发生」

它跟出去一样有生命周期：继续跟着干活 → 学会本户营生 →
慢慢承担家事 → 成婚 → 以后分出去另立门户 → 最终接过这个家。

**留下本身就是一种人生选择。**

### ② 去镇上是第一条该做的离家路线

因为世界已经证明了它——**这不是凭空新增一套系统**：

```
away.ts        哥在镇上做木匠那整整一册
nephew.ts      侄儿去镇上当学徒
town           已经是成熟空间
Person.livelihood / House.livelihood   人的营生和户的营生已经分开
离家、回来、关系变化                    基础设施都在
```

### ③ 读书**不做成 `schooling` 的复制版**

值得写的是「**一个孩子到底为什么会走上读书这条路**」：
他确实聪明 + 家里有人注意到 + 有人愿意教 + 家里承担得起 + 他自己也愿意。

不是「出现『读书』选项 → 点击 → 进入读书线」。

## 结果由什么决定（不是由玩家的按钮决定）

```
儿子的性情 + 年龄 + 家庭年景 + 家庭营生 + 有没有具体机会
+ 父亲态度 + 师傅/雇主愿不愿意 + 家庭关系 + 偶然
```

父亲能做的是：答应、劝他再等等、说家里离不开他、帮他找师傅、
不给路费、要求他先把今年的活做完——**这些是影响因素，不是开关**。

这样 `leanings` 那一族的立意才继续成立：

> 念头是人生经历的产物，**选择是影响因素，不是剧本开关**。

## `CHILD_AWAY` 是结果，不是目标

**不在设计阶段规定「去镇上以后中秋必须有概率不回来」。**
要定义的是另一件事：

> 一个已经离开家、在外谋生的人，**什么情况下会回来，什么情况下不会**？

三层，而**第二层最重要**：

| 层 | 内容 | 分量 |
| --- | --- | --- |
| 一、距离 | 本县镇上回得来；更远的成本明显增加 | **不该直接决定回不回** |
| 二、当年的事务 | 师傅正赶一批活、雇主不放人、刚接到新差事、逢农忙、身上有病、刚换地方 | **最重要**——比「他走得远」真实得多 |
| 三、关系 | 父子关系好更愿意想办法回来；冷淡则不 | 影响意愿，**不能是唯一开关** |

`CHILD_AWAY` 从这个系统里**自然产生**。

## 跟 `nephew.ts` 那一册的分别

那一册写得很成熟，可有一条**不能照抄**：

> ## 你不在场
> 他走没走成、父子后来和没和好，两卷都没有正文、不进编年——
> 发生的时候你在自己家。你在下一回正月看见。

侄儿那一册的分寸建立在「隔着一户」上。**儿子是你自己家的事，你就在场**
（实测 83/83 世玩家都活着）。

但**「在场」不等于「说了算」**——这正是上面那句「他从你的孩子变成一个人」
要处理的东西。

## 不做的

- **不建雇佣关系**：铺子的东家是谁没有格（照抄 `nephew.ts` 的口径，
  用户 2026-09-07 定过）
- **不加「父子亲密度」格**：关系变化只来自具体事件
  （用户在关系系统那一轮定的两条禁令）
- **不写 `if !nearby: bond--`**：同上
- **不做「选项→收益」**：见上面那一句

## 施工顺序

```
一、先写「他长大了」——那句已经在等的 seen 有了下文
二、再写②那条路（去镇上做工／学艺）
三、②走通之后，回来那一层（含中秋回不回来）才有得写
四、①和③留到②验过之后
```

⚠️ **每一步走完先量到达率**，别攒到最后
（这几轮反复撞到的：写完才发现演不到）。

## 第一步已落地（2026-09-13，`6a11a9a`）

`son:grown`，四种看见由性情分。到达率 61/63 世有子（96.8%），
四条分支全走到（21 / 20 / 12 / 8）。

### ⚠️ 它是【认知节点】，不是无效节点

不落旗、不进编年、不给好感，**而那不等于它没有作用**：

```
son:grown  = 玩家第一次【重新认识】这个人
           ≠ 玩家第一次【处理】一个事件
```

**别为了「证明它有用」给它加奖励、好感、性情旗或编年记录**
——那会把一次细腻的观察重新游戏化。哪天真有内容要引用
「他记得家里的账」这类事实，**那时候再落**。

## 第二步的形状（跟 GPT 过完定的，还没动笔）

### 不先写「念头系统」，先写一个具体的「机会出现」

```
son:grown
    ↓
son:heard-of-a-place  ← 一个具体的去处第一次进入这个家庭的视野
    ↓                   （命名理由见下）
son:goes-to-town
```

现实中的离家不是「我今天产生了一个抽象念头」，而是：

> 我原本有些想法 **+ 有人告诉我一个具体机会** + 这个机会让我认真考虑离开。

具体机会可以是：镇上某家木匠缺学徒、某个熟人愿意带他去做工、
某个雇主需要短工、某位读书人愿意收一个识字的孩子、某个亲戚传来消息。

### ⚠️ 机会出现 ≠ 他决定去了

第二步的结果**限定为「机会被带到家庭面前」**，不是「机会出现 → 儿子离家」。
这样后面才有空间容纳「你不同意他还是去了」「你催他他反而不想走」。

### 三层不能合成一个旗

```
① 他有没有某种倾向
② 他有没有一个具体机会
③ 他是否真的采取行动
```

### 第二卷要证明的三个事实，以及【不许】自动成立的六件

跟 GPT 过完之后钉死的：

```
✓ 外部确实存在一个去处
✓ 这条消息确实传到了家里
✓ 家里知道有这个去处

✗ 儿子已经想走          ✗ 儿子已经答应
✗ 父亲已经同意          ✗ 儿子已经离家
✗ 这个机会一定适合他     ✗ 这个机会一定会再次出现
```

> 否则「听说有个去处」会**偷偷变成「离家路线的起点开关」**。

整条链是这样，而**这一卷只负责第二步，最多让第三步发生**：

```
外部机会存在 → 消息传到家里 → 家里知道有这个去处
             → 是否认真谈、是否试做、是否答应 → 是否真正离家
                ↑ 不要越过这一步
```

### ⚠️ 消息来源不立人——立了就成稀卷

400 世实测，**儿子长大那一刻谁在场**：

```
配偶      98%
童年玩伴  37%
哥        16%   ← 而哥还得【在镇上】：「当过木匠」只有 3.2%，
                  其中改行去镇上的占 12%——合起来 0.5% 量级
东邻       5%
```

**靠具体某个人捎话，分母立刻掉到 37% 以下**，而这一卷本身只有 14.7%
——再乘一次就是稀卷（这几轮反复撞到的墙：分家请玩伴做中人 1%、
荒年 × 当家 0.8%）。

所以消息来源**用库里现成的「不立人」形状**：

```
days.ts     { doing:'town', omen:'book', text:['庙前那个货郎的摊角…'] }
            那个货郎【没有 id】，他只是「镇上有这么一档事」
exam.ts:538 「镇上有人家请西席，托人来问你」——「托人」那个人也没有 id
```

写「镇上有人来问，说他家铺子想寻个学徒」，**谁来问的不写**。
这跟 `nephew.ts` 那条规矩是一路的：

> 铺子的东家是谁没有格——他「在镇上一家铺子里」，
> 那铺子不是人也不是组织。

⚠️ **准确的说法不是「消息来源是镇上」**，而是：

> 消息来源**不具名**：机会发生在镇上，消息通过未具名的现实来往
> 传到家中。当前内容只保留机会及其抵达事实，**不建立传话人的持久身份**。

省略的是「不影响当前事实的中间人」，**不是取消消息传播**：

```
世界事实层   某个具体的人听见消息，把它带到了这个家   ← 仍然发生了
内容呈现层   「镇上有人来问，说他家铺子想寻个学徒」   ← 没写他是谁
```

**不许写成**「镇上知道你儿子长大了，便给他送来一个去处」
——那把「镇上」写成了有全知视角和主动意志的主体，破坏世界的具体性。

哪天后续剧情要这个传话人继续出现（承担承诺、传递条件、见证结果），
**那时候再给他立人**。现在不为了「消息必须由人传递」提前造角色。

⚠️ **「家里知道」不等于「全家每个人都知道」**：正文只写父亲和儿子
听见了，知识范围就停在这两个人。配偶、别的孩子知不知道，
由文本实际表达定——这守的是
「世界事实 ≠ 玩家认知 ≠ NPC 之间各自的认知」。

### 机会**不按家庭营生分化**

**根本理由不是分母**（那只是工程约束），而是：

> 这一卷要表现的是「**一个家庭第一次听见外部去处**」，
> 不是「根据家庭职业生成适配职业机会」。

按七种生计拆开，系统会不知不觉变成：

```
家庭营生 → 可匹配职业 → 适配机会 → 传话内容
```

——**那就把一件生活事件改造成了职业匹配系统**。

而且它会把家庭营生变成命运门槛：家里不是木匠，不代表儿子
不能接触木匠铺；家里不是商户，也不代表他不能去当伙计。

（分母那一层同样成立：那一年家里过的日子有七种——
farm 36 · shop 16 · craft 10 · yamen 7 · hunt 7 · clinic 5 · office 2
——一分就是七条，每条都薄。）

而「镇上有铺子要人」对哪种人家都成立：农户的儿子去当伙计、
匠户的儿子去别家学手艺、铺子人家的儿子去更大的铺子——
**同一件事的不同读法**，正文不点破它是哪一种。

### 命名

```
卷 id    son:heard-of-a-place    「有个去处」——说的是一件外部的事
title    镇上捎来的话
```

不叫 `son:restless`（那个词暗示他已经不安，而「他有没有倾向」
这一层先不做成状态）、不叫 `son:opportunity`（太像系统词，
这个库的卷名都是具体的：「二两银子」「哥去了镇上」）。

### ⚠️ 不复用玩家的 `leanings`

一手核验（`stores/leanings.ts`）：那个 store 是
`Record<念头id, 状态>`——**整个只有一套念头，没有「谁的」这一格**。
它只能是玩家的。

**不要为儿子这一条线把它改造成 NPC 通用念头系统**：

```
一、玩家念头和 NPC 念头不是同一种运行对象
     玩家：经历 → 念头 → 选择
     NPC： 自身经历 + 性情 + 家庭 + 关系 + 机会 + 所知信息 → 倾向 → 可能行动
二、NPC 念头不该一出现就是玩家可见事实
     儿子可能想去镇上，而父亲未必知道——
     少了 `son.倾向` vs `玩家知不知道` 这一层区分，
     系统会默认「NPC 心里想什么玩家就知道什么」，
     破坏「世界事实 ≠ 玩家认知」
三、当前只有一个真实使用者，不值得建通用框架
     真正的需求只是「儿子成年后，有时会产生离家谋生的念头」
```

## 第二步已落地（2026-09-13，`bf292b9`）

`son:heard-of-a-place`「镇上捎来的话」。四条分支分的是**他怎么听见的**，
不是他想不想去。不落旗、不进编年、不给选项。

### ⚠️ 门槛靠儿子的岁数收，不靠 `chance`

头一版窗口 36–60 + `chance: 0.35`，**实测 94% 都撞上**。
`LifeEvent.chance` 那一格的注释写着：它挡的是「回回是它」，
**挡不住「一辈子撞不撞得上」**——二十四年反复掷，累计几乎必中。

收成儿子 17–20 岁（寻学徒寻的就是这个岁数，过了二十该说亲该顶事了），
94% → 44%。**而这正好落实了「✗ 这机会一定会再次出现」那一条**：
没赶上那几年，它就不再来。

## 第三卷的形状（跟 GPT 过完定的，还没动笔）

### 它跟前两卷性质不同

```
son:grown              认知节点，不改世界
son:heard-of-a-place   消息到了，不改世界
son:goes-to-town       ← 唯一会真正改变世界状态的一卷
```

### 核心原则

> **选项改变过程中的事实与关系，结果由这些事实参与后续判断，
> 而不是由选项直接指定。**

选项不是「结果按钮」，**但也不能只是装饰**。

### 「父亲态度」不抽象成 support/oppose，写成具体行为

```
✗  fatherAttitude = oppose → 儿子不去      ← 隐藏开关，禁止
✓  「跟他说家里眼下离不开人」                ← 这是世界事实
```

后续儿子的反应**观察这些行为**，不读一个抽象态度值。

### 第一版只放三个选项——它们重量级相同

```
跟他说家里眼下离不开人      对儿子表达家庭约束
问他那家铺子的东家是什么人   询问机会可靠性
什么也没说                 不介入
```

⚠️ **「托人去镇上打听一句」不放进第一版**：它不是态度表达，
是**一条新的行动链**（找谁去 → 他愿不愿意 → 去没去成 → 带回什么），
放进去就成了「点一下系统自动给调查结果」。
等有了合资格的现实联系人再说。

### 三段式：不「选完立刻判去不去」

```
第一段  父亲的回应        玩家选一个具体行为
第二段  儿子的反应        ← 【不立即分「去」和「不去」】
                          只写他对父亲行为的反应，
                          反应由性情、机会、家庭处境共同定
                          （「他没有争，只说知道了」「那要等到什么时候」
                            「能不能先去看一眼」「等这一季忙完再说」）
第三段  真正的去向        过一段时间之后，由世界条件决定
```

第二段是关键：**让玩家看见选项确实进入了人物之间的现实互动**，
而不是变成一次隐藏骰子。

### 「选项没用」这个担心怎么答

```
伪选择   选了什么都一样，后续关系、消息、时间、条件全部相同
真选择   选项【影响过程，不保证结果】
```

「说家里离不开人」可以增加家庭约束的现实重量，**但不能自动把他锁在家里**。
它改变的是：他对家庭处境的认知、他是否先完成一段家中事务、
离家时是带着歉意还是沉默、日后父子怎么继续。

⚠️ **而这些影响眼下没有承载系统的，不要为了证明选项有效
就立刻新增一堆好感值、关系值、记忆旗**——先让影响体现在
实际内容和后续事件资格上。

### 「家里少个劳力」照 `hardship` 那一族的形状

一手核验：那一族用 **`father-away` 旗 + `household.standing` 变化**
（`hardship.ts:146/253`），而且有配对的 `father-home` 把它撤掉。
卷宗宗旨写着「把『家里少个劳力』变成**后面事件读得到的事实**，
而不是一句旁白」——**这一卷沿用同一个形状**。
