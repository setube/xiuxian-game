# 模拟修仙人生

一款纯文字的人生模拟。**纯文字，但仍然是一款游戏** —— 丹青水墨只是视觉风格，
不能压过交互、信息层级和游戏功能。

它模拟的是：**一个人在一个存在修行者、超凡力量和普通人的世界里，
究竟会怎样度过自己的一生。**

出生 → 长大 → 攒下自己的经历、欲望、关系和对世界的看法 → 某些道路慢慢变得要紧 →
可能走上修行，也可能一辈子不走。**修行只是其中一条路**——极其稀有、风险极高、
但可能改变一个人的寿数和他眼里世界的样子。

一生从出生跑到咽气。天年在出生那一刻掷定（`engine/lifespan.ts`），
**没有任何一卷内容能提前终止人生**。跑 `bun scripts/lifelong.ts`
看当下这一批的样子：六千世里咽气的岁数中位六十出头，两头在四十五到八十几之间，
碰上修行那件事的一成上下。

> 这三个数每跑一批都会挪一两点——它们是六千世抽出来的，不是配置里写死的。
> 底下凡是带百分比的说法都同理：**看的是量级，不是那个小数点**。
> 一个抄进文档就再也不会自己更新的具体数，早晚会变成一句有出处的假话。

```text
┌──────────────────────────────────────────────┐
│ 云州 · 临江府 · 柳溪村     第八年 · 三月初七 │   ← 状态栏：常驻，时/地一变就闪朱砂
├──────────────────────────────────────────────┤
│  这一年村里几个同龄的孩子开始去私塾了。      │
│  你听见母亲和父亲在灶间说话，说的是束脩。    │   ← 当前经历：整屏唯一会滚动的区域
│                 ─────                       │
│  你可以：                                    │
│  ○ 每天早去一个时辰   耗 一年   天不亮就出门 │   ← 操作区：可用 / 锁定 / 隐去 三态
│  ○ 跟大家一样上下学   耗 一年                │      时间代价写在落笔之前
├──────────────────────────────────────────────┤
│ 人物 行囊 知识 人际 日录 编年 世界       │   ← 面板栏：有新内容的那一格点朱砂
└──────────────────────────────────────────────┘
```

## 它曾经是一个修仙入门筛选器

上一版人生停在十六岁：那年所有人都会走到江边的渡口，把攒下的东西
拿到一个明白人面前过一眼，演完卷终，末尾盖一枚「凡」。

那个结构在替玩家回答一个他没问过的问题——**「你这一生能不能在十六岁以前
接触到修仙？」**——而只要那是唯一的出口，它前面的家庭、谋生、教育、疾病、
灾荒、人际、迁徙就全都成了一道入门检测的前置步骤。**「他没能修仙」
和「他这一生失败了」是两句完全不同的话，上一版把它们写成了同一句，
因为除此之外没有别的结局。**

现在十六岁只是人生阶段的一个变化点：**从「被生活推着走」进入
「开始自己决定怎么活」**。少年那一卷的开场是「家里人说话开始带上你了」——
带上，那还是别人在决定；成年那一卷里的成家、出远门、盘间铺子，
每一条都是他自己往下按的。

十六岁那年什么也没改变，也完全成立。渡口照演，演完接着活。

那一版的「凡」印跟着一起撤了。落幕那一卷只盖一枚「终」——
**它说的是这卷到这里没有了，不评价卷里写的是什么。**

## 已建成的世界基础层

内容可以慢慢加，这一层不能事后补。它们按依赖顺序建起来，
每一层都由 `scripts/` 下的走查守着：

```text
世界基础层
├─ 人物认知系统        玩家读到的是自述与他人之言，不是数值
├─ 第三方观察系统      真实属性 → 观察能力 → 措辞 → 玩家理解，每步都可能失真
├─ NPC 实体系统        持续存在的人，不是一次性剧情变量
├─ 关系图系统          关系是边，不是槽位
├─ 持续关系生命周期    关系会结束，但不会被删除
├─ 出生境况系统        出生 → 生存环境 → 抚养关系 → 人际网络 → 人生发展
├─ 世界时钟            世界先于玩家存在，且玩家不在场时照样在走
├─ 感知系统            世界状态 → 玩家可观察到的现实（可能读错）
├─ 打听系统            主动去问，得到的是那个人的局部世界
├─ 认知三轴            接触只能往上，解释可以往下，对错与两者正交
├─ 认知扰动            动摇 / 有了别的说法 / 明确纠正，三种各不相同
├─ 主动行动            没有人叫他，他自己决定今天干什么
├─ 日录　　            我活过什么。旧日子可以被后来的事重新点亮
├─ 念头　　            经历 → 倾向 → 反复 → 说得出口。大多数人说不出口
├─ 机会　　            世界照常发生，念头只改他怎么读它
├─ 需求→愿望→念头     三层各管一头，而愿望不必通向任何地方
├─ 找门路　            打听 → 跑一趟 → 门前。假的占大头，而他分不出来
├─ 主动寻找　          念头 → 寻访 → 线索 → 判断 → 再行动。找不到是正常结果
├─ 会面　　            两个人互相打量了一回，两边都会看错，两边都不知道
├─ 师承　　            他凭自己量到的数决定教不教你，而那道顶是他自己的事
├─ 掌握　　            脑子里懂到哪一层和身上走到哪一步是两条轴，而教法对不上会把人送岔
├─ 家庭生活来源        出身是你生在哪一家，日子是你实际过的——抚养人一换，日子就换
├─ 我自己的日子        解析链的顶端。人生半路上能换活法，而换过的每一段都留着
├─ 离开原来的生活      人走了，关系一条不断；变的只是谁还在你天天照面的地方
├─ 分开之后的那些年    不见面不等于疏远；重逢时她还那样叫你，因为她认了你这么多年
├─ 称谓语境　          他怎么称呼别人跟着教养走，别人怎么称呼他跟着身份走——削爵那天两头脱节
├─ 家人礼与君臣礼      同一个人，堂上叫王爷，便殿里叫父王，削爵之后叫父亲
└─ 户籍与家世          籍业产家世居所各管一头；削爵那天门第塌了，玉牒上那个名字还在
```

### 十八条硬规则

前十一条是设计立场，后七条是**能跑的验收**——因为它们一旦破了，
不会报错，只会让玩家读到自己死去的父亲下地干活。

| #   | 规则                                               |
| --- | -------------------------------------------------- |
| 1   | NPC 必须是持续存在的实体                           |
| 2   | 重要 NPC 不得匿名                                  |
| 3   | 人物关系用图结构，不用固定槽位                     |
| 4   | 关系结束不代表关系历史消失                         |
| 5   | 世界事实与玩家认知严格分离                         |
| 6   | 第三方评价不得修改真实属性                         |
| 7   | 第三方评价不得作为 `Condition`                     |
| 8   | 第三方评价只能通过玩家选择影响人生                 |
| 9   | 出生环境可以极端不同                               |
| 10  | 出生环境不直接决定角色最终上限                     |
| 11  | 世界事件改变条件，不直接替玩家决定结果             |
| 12  | **内容必须适配不同家庭结构，不能默认玩家拥有父母** |
| 13  | **正文不得无条件假定出身**                         |
| 14  | **当前的日子只能有一段，过去的日子一段也不能少**   |
| 15  | **离开一种生活不结束任何关系，只改变谁在身边**     |
| 16  | **不见面不等于关系变差——关系只由发生过的事改变**   |
| 17  | **他怎么称呼别人跟着教养，别人怎么称呼他跟着身份** |
| 18  | **「世子」是身份不是称呼，隔一道门就换一个叫法**   |

第 12 条的来历值得记下来：关系图做完的当天，走查发现
**227 个「生下来就没爹」的人生里，227 个的正文仍在写「父亲每天傍晚去地里站一会儿」**。

那不是一个内容 bug，是**藏在剧本里的系统假设**——写剧本的人默认了玩家有爹娘。
这种假设不会自己消失，只要还有人往里加正文，它就会重新长出来。
所以它必须是一条跑得起来的验收，而不是文档里的一句话：

```bash
bun scripts/verify.ts
```

> 任何重要事件，在没有对应关系节点时，都不能产生关系穿帮。

第 13 条是同一个手法收的第二笔账，隔了很久才发现——因为它绕过了上面每一道门禁。
`{ origin: 'court' }` 的人生里，正文照旧在写
**「父亲在檐下修一把锄头，你跟着下了地」**：结构正确、条件正确、
NPC 存在、关系正确、世界状态正确，可正文把出身那一格当成了默认真相。

第 12 条默认的是「玩家有爹娘」，第 13 条默认的是「玩家家里有地」。
**同一种病：写剧本的人把自己脑子里那个家，当成了所有人的世界。**

```bash
bun scripts/upbringing.ts
```

> 出现生活细节时，必须有对应的人生环境来源。

第 14 条是第 13 条的时间那一维。第 13 条只说「日子由出身和抚养人决定」，
那句话对绝大多数人生是对的，**削爵那一卷正好是那个例外**：
皇子在宫里长到十五岁，一道旨意下来迁出京城，此后他过的日子跟宫里再没有关系。
把它写成 `character.living = 'market'` 是最省事的做法，也是最坏的做法——
三年前那个 `fallen` 会从世界上消失，而门第塌了那三年是真的发生过。

所以它跟第 4 条是同一个手法：**旧的那一段不删，只封口。**

```bash
bun scripts/living.ts
```

> 当前的日子只能有一段，过去的日子一段也不能少。

第 15 条是第 4 条的空间那一维。第 4 条说「关系结束不代表关系历史消失」，
而削爵那一卷问出了一个更难的问题：**人还在，关系也还在，只是他不在你的日子里了。**

```text
十七岁，你离开家，在镇上做伙计。

姐姐 —— 仍然是姐姐
父亲 —— 仍然是父亲
先生 —— 仍然存在

只是：你不再每天见他们。
```

所以这两件事必须分开，混起来会写出两种都很难看的实现：

|                        | 问谁                        | 混掉之后                              |
| ---------------------- | --------------------------- | ------------------------------------- |
| 关系**是否存在**       | `people.relations` 上那条边 | 搬走就删边 → 他成了一个没有过去的人   |
| 关系**是否还在日常里** | `engine/nearby.ts`          | 边在就当他在场 → 千里之外的人天天出现 |

正确的形状只有一个，而且它一格新状态也不要：

```text
世界里的人一直存在  +  玩家当前生活地点改变  →  能遇见的人改变
```

`isNearby(id)` 是**算出来的**：他此刻在哪（`Person.place`）== 你此刻的家在哪
（`household.home`）。存一格 `nearby: boolean` 会立刻多出第三份真相——
搬家改一处、他离乡改一处、他回来又改一处，三处里漏一处就永远对不上。

落到剧本上只加了三个子字段，一个新的顶层概念也没有：

- `home.takes` —— 谁跟着你搬。**不写是有意义的默认：没被列到的人留在原地。**
  削爵那一卷只写 `['mother']`，即位的兄长没被列到不是遗漏——他还活着、
  那条边一条没断，只是从此不在你天天照面的地方。
- `meet.who` —— 把新遇见的人记进人口册，落在你此刻的家。它是显式的，
  不是「查不到就造一个」：后者在 id 打错一个字母时会凭空生出一个人来。
- `bond.near` —— 剧本问得出「他还在不在我身边」。「找{elder}说话」那个去处
  从此问 `near` 而不是 `alive`：玩家点的那个人，得是说得上话的那一个。

明确**不做**的是那条捷径：`living = market` → 自动生成掌柜 → 自动删掉姐姐。
新的人由「你走到了那儿」带来，不由「你换了一种日子」带来。

```bash
bun scripts/apart.ts
```

> 离开一种生活不结束任何关系，只改变谁在身边。

这一道的判据设计本身也是一次教训。**第三条不能拿父亲去量**——
`royal:fall#edict` 里父亲死了，死人当然不会天天出现，
拿他量到的绿是死亡免费喂的，而「搬家改变了接触范围」一次也没被验到。
所以挑战对象换成**留在宫里、活着、没跟着搬的那个兄长**，
旁边站两个对照：跟着走的母妃仍然在身边，举家迁走的那一世全家都还在身边。
第四条同理——对照不能只有「什么也没发生」的那一世，还必须有
**同样搬了家、同样换了日子、只是没走出门**的那一世，
否则「搬家就自动派个新人」这种实现分辨不出来。

这一步做完，「人离开家以后还是这个人的儿子、兄弟，但已经过着另一种日子」才真正成立。
它也是为后面那件事打的地基：**玩家修仙离开凡俗以后，凡人时代的人不会从世界上消失。
他们仍然活着，只是不再天天出现在他身边。**

### 不见面 ≠ 关系变差

上一节把「关系存在」和「关系在日常里」切开了。切开之后，
剩下那半边里还混着两件事——而混掉的写法非常顺手：

```text
不在身边　　← 地点问题，isNearby 当场算得出来
关系变差　　← 只能由发生过的事引起，跟地点没有关系
```

```ts
// 顺手，且完全错
if (!nearby) affinity--
```

亲兄弟离家十年，感情必然按算法腐烂。那不是人生，是一个每年扣分的计时器。
**世界没有资格替人做这种判断。** 反过来也一样：天天见面的两个人关系可以越来越差，
而那只能来自具体发生过的事。所以这一轮加的机制是零——**加的是一道拦着人去写那行代码的门禁。**

同样明确不做的是「再塞一格好感度」。`Acquaintance.affinity` 早就有了，
再来一个 `closeness: 72` 只会让人物册重新变成数据库。这一轮要守的是
那一格**不被距离自动改动**，不是再造一格。

那么重逢时那句「瘦了」凭什么跟客栈伙计的「客官住店」不一样？
凭**她认了你十几年**，不凭好感够不够高：

```ts
{ bond: { kind: '抚养', alive: true, years: { atLeast: 8 } } }
```

`years` 是从那条边的 `since` 减出来的，不是存着的一格。
存一格「相识年数」就得年年去加，而人在外做工的那三年没有任何代码会想起它——
漏一年，这个人就永远差一年。跟 `ageOf` 是同一条道理。

还有一格是 `home.joins`，它收的是 `Bond` 而不是一个人的 id：

```ts
{ type: 'home', place: '{province} · {prefecture} · 村里', joins: '抚养' }
```

老家的村名是出生那刻掷出来的，剧本里写不出它，可它一直记在没跟你走的那个人身上。
写死 `'mother'` 的话，由叔父拉扯大、由长姐拉扯大的孩子回的都是一处谁也不在的空地址——
**养大你的那个人在不同人生里不是同一个人**，跟 `{dam}` 那个占位符是同一条理由。
门禁实跑掷出来的第一个抚养人就是 `uncle`，不是 mother。

```bash
bun scripts/kept.ts
```

> 走了三年再回来，她还是那样叫你——不是因为好感够高，是因为她认了你这么多年。

#### 「什么都没变」是一句不需要尺子也能说的话

这一道最要紧的设计在第三条。「三年不见，好感一格没动」单独看永远为真——
**一把量不出任何变化的尺子，量什么都是「没变」。**

对照组不能另起一世，得长在同一步里。`reunion:apprentice#open:go` 那一步
同时发生两件事：他跟家里人分开三年，他在货栈认识了管事的。同一把尺子问下去，
一边一格没动，另一边动到了 6。**两种答案，第三条才算量到了东西。**

#### 门禁自己的起点造错了

第一次跑出来是红的，红在「那条边只牵了 0 年」。起因是我造起点时写了
`world.bornYear = world.time.year - 13`——把生日往前挪，`age` 确实变成 13 了。

可 `boundFor` 拿的是 `world.time.year - edge.since`，而 `since` 是出生那刻写下的。
生日挪了，世界还停在原地，那条边照样只有零年。

> **年龄是走出来的，不是改生日改出来的。**
> 造起点要推时间（`{ type: 'time', years: 13 }`），跟正文里那些效果走同一条路。
> 从状态的侧面塞一个看起来对的数进去，塞出来的世界是自相矛盾的。

这跟 `nearby` 不存成一格是同一件事的两个面：**算出来的东西不许从旁边改。**

#### 移交不是豁免

这一章的几处 `home` 效果，`apart.ts` 和 `kept.ts` 都够得着。同一处路让两支各走一遍是浪费，
可**在一张覆盖率表上，「没人量过」和「另有人量过」长得一模一样**——
而它们完全是两回事。所以覆盖率报三态，不报两态：

```text
走过 · royal:fall#edict                        搬家（mother）
移交 kept.ts · reunion:emptied#open            搬家（没人跟着）
没走 · ...                                     ← 只有这一行才是债
```

移交表有牙，它核两件事：门牌号在库里真的还在（卷改了名、节点删了，当场红），
接手那一支的源码里真的提到这一卷（它哪天不走了，这里也红）。

写这张表的当天它就咬出了一处真缺口：`kept.ts` 明明在移交表上认领了
`reunion:emptied`，可它从头到尾只用 `requires` 验过那一卷该不该被走进去，
**一次也没真走进去过**。一袋死字符串是查不出这个的。

#### 一句不问也是有代价的

「人不在了」那一卷头一版整卷没有一个选择：推开院门，读十来句，完。
`verify.ts` 当场拦下了它，而理由不在这一章——

不落笔就不花时间，年表于是可以一卷接一卷地连演下去而人不长岁数，
最后落进日常那一章的成年卷，那一卷至今是占位内容。所以「这一卷可能一句不问」
和「窗口开到几岁」是同一件事：**窗口开到几岁本来就不是这一章一个人的事。**

修法不是把刚实测算准的窗口再收窄一岁去迁就它，是补上这一卷本来就该有的两个去处：
留下来把事办完，还是办完就回镇上。隔壁那一卷有两个去处，这一卷一个也没有的话，
**两卷的对照就只剩正文了——区别不该只在读到什么，也该在接下来他能做什么。**
两条都不加任何「悲痛」之类的格子，跟隔壁不给「回家住两个月」加好感是同一条规矩：
**这局没有资格替玩家判断谁更孝顺。**

补出来的正文当场又被另一支咬了一口。原先写的是「地里那几亩得有人交代」，
`upbringing.ts` 指出有地的只是七种人家里的一种——**走到这一卷的十一种出身谁都可能推开那扇门**，
而宫里出来的、铺子里长大的、寺里捡来的，一亩地也没有。留下来要办的事各家不同，
能一句说尽的只有「该还的、该收的，总得有人认」。

#### 换日子有两种来源，之前只量过一种

全库四处效果在换日子。之前走到的三处都是同一种事：削爵、削藩——
**家道变了，人被动掉进另一种日子里**，而且掉的时候全家一起掉。

第四处是他自己走出去做工。家还是那个家，家里的营生一格没动，
只是他从此不靠它吃饭了。补上这一条不只是把覆盖率填满：

```text
他过 market，家里的营生仍解析成 farm
而没走出去的那个农户孩子，家里也是 farm
```

**日子不是家里那格的别名**——这一句削爵那几条其实也验得到，它们家里那格解析成 `palace`，
跟他自己那格分得清清楚楚。可它们验不到下一层：削爵之后一家人已经搬出京城了，
家里还过着宫里的日子，这话本身就站不住。**它们能证明两格分得开，证不出家里那格是对的。**

分得出这一层的只有对照组。同一户农家，一个孩子走出去，一个没走，
两下一对——**家里那格是真的一格没动，不是残留，也不是巧合。**

### 称谓语境

「皇子就该满嘴父皇母妃」是个误区。古代称谓高度依赖**朝代、场合、身份关系**——
宋代皇室内部的日常称呼相当家常：皇子称父可以是「爹爹」，称母「娘娘」，
兄弟之间按排行叫「大哥」「九哥」；清代「阿哥」本是满语里的兄长称呼，
清初用于贵族子弟，后来才成了皇子专称，而官方文书里另有「皇某子」的制度化写法。
**满口父皇母后的是戏台上的皇子，不是宫墙里长大的孩子。**

所以这一层要的不是「给皇子发一套特殊词汇」，是那句更朴素的话：
**一个人管家里人叫什么，取决于他是在哪儿学会说话的。**
爵位和场合再盖在这句话上头——他爹身上挂着亲王，那声「父亲」才成「父王」；
跪下行礼的时候，那声「父王」又成「王爷」。三层叠出他开口的那个词。

在它落地之前，全库十一种出身的孩子管爹一律叫「爹」。`calls` 是
`content/circumstances.ts` 那张境况表里写死的一个字符串，而境况跟户籍是**正交**的：
境况只管关系网长什么样（有没有爹娘、谁把你养大），管不着这家是种地的还是坐龙椅的。
于是童年那一卷里读到的是这么一句——**这是实测跑出来的，不是设想**：

```text
后来母妃带你去给爹问安。
```

「母妃」是当时硬写在正文里的宫廷词（它后来搬进了爵位表，见下），「爹」是 `{elder}`
插值出来的寻常人家的词，并排站在同一句话里。**身份是皇子，台词却像普通农户。**

#### 称谓有两个方向，而这两个方向的来源不一样

```text
他怎么称呼别人   跟着教养走   读 household.origin（出身）  改不掉
别人怎么称呼他   跟着身份走   读 character.identity        一道旨意就改
```

这两件事在削爵那一卷里同时被检验，而且**朝相反的方向脱节**。门禁第三节实跑的三行：

```text
royal:fall#saw → royal:fall#outside
  别人怎么称呼他   殿下 → 公子   （皇子 → 庶人）
  他怎么称呼别人   娘娘 → 娘娘
  他过的什么日子   palace → market
```

跟 `identity`（社会身份）和 `living`（实际生活状态）那一次同构：一格说变就变，
另一格纹丝不动，分开之后才写得出那种别扭。落到正文里就是街上那一句——

```text
有一回你在巷口叫了一声娘娘，卖菜的回头看了你一眼。
```

上一句是「你学会了很多从前不用学的事」，说的是他学得会的那些。
这一句说的是学不会的：**口音是最后一件跟着人走的东西。**

「他怎么称呼别人」读出身，而不读他此刻过的日子，是整层里最要紧的一个选择——
「话改不掉」这条性质全押在它上面。三个候选，两个是错的：

- `character.living` 是他**此刻**的日子。削爵之后它变成 `market`，
  于是他一搬进城南那个小院，开口就从「娘娘」变回「娘」——
  **一个人的口音不会在搬家当天改掉。** 四十天的路上没有人重新教他说话。
- `character.livings[0]` 更不行。`liveAs` 只在**换**日子那一刻记一笔，
  出生那一段根本不在数组里；于是第一条恰恰是他**离开**那地方之后的那一段。
  拿它当「他在哪长大」，答案永远是「他后来搬去的地方」。
- `household.origin` 是他这一世从哪一行掷出来的，掷定就不再动。**那正是他长大的那个家。**
  它读的是出身那一格，不是籍那一格——籍削爵之后同样没动，可它只有四种值，
  而**民户底下压着七行人家**：种地的、打猎的、三家开铺子的、走镖的、当差的。
  官宦家的孩子和农家的孩子在黄册上是同一种户，学的话不是同一套。
  籍那一格给不了教养要的分辨率，这跟它改不改得动无关。

前两个候选都被写成坏实现喂给了同一把尺子（见下）。

#### 爵位盖在教养上头，而削爵不需要「清除」这个动作

教养那一层只回答「他在哪儿学会说话的」，答不了「他爹是谁」。王府和官宦共用读书人家
那一套话，两家的孩子管爹都叫「父亲」——可其中一个的父亲是亲王。

所以上面再盖一层，查的是**对方身上挂着什么爵**：

```text
教养 REGISTERS    王府 → 读书人家那套      生父 → 父亲
爵位 RANK_CALLS   亲王 · 生父 · 家常  →  父王     ← 盖在上头，查不到就落回
                  亲王 · 生父 · 礼上  →  王爷
                  王妃 · 生母 · 家常  →  母妃
```

「查不到就落回」这一句正是削爵那一卷**不需要写任何清除逻辑**的原因。旨意下来之后，
那一节只做一件事：

```ts
{ type: 'family', id: 'father', rank: '宗室' }
```

「宗室」在爵位表里查不到，于是那声「父王」自己失去依据，落回教养层的「父亲」。
没有一处代码去删那个词，也没有一句正文说「他不再是亲王了」。

`Person.rank` 因此是自由字符串，不是枚举。枚举会把「宗室」这种**查不到才对**的值
也逼成合法值，于是「查不到」和「写错了」再也分不开——而这一层全部的力气
都花在「查不到」这件事上。

#### 场合：同一个人，隔一道门两个称呼

《礼部志稿》卷十六记着一条规矩：亲王入朝，**在朝廷则行君臣礼，至便殿则叙家人礼**。
同一天、同一对父子，隔一道门换一套礼。这不是文学修辞，是写在礼部文书里的制度——
**身份上的君臣和家庭里的父子，本来就可以并存。**

于是场合成了第四格，而它只有两档：

```ts
type Manner = '家常' | '礼上'
```

节点上标 `manner: '礼上'`，那一节的正文、选项和回响一起走礼上那一档；不标就是家常。
默认挑家常不挑礼上，是因为**漏写不会报错**——漏写只会让八岁孩子在灶间管他爹叫王爷。

削爵那一卷为此拆成三节，三节里 `{elder}` 指的都是同一个人。门禁第五节实跑出来的是：

```text
royal:demote#open   礼上 · 亲王  →  王爷    （家常 父王／礼上 王爷）
royal:demote#home   家常 · 亲王  →  父王    （家常 父王／礼上 王爷）
royal:demote#after  家常 · 宗室  →  父亲    （家常 父亲／礼上 父亲）
```

前两节隔的是**礼**：旨意念完人还跪在堂上，当天搬进城西旧宅，屋里就是父子。
后两节隔的才是那道旨意——第三节里两档已经落成同一个词，因为爵位没了，
礼上那一档也没有东西可查。

三节的正文一个字也没提「称呼变了」。玩家是从那三个词上读出来的，
这是这一层唯一说得出口的验收标准。

#### 史料能证明的是规则，不是那个词

「父王、母妃、皇兄、皇弟」不能全部当成同一级别的明代固定制度称呼——有些是后世小说
高度固化的文学表达，有些才是真实礼制。所以表里每一格都挂着出处，而出处分两层：

```ts
interface Attestation {
  level: '史料' | '合理化'
  from: string
}
```

分界线是一句话：**史料能证明的是规则，不是那个词。**卷十六证明的是「两套礼并存」
这条规则，它没说亲王的儿子在便殿里开口叫的就是「父王」两个字。所以「父王」「母妃」
「王爷」一律标合理化——那是为了游戏语言好读而定的词；而「世子」「郡主」
（卷十五：亲王嫡长子十岁立为王世子，其余诸子封郡王，世子之妻称世子妃）、「殿下」，
以及「爹爹」「娘娘」（宋代皇子日常），标史料。

出处全库 9 条，史料 5 条、合理化 4 条，门禁自己数出来报。**光有一个 `level` 字段没有用**——
一句「大概是这样」也能填进去，所以还校验每条出处至少二十字、史料那几条里至少一条引到书名。

#### 皇帝故意不在爵位表里

宫里那位有 `rank: '皇帝'`，他的妃有 `rank: '妃'`，而爵位表里这两个都查不到。
于是皇子开口落回教养那一层，还是「爹爹」「娘娘」——这保住了街上那一句
「那两个字你从会说话起就这么叫」。

但**照样把爵位写上去**，是为了给门禁一条反向判据：不写的话，「查不到就落回教养」
这条规则在宫里那一支根本没被走到过，一个「见 rank 就换词」的坏实现能安然通过。
写上去，它当场破。

#### 这一版明确不做的四件事

**不做时代礼制那一维。** 这个世界根本没有朝代设定——全库「本朝」出现过两次，
两次都在注释里（`types/game.ts` 和 `youth.ts` 里那句「本朝女子不应举」），
**正文一个字也没提过朝代**：没有国号、没有年号、没有一条礼制条文。上面那些出处
注的是**这个词从哪儿来**，不是这个世界的年号——引《礼部志稿》不等于把这个世界
设成了明朝。凭空造一张朝代对照表，仍旧是先造阶梯再找楼。

**场合只做两档，不做第三档。** 一份更细的分法会是「王府内部 / 府外非正式 / 朝廷正式」
三档，而中间那档在称谓上跟第一档同档：「长兄，你今日怎生得空来了」跟在自家院里说的
是同一个词。**真正的分界不是地点，是有没有在行礼**——卷十六那条规矩分的也正是
「在朝廷」和「至便殿」，不是「在宫里」和「在宫外」。多出一档而两档产出同一个词，
只会让写内容的人每次都要先想一遍「这算第几档」。

**分不出伯父和叔父。** `Bond` 一共十五种，祖父、祖母、伯父、叔父、舅父、舅母
全落在「亲戚」那一格里。分得出来的前提是世界模型记着「父亲的兄长还是弟弟」，
而人口册上没有这一格，也没有一卷内容要用它。等哪天写出「二叔从外地回来」那一卷，
再去给关系图加边——先加格子，加出来的是一张没人填的表。

**不做「逐渐学会」那段时间差。** 完整的样子是：身份事实 → 别人怎么称呼他 →
他自己当下的习惯 → 经过教养 → 逐渐学会。一个从民间进王府的人，知道自己是世子，
不代表他已经掌握了那套话；反过来，宫里长大的孩子被贬为庶人，那套话也不会跟着爵位一起除掉。
这一版没做中间那段时间差，因为**没有内容逼它**：这个世界的出身是出生那一刻掷定的，
没有一条人生会中途换语言环境。硬做出来，就是一个谁也没走进去过的状态机。
什么时候该做：写出第一卷「他被抱进另一种人家」的内容时。

同样明确不做的是「给每种出身铺满一整套称呼」。`kin` 里没写的关系一律回落到境况表那个
`calls`——**绝大多数关系在哪一套话里都是同一个字**，逐条铺满只会让「哪几个字真的不一样」
淹在一片相同的字里。全库现在只有两套：宫里那套（爹爹／娘娘／哥哥／姐姐），
读书人家那套（父亲／母亲／兄长／姐姐，官宦和王府共用）。第二套是这一层不姓「皇室」的证据：
**教养那一格的差别来自语言环境，不来自爵位。** 王府的孩子和官宦的孩子学的是同一套话，
那一格里两家都是「父亲」；王府那个孩子开口成了「父王」，是**上头那层爵位盖下来的**，
不是他学的话不一样。削了爵，盖下来的那层没了，他就跟官宦家的孩子说同一个词。

```bash
bun scripts/address.ts
```

> 别人怎么称呼他，一道旨意就改了；他怎么称呼别人，改不掉。
> 而同一个人隔一道门是两个称呼——朝廷上是君臣，便殿里是父子。

覆盖率这一支自己报，七条都从库里数出来，不在门禁里另抄一张表：
那两套话一共 8 格验到 8 格，全库 4 种带封号的身份走到 4 种，
全库 2 处正文用了 `{title}` 走到 2 处，全库 3 种人家有专门的一套话走到 3 种，
爵位表 3 格命中 3 格，全库 1 处标了礼上的节点走到 1 处，出处 9 条（史料 5、合理化 4）。

#### 这一支头一版量错了三样东西，三次都长得像这一层坏了

**第一次，门禁自己掷错了人。** 造起点时只问了「关系网上有没有生母这条边」，
于是掷到了「生母难产而亡」那种境况：**边在**（世界永远记着她是他生母），**人不在**。
`{dam}` 一路落到生父身上，第三节读出来的是「他管娘叫『爹』」——
量到的是别的东西，而它看上去像这一层坏了。要问的是 `isNearby` 不是「还活着」：
削爵那一卷的 `takes` 只带走名单上的人，留在京城的那些边一条没断，可他们不在这个院子里。

**第二次，判据比的是两个人。** 人际面板那条判据硬写了 `callOf('father')`，
id 确实恒是这个字，可爹在他出生前就没了的那些境况里，这个人根本没进相识册，
`callOf` 老实答「一个陌生人」，而正文里的 `{elder}` 顺着顺序落到了娘身上。
判据于是报「面板管爹叫『一个陌生人』，正文里却是『娘』」——**两句话说的是两个人，
这条判据当时什么也没量。** 改成从 `kinOf('生父')` 里挑一个此刻还在身边的，
挑不着就整条不比。

**第三次，一支每次都红四十条的门禁。** 扫静态正文找硬写称谓那一节，
头一版把两套话拉平了扫，当场喂出四十来条误报，全库每一卷都在里头。
原因是「父亲」「母亲」同时还是**通用的书面叙述词**——「满月那天，父亲抱着你走了二里地」
是叙述者在讲这件事，不是主角开口叫人。「爹爹」「娘娘」不一样，这两个字只可能是当面的称呼。
所以这一节只扫宫里那两个字。**一支每次都红四十条的门禁，等于没有门禁。**

还有一处不是误报，是抄了第二份表：封号那条判据头一版手写了「官宦除外」，
那等于把 `birth.ts` 的 `TITLES` 表在门禁里抄了一遍——哪天给某种人家添了封号，
这一行不会红，它只会继续豁免。现在改成从库里读「出生那一卷里到底有没有封号那一节」，
并且补了对称的一条：没有那一节却带上了敬称，同样红。

#### 分工线不在词上，在「这个词有没有正经的产出路径」上

`upbringing.ts` 那张穿帮词典和这一支是分工，不是重复。头一版把线画在词上——
词典管硬写的字，这一支管插值出来的字——而爵位那一层落地之后，这条线自己动了：

- **有产出路径的**，归这一支。「父王」「母妃」现在是爵位表的产出：正文里写的是
  `{elder}`，他爹身上挂着亲王，落笔才成那两个字。这种词**一个字也不许硬写，
  不论在哪一卷**——手写的那份绕过了爵位表，削爵之后不会跟着变。所以这一支扫全库，
  而那张待扫清单是从 `RANK_CALLS` 自动生成的，不手抄。
- **没有产出路径的**，留在词典里，按读者集合量。「父皇」正是这一种：宫里那位在爵位表里
  查不到，皇子开口是「爹爹」，**这个系统里没有任何一处会产出「父皇」**，
  它只可能是有人手打上去的。

「母妃」因此从词典里搬走了，而它原先那条理由本身也是错的：那条规则写着「宫墙外没有这个词」，
可「母妃」是亲王正妃之子对生母的称呼，**王府就在宫墙外，那正是它该出现的地方**。
留着它还有一个具体的坏处——王府和皇室在日子那一层都映射到 `palace`，
于是有人在王府那一卷里手写「母妃」，那条规则不会红，而它本该红。

词典里留下的「父皇」带着一条豁免，而它是**实测逼出来的，不是预先想到的**：门禁自己打印的读者集合是 `edict=fallen`——
那一节的 `onEnter` 里 `{ type: 'living', living: 'fallen' }` 在 blocks 之前就落了，
于是「三天后有旨意下来」这一整节都算宫墙外的话，而这一节的正文正在转述那道旨意。
「大行」是皇帝驾崩的专用礼制词，旨意里用的当然是「父皇」。所以豁免写的是
`unless: ['父皇大行']`——**豁免的是这四个字连在一起的那种句子，不是「父皇」两个字**。
哪天有人写下「你去给父皇请安」放在削爵之后，照红。

### 户籍、家世、生计——一个词说不了五件事

上一节把「他开口叫的那个词」拆成了三层。可那一节刚落地就露出底下一个更严重的问题，
而且它不在称呼上：**称呼读的那一格本身就是混的。**

上一版每个人的处境写在一个字段里：`trade`，十一个值，从「农户」一直排到「皇室」。
排成一列看着整齐，可那一列里至少混着四层东西：

```text
trade: '客栈'   官府认定这家是民户 ＋ 这家靠经商过活 ＋ 家里那处铺面是客栈 ＋ 这是寻常人家
trade: '官宦'   官府认定这家是民户 ＋ 他爹在府衙当差 ＋ 没有铺面           ＋ 这是仕宦人家
```

四件事挤进一个词，于是有三种话写不出来：「凡是做买卖的人家」只能把
`商户 客栈 酒楼` 挨个列一遍（列漏一个没有任何机器会提醒）、「这家人改行去码头扛活」
一改就把籍一起改了、「削爵之后门第没了可玉牒上的名字还在」根本无从表达。

最不该混进去的是「官宦、王府、皇室」那三行。**「官宦」从来不是一种户籍**——
八品官的家在黄册上仍旧是民户，他本人的差事才是官。把它跟「农户」「猎户」并排放在
同一列里，等于说这个人「不是民户」，而那是错的。

#### 「籍」在明代有法律和赋役意义，不是职业分类

《大明律》户律「人户以籍为定」：军民驿、灶、医、卜、工、乐诸色人户并以籍为定，
而冒籍、脱籍、改籍都涉及法律责任。明初户帖登记的是户的种类、户主籍贯、居住地、
家庭成员及相互关系；洪武十四年以后又逐步以黄册承担更完整的户籍与赋役管理。

所以这一格的性质是「几乎改不掉」，跟「这家人今年在做什么」完全是两回事。
**但这一节不是为了「明朝味」换几个词。**换词解决不了污染——
下一轮内容一多，「他家开着铺子」还会被写进家世，「他爹是官」还会被写进营生，
而这两件事都不报错。所以先定的是那句问题，不是那张词表：

> **这五个维度分别负责改变什么？**

#### 八格，各答一个问题

```text
出身  household.origin      这一世从哪一行掷出来的  掷定就不动
籍    household.census      官府认定你家是什么户    几乎改不掉
业    household.livelihood  这一家靠什么过活        允许变
产    household.business    家里有没有一处铺面      允许变
家世  household.station     这是什么样的人家        旨意改得动
居所  household.home        家在哪儿                搬家就变
身份  character.identity    你本人被称作什么        一道旨意就改
日子  character.living      你早上起来面对什么      抚养人一换就换
```

**上面那一列「允许变」说的是这一格允许怎么变，不是眼下真有人这么写。**
到今天为止真有写手的只有 `station` 一格，写手只有旨意那两处（除封、削爵）——
`scripts/household.ts` 第四段把全库 895 条效果实跑一遍量出来的就是这句话。
「铺子盘出去 `business` 变 null」「改行去码头扛活 `livelihood` 变」这两件事眼下
一处内容也没有写，格子先空着等第一个使用者，不预先造一条效果去填它。

籍那一格同样克制：《大明律》列的是「军民驿灶医卜工乐」一长串，
出身表里只落了四种（民户、匠户、医户、宗室），因为十一行人家只用得着这四种。
军户、灶户、乐户不是忘了写，是**还没有一卷内容需要它们**。

#### 削爵那天，家世塌了而籍没动

这是五格不是一格的**全部现有证据**，也是这次拆分唯一一处真正的落地：

```text
royal:fall#edict      { type: 'household', standing: -60, station: '寻常' }
royal:demote#open     { type: 'household', standing: -48, station: '寻常' }
```

两处都**只写 station，不碰 census**。封号除了，门第跟着除；玉牒上那个名字不归旨意管。
于是从那天起他是「宗室籍的寻常人家」——上一版一个 `trade` 写不出这句话，
那天只能整格换掉，换完他就成了另一家的孩子。

门禁第三段把这两卷的 `onEnter` 顺着实跑一遍，量出来的是：

```text
削爵（王府）　动了 家世、居所、身份、日子
除封（宫里）　动了 家世、居所、身份、日子
（出身、籍、业、产 四格一动没动）
```

#### 拆开的时候揪出一个活 bug

`station: '寻常'` 那两笔不是补齐对称写上去的，是补上去之前那里本来就是错的。

削爵那一卷的窗口是 12–15 岁，渡口那一卷 `riverman` 是 16 岁往后——
**削爵必然先发生**。而 `riverman#open` 有一条 `{ station: '宗室' }` 的分支，
读到就把人当贵人写。上一版削爵那一卷从头到尾没有任何一笔动过家世那一格，
于是一个刚被削了爵、住在城西旧宅、身份已经是「寓公之子」的少年，
走到渡口会被重新认成贵人。

补上那两笔之后，库里六处「削爵那天 `station` 落到寻常」的注释
（`riverman.ts`、`schooling.ts`、`CharacterPanel.vue`、`engine/address.ts`、
`engine/book.ts`、`types/game.ts`）**同时从空话变成了事实**——
它们本来全指着一件没有发生的事。

#### `scripts/household.ts`：不查错，回答那句问题

这一支跟别的门禁不一样：它不查拼写、不查连通、不查遮蔽。
它把「八格分别负责改变什么」跑成数字，五段各答一问。

```bash
bun scripts/household.ts
```

**一、谁读得动哪一格。** 全库 281 条条件里数出来：

```text
出身　条件 24　代码 3 处      家世　条件  5　代码 3 处
籍　　条件  0　代码 0 处      居所　条件  —　代码 4 处
业　　条件  8　代码 5 处      身份　条件  —　代码 3 处
产　　条件 21　代码 4 处      日子　条件  6　代码 2 处
```

居所和身份在 `Condition` 上没有入口，这是有意的：它们由正文插值和称谓层读，
剧本要分岔的时候问的是日子，不是门牌。

**二、这真的是五件事吗。** A 相同的行里 B 也都相同，那就是 A 把 B 决定死了。
量出来：出身决定了其余四格（它是主键，本该如此），**业把籍决定死了**
（务农→民户、木工→匠户、行医→医户、食禄→宗室，十一行没有例外）。
籍、产、家世谁也没决定谁。三条独立性各对着一句原来写不出来的话，
塌了哪一条那一格就该并回去：八品官家在黄册上仍是民户、寻常人家里有民户也有匠户也有医户、
经商那三家柜台上摆的不是同一样东西。

四格合起来还剩 1 行分不开（藩府和宫里四格完全相同），
所以 `origin` 这个主键得留着——它现在写的理由就是这一行。

**三、削爵那两卷实跑。** 见上。

**四、谁改得动哪一格。** 全库 895 条效果，每一条各从三种人家落一遍
（宫里、农家、药铺，2685 次跑通 2685 次），落之前拍一张八格的照，落完再拍一张：

```text
出身　（一个也没有）      家世　household（如 royal:fall#edict）
籍　　（一个也没有）      居所　home      （如 royal:fall#edict）
业　　（一个也没有）      身份　identity  （如 birth:manor#titled-male）
产　　（一个也没有）      日子　living    （如 royal:fall#edict）
```

**五、压回一格会写不出什么。** 58 条条件问了这五格，其中 **34 条问的是性质而不是某一行**——
压回一个 `trade` 之后，这 34 条全得改写成列出身名，那句话就从「问的是铺面」
变成了「问的是这几家」：意思没了，只剩名单，添一行新的药铺人家名单不会自己长。
另有 2 条一次命中不止一行（`{ station: '宗室' }` → 藩府和宫里），改写之后还要多写 2 行分支。

#### 这一支自己量错过三次，三次都长得像结论

**第一次，一条永远绿的自检。** 头一版写的是「五格写满，逐格抹掉一格，命中面必须变宽」。
它每次都绿，而它什么也没量：五格写满只命中一行，其中 `origin` 一格自己就把那一行钉死了，
抹掉别的哪一格都还是那一行。**输入不构成挑战的判据，跟没有判据是一回事。**
改成一格一格单独问，另加一条反向的：不问出身的条件谁都成立，一行也不许筛掉。

**第二次，一条明写 `station: '寻常'` 的效果被量成了「没有写手」。**
第四段头一版只落一遍，而那一世的出身是随机掷的——掷到的那一世本来就是寻常人家，
落下去前后一模一样。判据当时报的是「家世一个写手也没有——那么库里五处注释全是空话」，
**而那句话看着完全合理**。改成三种相互最远的人家各落一遍取并集。

**第三次，身份和日子都报了 0 个代码读者。** 正则只认 `household.census` 这一种写法，
可真读者写的是 `useCharacterStore().identity`，还有 `storeToRefs` 拆出来直接在模板里用的。
这一列本来就粗（它说得了「没人读」，说不了「有人读」），可粗跟错不是一回事。

#### 明写的缺口：籍这一格今天一个条件读者也没有

全库没有任何一条 `requires` 写 `{ census: ... }`，而业那一列又把它决定死了。
按「先有使用者再抽象」的尺子量，它今天只剩一个使用者：**削爵那天它不跟着 `station` 走。**
要是连那件事也没有，这一格该删。

这个零钉在门禁里，两头守着：哪天有人写了第一条 `{ census: ... }`，那一支会红，
提醒去删 `types/game.ts` 里那段「这一格眼下没有读者」；而名单之外的格子掉到零，
同样红——那说明有人把读它的内容删光了。

### 八道结构门禁

纯文字游戏最容易坏的地方不是类型错误，是**某条剧情只有千分之一的人生会走到，
所以它坏了半年也没人发现**。`verify.ts` 现在拦八类：

| 门禁     | 拦什么                                        | 当前              |
| -------- | --------------------------------------------- | ----------------- |
| 关系穿帮 | 没爹的人生里正文写「父亲下地干活」            | 300 世无穿帮      |
| 断头路   | 跳转指向不存在的节点（id 是字符串，tsc 不管） | 72 卷 336 条      |
| 孤儿     | 忘了删的旧节点，和忘了接入口的整卷            | 294 个 · 72 卷    |
| 前置条件 | 剧本要一样东西，而世上根本没人给              | 64 种都有出处     |
| 可观测   | 图上连得好好的，人生里却没人抵达得了          | 300 世走到 84%    |
| 占位     | 故意走不到的那一卷，还走不到吗                | 四条前提都在      |
| 拓扑     | 目录上写的章，跟长出来的内容对不对得上        | 20 章 · 36 处痕迹 |
| 称呼     | 玩家读到的字里混进了内部 id                   | 300 世零个字母    |

第四道起因是一次真的回归：把 `omen:wounded` 改成五节点时，
六个旧结局节点被删了，挂在它们身上的 `thin-book` 和 `touched-by-wicked` 一起没了。
**正文照样在说「他从怀里摸出一册薄书，塞进你手里」，行囊里却是空的**，
而渡口上认得这册书的那个结局，就那么哑了。前三道都查不到它——
节点连得好好的，断的是前置条件。

#### 而第五道是另一层：来源和路径会分开坏

同一轮里撞见两件事，看着像同一类，其实分属两层：

```text
illness-at-home     火种引用了它，世上没有一处设过它      → 来源问题
omen:wounded#miss   节点连得好好的，三百世零个人走到      → 路径问题
```

于是这一句正式改成：

> **门禁检查所有内容元素是否有「来源」和「可观测路径」。**

**一个事件存在，不代表玩家有机会经历它。** 普通事件表查的是「事件有没有触发」，
这一道查的是「这个人的人生轨迹是否可能抵达那儿」。

它不能要求「每个节点都有人走到」——那条要求会逼着把长尾内容删掉。
所以它只把没人走到的名单**印出来**，给人读，不给人清零，
读法是去可达性那一层查它。头一批跑出来就分出了两种截然不同的东西：

| 名单成员                     | 查下来是什么                               |
| ---------------------------- | ------------------------------------------ |
| `seek:crossed` / `seek:door` | **稀**。每一环都在乘，三百世期望一个人上下 |
| `routine:adult`              | **走不到**，而且是别处四个数字凑出来的     |

前者的交代在 `scripts/seeking.ts` 第七节：两千世完整人生，走进去两回上下。
链条完好，只是「心里生出想弄明白」2.6% × 「听说过有修士」37% × 「年表抽中问人那一卷」2.8%
× 「真问着了东西」2.2% × 「两条消息撞在一处」0.2%——乘到最后三百世轮不到一个人。
（这几个数每批都在晃，读的是形状不是准数，原委见下面那一节。）
**一个期望值在一附近的格子印出零来不是内容坏了，是三百世不够。**

> 那一节还顺带查出一件本来看不见的事：「两条对上了」的人绝大多数是**十五岁那年**
> 才对上的，而用得上它的那一卷窗口是十三到十六。这条路十有八九只赶得上最后一年——
> **旗标设上的时候，那扇窗快关了。** 它现在还通，可再往前挪一岁就会当场断掉，
> 而断掉的样子跟今天一模一样：名单上多两卷，谁也说不清为什么。

后者是另一回事：它走不到不是自己的性质，是别处四个数字凑出来的结论。
`enterRoutine()` 只有两个入口——年表抽不出事，或者连演的卷数顶到上限——
四条前提各堵一半，详见下面第六道。不是漏接，是这一段人生还没写，
留着它替将来占位子，原委写在那一卷上头。

#### 而这一道差点变成一支会随机红灯的门禁

第五道原本还兼一件事：守住那份名单别越来越长，上限 32。
理由听着挺硬——**新加一卷却忘了接入口，名单该多出五到十个，必须顶穿它。**

后来把三百世那一批跑了十二遍：

```text
16　21　19　22　20　21　22　24　28　30　37　19
均值 23.3　标准差 5.6
```

**十二批里有一批 37。** 上限 32 大约十二分之一的概率会红一次，
而红的原因是抽样、不是内容——那正是这一整套走查最忌讳的事。

晃成这样是因为这份名单不按「个」跳，按「卷」跳：`seek:crossed`
十二批里有五批整卷没人走到，`royal:fall` 三批，`birth:皇室` 一批。
一卷稀，它就整卷进进出出。**噪声幅度 ±11，而要抓的信号只有五到十个节点。**

于是那件事整个挪走了。一卷只有三种进法——年表事件、四个阶段的日常、
收尾那一卷，外加别卷跳过来；`begin()` 也只是 `toNextChapter(0)`，
连出生那一卷都是年表抽出来的。**所以「这一卷有没有入边」是纯静态的，
一个随机数也不用掷**，现在归第三道。第五道剩下的上限改成 40
（均值加三个标准差），只防一件事：一次改动把大片内容切下线。

> **能静态判的，别拿模拟去判。** 模拟是用来量分布的，不是用来判存在的——
> 判存在，抽样迟早会替你判错。

#### 同一个毛病，隔壁一格又犯了一次——这回是数字自己漂走的

替第五道作证的那一节（`seeking.ts` 第七节）自己有一道判据：两千世里
走进「两条对上了」那一卷零回，就判红。依据写在它自己的注释里——
「实测千分之三点七，两千世里七回上下，掷出零的概率不到千分之一」。

那个数从写下那天起就没人再复核过。这一轮连跑五批：

```text
0　2　3　1　3　　→ 千分之一上下，两千世的期望只剩两回
```

期望两回，掷出零是七分之一的事。**也就是说这道判据每七八次跑就无故红一次，
而内容一个字也没坏。** 上一节明写着「红的原因是抽样、不是内容，
那正是这一整套走查最忌讳的事」——它就写在同一支脚本里，隔着三十行。

不是新内容把它挤稀的。摘掉最近新写的那一章再跑三批是 3、1、3，
带着它跑是 0、2，同一个量级。**这个数是这些年一点一点漂下去的，
而漂的过程中判据一直是绿的，所以没有任何一次跑会提醒你去看它。**

于是上一节那句话有了另一半：

> 能静态判的别拿模拟去判；**而拿模拟判的，判据的依据是一个实测数，
> 实测数会随内容漂。** 漂了不会有人吭声——判据平常还绿着。

修法不是把世数一口气抬上去：这一支要跟另外三十八支一起跑，
那八成七的正常跑法不该为了兜住一成三的坏运气一起变慢。改成零回时才追加四千世，
撞上一回就够了——**这一节要证的是路通着，不是路有多宽**。累计六千世仍是零回才判红，
期望两回的话那是四百分之一的事。

**判据一格没松：路真断了，追加多少世也撞不上，照红。松掉的只是抽样。**
这句话是量过的——把那一卷的名字改成一个库里没有的，五十三世全不中，照红。

#### 第六道：人生的形状

六段日常各占一段年龄，终点只有一个。这一道判**结构**，一个随机数也不掷：

```text
① 阶段跟年龄轴一一对得上    两档撞在一起，夹在中间那档就没人走得到；
                            反过来漏掉一档，活到那一年就没处落脚
② 一卷日常只归一档          同一卷挂两个阶段，那是一格换了两个名字
③ 每一档的日常都在库里      挂了个不存在的卷名，要活到那一档才炸
④ 落幕不在年表里            进得了年表就可能被抽中，人会莫名其妙地死
⑤ 没有别的卷跳得进落幕      有一条这样的边，就有了第二种死法
⑥ 落幕跳转不出卷，且一定问玩家一句
```

##### 这一道从前守着一个不该存在的结构

上一版这里守的是反过来的事：`routine:adult` 是一卷占位内容，谁也走不到，
而这一道守的正是「它还是走不到吗」。它当时把四个数字钉得死死的——

```text
收尾事件　window 16–99，没有 requires    到了年纪就一直在候选池里
收尾那一卷　跳转全在卷内                 演到它就一定演到底，一定 finish()
stageOf　　16 岁仍算「少年」，17 岁才成年
连演上限　 顶满要四卷不给玩家落笔，而那些卷的窗口都封顶在 16 岁
```

前两条堵住「年表抽不出事」，后两条堵住「连演顶到上限」——`enterRoutine()`
只有这两个入口。四条合起来只说了一句话：**人生在十六岁那年结束**。

判据当时写得很结实：四条全静态、四条都造过反例验它会红。
**一条判据长得越结实，越可能是在替一个不该存在的结构做保。**
今天第 ④ 条正是直接钉死旧机制的那一条——从前 `lifeFinale` 指着渡口，
而渡口有年表事件，「演到它人生就结束」就是从那里长出来的。

##### 这一道先验自己的尺子

六条全绿说明不了什么。所以判词写成了一个收世界、吐结论的纯函数，
先拿七个手工掰坏的世界喂它一遍，每个只掰一处，红的位置得正好落在那一处上：

```text
多一个年龄轴上根本不存在的阶段              该只红 ①
两个阶段挂同一卷日常                        该只红 ②
某一档的日常在库里不存在                    该只红 ③
年表里加一件指着落幕的事件（十六岁那条老路） 该只红 ④
别的卷开一条边跳进落幕                      该只红 ⑤
落幕的跳转跑出卷外 / 落幕一句也不问玩家      该只红 ⑥
```

底样用的是手搭的落幕，不是真落幕——真落幕改一个字，七个变体就有掰不准的。
尺子不准的时候，真世界那六个绿灯一个也不作数：这一道会先报尺子坏了，
再谈内容。

##### 顺带纠掉一句自己写错的话

旧版那四条里原先只写了一条，还写错了：「十六岁那年收尾事件必被抽中，
所以证得出永远是零」。查下来是——十六岁之后还有二十来件散事件，
权重合起来两百多，收尾权重 1000，**单轮被挤掉的概率将近两成**，
人照样能活到十七岁。

真正管用的不是「必被抽中」，是**它永远在候选池里**：池子不空，
`pickEvent` 就不会返回 null。抽中与否无所谓——**差一点就把一条侥幸
当成了证明**，而那句错话已经在代码注释和这份文档里躺了一轮。

##### 「有没有人真的走到」不归这一道

那是存在性，静态判不了：一卷「可以被走到」和「真有人走到」是两回事，
中间隔着权重、条件、和这个人前面几十年攒下的东西。**存在性只能跑出来**，
归 `scripts/lifelong.ts`（见下）。

#### 第七道：目录跟内容对不对得上

到第六道为止，这支脚本一直在问同一类问题——**这份内容自己是不是自洽的**。
答案全从数据里推：跳转指向存不存在、条件有没有来源、卷有没有入边。

推得越多，门禁就越要懂剧情。已经要懂剧情结构、懂人生阶段、懂事件来源了，
再往下加几道，`verify.ts` 会长成半个编辑器。所以这一层换了个方向：
**把结构显式写下来，门禁不再猜。**

`src/content/life/chapters.ts` 是这一册的目录，二十一章各一行：

```ts
{
  id: 'day',
  scenes: dayScenes,
  events: dayEvents,
  called: ['年表'],       // 怎么被叫出来：年表 / 日常 / 收尾
  to: ['encounters'],     // 这一章会把人送进哪些别的章
  age: [7, 16],           // 事件窗口该落在哪几岁之间
  purpose: [              // 这一章为什么存在
    '玩家第一次不是被事件叫出来才行动，而是自己安排一天',
    '一天最常见的结果是什么也没发生——正因如此，出事的那天才要紧',
  ],
  marks: ['daily', 'diary'],  // 少了这几种效果，这一章就不成立
}
```

**它不是额外的一层抄写，是唯一真相源。** `index.ts` 的 `lifeScenes` 和
`lifeEvents` 都从这张表摊平出来——从前那是两串各写各的 spread，
卷十七行、事件十六行、顺序还不一样，新写一章要在两处各加一行，
**漏掉一处就是「场景在库里但年表叫不出来」**。现在漏不了：章只声明一次。

于是这一道要对的就是五句话：

```text
章名不重，卷也不重      Object.fromEntries 撞名不报错，后来的直接盖掉前面的
跨章的边都写在目录里    偷偷多接一条，或者删了一条却忘了删声明
事件窗口不越出章界      把一件事的年龄往外挪，一整章就漂到人生另一段上去
每章都叫得出来          写好了没接入口，或者接了却没在目录上认领
说了要留下的还留着      这一章还在干它当初存在的那件事吗
```

前三条各守着一种**静默失败**：出事的时候没有任何东西会报错，
只是玩家读到的东西悄悄变了。第四条守相反的方向——内容写了却没人读到。
第五条守的是最慢的那一种坏法，下面单说。

##### 断言力全在「手写」两个字上

`to` 和 `called` 完全可以从数据里算出来。**算出来的版本永远不会红**，
因为它跟着实现走：多接一条边，它自己就多一条，什么也证明不了。

写下来就不一样。要绕过它得手动去改那份声明，**而改的那一刻，
人就看见自己在做什么了**。这也是第三道能变简单的原因：
「这一卷有没有入边」从前要把年表、日常、收尾、跨卷跳转全扫一遍才答得上来，
现在目录里就写着。

`age` 是这几格里最松的一格，只管边界不管逐件：往里收不红，越出去才红。
这道松是有意的——调单件事件的窗口是常规内容工作，不该每次都惊动门禁；
但把一件八岁的事挪到十七岁，那不是调窗口，那是改了这一章在人生里的位置。

前四条各造过反例：让两章认领同一批卷，第一条红（并连带把重复的边算成跨章，
第二条一起红）；删掉 `day` 的 `to` 声明，第二条红，明细直接点到
`day:ordinary#morning-out` 那三处跳转；把一件病倒事件的窗口从 8–16 改成
8–17，第三条红；把 `youth` 的 `events` 清空，第四条红成
「目录写着『年表』，实际是『没人叫』」。

> 第三个反例顺带说明了这两道不重叠：**窗口延到十七岁，第六道没响。**
> 那一卷会问玩家，进不了「连演不落笔」的名单，四条前提一条没破。
> 同一处改动，一道看得见一道看不见——这正是两道都得在的理由。

##### 一章为什么存在，这件事也得能红

前四条守的都是结构：接错了、漏接了、挪了位置。第五条守的是另一回事——
结构一直对，而这一章已经不干原来那件事了。

这种坏法最慢：一章被改十次，每次都合理，十次之后它成了别的东西，
**而没有任何一次改动看起来像个错误**。

`purpose` 写的不是剧情概要，是结构目的——它在这套人生模型里顶什么用，
少了它哪一层会塌。写它是为了几年以后：那时内容有几百件，每一件单看都合理，
「这一卷当初是干什么的」只剩这几行能回答。**没人答得上来的内容不会被删，
只会被绕开**，然后新写的东西在旁边把同样的事再做一遍。

可一句中文没法验。所以配了 `marks`——这一章必须真的落下的那几种效果：
打听那一章要产 `ask`，机缘那一章要产 `encounter`、`book`、`hearsay`，
病那一章要产 `reflect`。不产了，它就已经不是原来那一章，只是没人吭声。
**能验的那一半替不能验的那一半站着岗**：`purpose` 那句话开始变味的时候，
多半 `marks` 会先掉一格。

`marks` 只写招牌产出，不写全部产出。`time` / `attribute` / `flag` 几乎人人都有，
写进来等于没写。二十一章加起来一共三十七处，平均一章不到两处——
它是一句话，不是一张清单。

反例两个：把「病」那一章里四处 `{ type: 'reflect' }` 删掉（就是有人重写这一章、
顺手把念头涨退那段拿掉的样子），红成「illness　说要留下 reflect，这一章里一处也没落」；
把 `inquiry` 的 `purpose` 清空，红成「说不出自己为什么存在的章：inquiry」。

> 这一格本来可以只是文档。做成能红的，是因为**没有检查地躺着的声明，
> 正是这个项目一直在对抗的那种东西**——它不会出错，只会跟内容慢慢分岔，
> 而分岔的那一刻没有人在场。同一个道理，`marks` 也完全可以从数据里算出来，
> 而算出来的那一版永远不会红：它的分量跟 `to`、`called` 一样，全在「手写」两个字上。

#### 第八道守的是最后一层：这些字要给人读

前七道守的都是结构——连得上、有出处、走得到、对得上目录。全绿之后仍然可能出这种事：

```text
人际
  弟弟　　　　　沈长根　　比你小几岁
  sibling
```

**这一行是真跑出来的。** 家里添丁那一卷写着 `{ type: 'family', id: 'sibling', … }`，
而那条效果当时的实现是 `people.meet(effect.id, effect.id, 0, effect.note)`——
**把内部 id 当成了玩家嘴里的称呼**。爹娘没露馅，是因为出生那一刻就 `meet` 过一回，
而 `meet()` 对已经认识的人不改称呼；头一个在半路上出现的人就露了。

前七道一道也拦不住它：`sibling` 这个 id 有出处、连得上、三百世里两百多世走得到、
在目录上归幼年那一章。**结构全对，只是玩家读到的那一行是英文。**

顺着查下去，坏的其实是三样，而且坏得很安静：

```text
人际面板上显示 sibling      callOf 取不到称呼，回退成内部 id
「比你小几岁」永不显示      noteFor 先查 personOf，查不到就返回空串
家里多一张嘴却数不出来      没有关系边，household.members 读不到他
```

根子是同一处：**那条效果只往认知层写了一句话，人口册上根本没有这个人。**
说了「家人也是人」，就得真把他放进册子里。现在 `family` 多一格 `born`，
置真时走 `bearKin()`：随这一家的姓，按行当取名，生年就是当年，
从此他自己长大、也自己有可能没了——跟这世上别的人一样。

所以第八道扫的是玩家真读得到的那几处字：称呼、关系、营生、附注，
一个英文字母也不许有。它的分量全在「实跑」上——静态扫内容文本查不到这一条，
`sibling` 这四个字从来没写在任何一段正文里，它是运行时拼出来的。

判据必须能区分对错，所以这一道自带两样东西：六段手工构造的字（`'sibling'`、
`'friend'`、`'沈家的Xiao弟'` 该红，`'弟弟'`、`'云州 · 临江府 · 柳溪村'`、
`'十七岁。药铺'` 该绿），以及一个计数——**这三百世里有两百多世家里真的添过丁**。
少了后面这个数，哪天添丁那一卷断了线，这一道会安安静静地绿着。

### `scripts/lifelong.ts`：一生跑得完，而且每一段都真的有人在过

上面第六道判的是结构：六个格子是不是真的六个，终点是不是真的一个。
可结构对了，人还是可能一辈子也不走进某一卷。**存在性只能跑出来。**

「十六岁结束」那条规则拿掉之后，有一批新问题全都是只有真跑一遍才看得见的：

```text
跑不跑得完      年表抽事、日常耗时、再抽事——这个圈会不会不停
后半生有没有内容 十七岁之后年表几乎是空的，三卷日常独自撑着
修行还碰不碰得上 窗口收到 16–28、加了命数门槛之后，会不会没人碰得上
```

六千世实跑（约 90 秒，每世约 122 下）：

```text
掷定的天年   最短 44　四分之一 56　中位 64　四分之三 72　最长 82
咽气的岁数   最短 46　四分之一 56　中位 63　四分之三 69　最长 82

走到落幕 600 世　按满回合上限 0 世　走到修行那一卷 76 世（12.7%）

幼年　600 世停过　1723 回　routine:child
启蒙　 10 世停过　  22 回　routine:youth
少年　  9 世停过　   9 回　routine:teen
成年　600 世停过　4193 回　routine:adult
壮年　600 世停过　5911 回　routine:prime
老年　517 世停过　2433 回　routine:old
```

#### 三个数字一个也不写死

上面这些数全都会漂：内容一多，寿命分布跟着变；日常的选项一改，
命数涨得快慢就变，能走到渡口的人跟着变。所以判据一个具体数也不认，
只守住三样谁也不该跌破的：

```text
每一世都走得到终点      跑不完就是死循环，那是引擎坏了
每一档都有人停在那儿    有一档是 0，那一档的内容就没人读得到
修行不是 0% 也不是 100% 0% 是碰不上，100% 是又变回必经的检测
```

最后那一条两头都守，因为两头是同一种病的两个方向：0% 说明门槛高到
这条路等于不存在，写了也白写；100% 说明它又变回了「十六岁那道检测」，
只是挪了个岁数。**中间那个数是多少不判——会漂的数不写进判据。**

具体的数照样打印出来给人读。**给人读的数和用来判的数是两回事**，
前者越细越好，后者一细就会在某次无关的改动里假红。

#### 跑六千世而不是三百世，是量出来的

少年那一档特别稀：十三到十六岁那几年年表塞得很满（少年、那一日、离村、
寻访、师承、照面全挤在这几岁），候选池难得空一次。三百世量下来那一档
只停过 4 世，而「不是 0」这条判据在个位数上会自己抖——摊上一批背运的样本
就假红一次。翻倍之后那一格上了两位数，抖不出 0 来。

那个位数本身会漂（往后半生补内容、或者给十三到十六岁减两件事，它就变）。
**它是定这个数的出处，不是判据本身。** 内容大改之后该重新量一次，
而不是照抄 600。

#### 尺子自检

跑出来的数天然会让人放松警惕：满屏都是真实样本，看着就像在工作。
所以判据先拿手工捏的账本喂一遍——底样一切正常，三道都该绿；
五个变体各只捏坏一处（有世按满回合上限、有世没走到落幕、有一档没人停过、
没人走到修行那一卷、人人都走到修行那一卷），红的位置得落在对应那一道上。

### `scripts/refs.ts`：统一索引

`SceneNode` 有七个字段，每一个都可能引用世界状态——出边、前置条件、产生的效果。
从前 `verify.ts` 里六处遍历各自手写，扫 `exits` 的代码、扫 `conditions` 的代码、
扫 `effects` 的代码，三者之间没有任何共同点。**每加一种表达能力（比如给某格加一种新的去向），
就需要去找到所有「遍历出边」的地方，逐一补上。** 漏掉一处，那一格对门禁是透明的。

`scripts/refs.ts` 把这件事收拢成一张登记表：

```ts
const NODE_REFS = {
  id: {},
  blocks: {},
  onEnter: { effects: (node) => node.onEnter ?? [] },
  seen:    { conditions: (node) => … },
  choices: { exits: …, conditions: …, effects: … },
  branches:{ exits: …, conditions: … },
  next:    { exits: (node) => … },
} satisfies Record<keyof SceneNode, FieldRefs>
```

`satisfies Record<keyof SceneNode, FieldRefs>` 把穷尽性变成编译约束：
给 `SceneNode` 加一个字段不在这里登记，`vue-tsc --build --force` 立即红。
登记表既是声明也是实现——`exitsOf` / `conditionsOf` / `effectsOf` 三个提取器
直接从它摊平，`verify.ts` 里六处手写遍历全改成调提取器，从此不会再有「扫出边的遍历」
和「扫条件的遍历」各自记账的问题。

这个守卫只在 `scripts/` 被类型检查时才有效。`tsconfig.scripts.json` 把这四十一支脚本
纳入 tsc 覆盖范围，并加进 `tsconfig.json` 的 references，让 `vue-tsc --build --force`
一次性把 app、node、scripts 三个范围一起检查。

### 另一个维度：`Condition` / `Effect` 的登记表

`refs.ts` 守的是**结构**——一个节点有哪几个格子。它守不到另一件事：
**一个格子里能装几种东西**。`Condition` 和 `Effect` 各自还在长，
而它们的每一种新写法，都得有人认得。

这两者形状不同，锁也不同：

|             | 形状                       | 锁                                                  | 漏了会怎样                    |
| ----------- | -------------------------- | --------------------------------------------------- | ----------------------------- |
| `Effect`    | 可辨识联合（37 个 `type`） | `switch` 尾巴上 `const unreachable: never = effect` | 走到那一支时打日志、返回 null |
| `Condition` | 一袋可选字段（12 格）      | 登记表 + `satisfies`                                | **静默放行**                  |

`Condition` 那一栏是这次真正的理由。它没有 discriminant，
`assertNever` 在它身上使不上劲；而从前 `conditions.ts` 里是十二段独立的
`if (condition.xxx)`，加第十三格却不写对应那一段，TypeScript 一个字也不会说——
**没有任何 `if` 拦它，那一格条件就被当成「通过」**。
剧本写「要会引气诀才能进」，引擎读成「谁都能进」。
这比漏渲染糟：那是错误地放行。

所以 `src/engine/conditions.ts` 改成了一张 `CHECKS` 表，
`satisfies { [K in keyof Condition]-?: Check<K> }` 兜住。
锁下在**运行消费的位置**，不是只下在门禁上——加一格而不表态，
所有该理解它的地方同时红，而不是等某一支走查偶然发现。

同一张表也补在了 `verify.ts` 的第四道上（`NEEDS` 管「这一格要不要有人给」、
`MAKES` 管「这一种效果产不产出」）。这两张表落地当天就逼出了两处真东西：

- **`knowledge` 从来没被查过。** 剧本里三十处在问「他知不知道这件事」，
  而第四道门禁只对账 `item` 和 `flag`。少写的那些当时都对——`age` 确实不需要来源——
  **可它们是「碰巧对」，不是「说清楚了对」**。登记成 `null` 是明写的一句话，漏掉不是。
- **`breathing` 谁也没给。** 补上对账后当场红：`riverman#river` 有一条选项
  「你想起那个教你换气的人」，要求认知 `breathing`，而全库没有一处产出它。
  往回查，`wounded.ts` 的 `lift-fighter` 正文里写着「他教了你两遍」——
  事情发生了，认知层什么也没记。那条选项一辈子不会出现。

第二条跟 `Outcome.grants` 那段注释记的是**同一个教训的另一半**：
世界给的东西必须由结果携带。给了书没进行囊那次已经栽过一回，
这次是给了法子没进认知。于是 `Outcome` 补了 `teaches`，跟 `grants` 并排放着。

#### 后来这一道多了第四类：日子

从前它只对账三类东西——物件、旗标、认知。**日子从来不需要来源**，
因为出身掷出来是什么就是什么，世上没有哪一处效果产得出一种日子。

`character.livings` 落地那天，那句话变成了谎话。于是 `NEEDS.living` 从
「不需要来源」改成了真判据，`MAKES` 里也多了一格；三个出处各归各位：

| 日子从哪儿来 | 怎么进的对账表                          |
| ------------ | --------------------------------------- |
| 出身         | `LIVINGS` 那张表直接播种                |
| 抚养人       | 从 `CIRCUMSTANCES` 现算，不照着键名抄   |
| 半路上换的   | `MAKES.living` 扫库，跟旗标认知同一条路 |

而这一格逼出了一个存量漏洞：**第四道从来没扫过一天里那些去处和落点的
`requires`。** 补上之后对账的种数从 62 涨到 63——多出来的那一种正是
`work` 要的那个日子。原先那两处 `schooled` 恰好有人给，
所以一直是绿的：**它是碰巧对的，不是查过了对的。**

### 第三个维度：顺序。而这一层查完是干净的，干净得不一样

前两把锁都守静态的东西——字段有没有被索引、字段有没有被解释。
它们守不到第三件事：**同一批东西，换个次序还是不是同一个结果。**

引擎里有三处顺序确实决定语义，逐个查过：

| 查什么                    | 结果                                 | 而它为什么是对的                             |
| ------------------------- | ------------------------------------ | -------------------------------------------- |
| `branches` 前面遮住后面   | 0 条                                 | 靠作者每次写对，外加类型注释讲清了意图       |
| 同批 effects 读写同一面旗 | 0 处                                 | 靠作者每次写对                               |
| `time` 与记 `at:` 的先后  | 57 处同批，**全部 `time` 在第 1 位** | 曾经靠一个没写下来的约定，**现已改成分相**   |
| 同一条认知学两次          | 不可能错                             | **`contact` 只升不降**——结构上就不取决于顺序 |

三类都是对的，可**对的牢固程度差着量级**。

最后那行是唯一一个不靠人的：`character.ts` 的 `learn()` 里，
「接触」这一档只能往上走——听人说一嘴推翻不了亲眼见过。
于是同一条认知无论先听说后亲历、还是先亲历后听说，落下来的都是「亲历」。
**顺序敏感不是被检查掉的，是被单调性消掉的**：它压根不存在了。

`time` 那 57 处则是另一个极端。一致率 100%，可这个 100% 没有出处——
没有一行代码、一句注释、一道门禁要求 `time` 写在第一位。
下一个人把它写在末尾，那条认知的时间戳就退回去几天，
没有任何东西会吭声。**这正是 `breathing` 那种病的形状**：
不是坏了，是没有任何东西保证它不坏。

### 时间不是一个普通效果

那 57 处后来没有变成一条规矩，变成了一次分相。

立「`time` 必须写在第一位」会禁掉本来合法的写法：
`[{ 受伤 }, { time: 养了半个月 }]` 读起来就该是这个次序——先挨那一下，
再养半个月。作者按叙述顺序写是对的，不该为了引擎的方便改成倒着写。

而且这条规矩找错了病因。三十七种 `Effect` 里，三十六种在陈述**一件事发生了**：
拿到什么、认识谁、学会哪一条、旗立起来。只有 `time` 不陈述事实——
**它改变其余所有事实的解释上下文**。认知记 `learnedAt`、纪事记年份、
日记记日期，全都读世界时间。它跟世界年龄、天气、灵气浓度、因果链是同一层的东西，
不是同一批里的一员。

所以 `effects.ts` 里多了一张三十七行的登记表：

```ts
const PHASE = {
  /** 唯一的上下文相。它一动，底下三十六种记下的时刻全跟着变 */
  time: '上下文',
  attribute: '事实',
  flag: '事实',
  // ……其余三十四种
} satisfies { [K in Effect['type']]: '上下文' | '事实' }
```

`applyEffects` 据此两相结算：上下文相先走完，事实相再按原序落下。
`time` 不产生回执，提前它不动正文的次序；多条 `time` 同批也无所谓先后——
推进的是天数，加法不挑顺序。

**为什么是一张表而不是 `effect.type === 'time'`：** 因为这一相还会长。
`assertNever` 守的是「新变体有没有被处理」，这张表守的是「新变体属于哪一相」。
两件事，两把锁——修仙线加进天气或灵气浓度时，漏了会编译不过。

至此第三行也从「靠人」挪到了「结构上不取决于顺序」，跟第四行并排。
**顺序不是被检查掉的，是无从影响结果。**

### `scripts/settle.ts`：结算顺序走查

分相改完了，还得证明它真的生效。这一支拿全库每一批含 `time` 的 effects，
正着跑一遍、把 `time` 全挪到末尾再跑一遍，比对五个 store 的**完整快照**。
报「295 批效果，其中 226 批含 time，没有一批会因为 `time` 写在哪儿而改变结果」。

**这支脚本的全部可信度压在「两遍跑的差异只可能来自顺序」上，
而第一版没做到。** 世界起点是随机掷的（`birthTime()` 三个字段都走 `randomBetween`），
`roll` 也是随机的，两遍跑必然不同——那样它永远红，而且红得没有意义。
钉死 `Math.random` 之后还剩第二个噪声源：`id.ts` 用 `crypto.randomUUID()`
给关系编号，它不走 `Math.random`，钉死一个漏掉另一个，快照照样两遍不同。
换成计数器才算干净——而计数器本身也在查顺序：调用序列一变，编号就对不上。

**两个方向都验过。** 把 `applyEffects` 临时改回单相，这一支当场报出
50 批「换了写法就换了结果」；改回分相，全绿。只验绿的那一半不算数——
这条规矩从第四道门禁那次起就没松过。

### `scripts/shadow.ts`：分支遮蔽走查

`story.ts` 里 `branches` 是 `.find()` 取第一条满足的，
**声明顺序即命运**。这不是缺陷——`riverman#open` 那十一条并列分支里
「墙塌过的人排在最前」是刻意的，顺序表达的是优先级而非互斥。

可正因为顺序有意义，才会出一种静默的错：前一条比后一条更宽，
后一条就永远走不到。不报错、不断线、**也不算孤儿**——
那个 `next` 从别处也许还有入边，第二道门禁看不见它。

所以单开一支走查。它报「14 个节点写了多条分支，没有一条被前面的遮住」。

**它是走查不是第八道门禁，因为「判不出来」和「没问题」在这里是两回事。**
里面的 `implies()` 只认它有把握的那几类（区间、属性门槛、旗标有无、纽带），
剩下一律返回 false——宁可漏报，不可误报。报 0 只等于
「我有把握的那些都没重叠」，这种话适合走查说，不适合门禁说。
一支会误报的门禁比没有门禁更糟，第四道已经替这条教训交过学费。

**尺子自己也会瞎，所以末尾钉了十个例子。** 第一版拿
`JSON.stringify(c, Object.keys(c).sort())` 当条件指纹，
以为第二个参数是排序器——它是**属性白名单，而且递归生效**，
`{flag:{key,equals}}` 的内层全被抹平，两条不同的旗标条件都成了 `{"flag":{}}`，
当场"抓"出 26 条假的遮蔽。报 0 可能是干净，也可能是瞎。
于是六个必须抓到、四个必须放过，先证明尺子准，再信它量出的数。

### `scripts/founding.ts`：立基次第

前面三处顺序都在一批 effects 内部。还有一处在更底下：**八个 store 谁先建起来。**

一个人出生的次序是定的——先有你生在哪家，才有你在哪儿，才有你周围那些人，
最后才有你自己。`character.ts` 里那句「先有父母，才有你」说的是人物，
这一层说的是同一件事，只是落在了 `defineStore` 上。全库四处：

| 哪一行             | 建的时候读了谁                                                   |
| ------------------ | ---------------------------------------------------------------- |
| `world.ts:73`      | `ref(household.home)`——你在哪儿，取决于你生在哪家                |
| `world.ts:75`      | `ref([household.home])`——到过的地方，第一个是家                  |
| `character.ts:179` | `beBorn(household.origin, household.home)`——名字要问家里；       |
|                    | 它内部还会 `usePeopleStore()` 落父母、`useWorldStore()` 取出生年 |
| `character.ts:196` | `rollAttributes()` 里读 `household.origin`——什么家养出什么身板   |

这四处是**初始化期跨 store 读值**，跟函数体里读值完全是两回事，
而**代码上看不出区别**：两者写出来都是 `useHouseholdStore()`。
`people.ts:46` 也在 setup 顶层拿了 `useWorldStore()`，可它只存着不读，
真正读 `world.` 全在函数体里——所以它建的时候谁也不用等。
`character.ts` 的 `age` 是 `computed`，惰性求值，同样不算。

**违反了会怎样，试过：** 把 `household` 顶层改成读 `useWorldStore().time.year`，
造一个环出来。

```text
先建 household  → place 成了 undefined，而 home 是好的，不报错
先建 world      → TypeError: Cannot read properties of undefined (reading 'year')
```

同一个环，换个入口，一个静默污染一个当场崩。Pinia 遇到重入不抛错，
它把一个**尚未建完的 store** 交给你。静默那条更坏——状态栏上会写着 `undefined`，
而没有任何东西吭一声。**这又是 `breathing` 那种病的形状**：
不是坏了，是没有任何东西保证它不坏。

**判据是 `pinia.state.value` 的键。** 单独建一个 store，那里就是连带建起来的所有人：
建 `household` 应该只有它自己，建 `world` 应该是它加 `household`，
建 `character` 应该是四个；`diary` / `leanings` / `narrative` / `ui` 各自一个。
没有「判不出来」的灰色地带——所以这一支是门禁不是走查，
跟 `shadow.ts` 那种只能少说不能说错的走查不同。

同样先证明尺子会红：表里少写一条依赖、多写一条依赖，两种写坏法都必须被抓到。
另外 `satisfies` 只管表里的键跟手写的 `StoreName` 对得上，
而新加一个 store 文件不会让 `StoreName` 自己长出来——所以还扫一遍 `src/stores/`
里所有 `defineStore('…')` 跟表对账。
**一道守在没人走的门口的关卡，跟没有这道关卡是一回事。**

### 而「开始一世」有两个入口，第二个抄错了

上面那一段守的是**第一次建**。可开始一世还有另一个入口：**重掷**（`restart()`）。

两个入口要读的是同一个次序——`household` 先，`world` 和 `character` 跟上。
从前却各写了一遍：setup 里靠顶层调用的先后，`restart()` 里靠手写的四行。
连读的字段都是同一批：

|             | 建的时候读 household   | 重掷的时候读 household |
| ----------- | ---------------------- | ---------------------- |
| `world`     | `world.ts:66,68`       | `world.ts:189,190`     |
| `character` | `character.ts:159,168` | `character.ts:416,420` |

**抄第二遍的时候漏了两行。** `diary` 和 `leanings` 的 `reset()` 写好了，
全库没有一处调用。实测重开一世：

```text
日录　1 → 1     上一世那天还在
念头　1 → 1     上一世的「求道」还在
姓名　江瑜 → 许芝
家世　官宦 → 药铺
```

两者都 `persist`，所以刷新页面也还在。不报错、不断线——
**玩家开了新的一世，翻开日录，读到的是上一个人的一生。**

次序知识当时散在三个地方：`defineStore` 的 setup 顺序、`restart()` 的四行、
还有 `character.reset()` 里那句 `usePeopleStore().reset()`。
所以修法不是再补两行手写调用，而是把表挪进 `src/stores/founding.ts`，
两个入口都从它推导——`restart()` 现在只有 `resetAll()` 一句，
`satisfies Record<StoreName, () => Resettable>` 顺带保证**每个 store 都真有 `reset()`**，
新加一个忘了写，`vue-tsc` 当场红。

**判据同样是测实际行为，不是读代码推测：** 往八个 store 的 `$state` 里各塞一枚哨兵，
走玩家真正走的那条路（`story.restart()`），看谁还留着上一世的东西。
塞法不列字段名——列了就是又一张手写表，又会漏——按值的形状塞：
数组 push、对象加键、字符串和数字换成认得出来的值。
（布尔测不到，`true`/`false` 都是合法值塞不进哨兵。这是已知缺口，写下来而不是假装没有。）

两个反例都验过会红：`resetAll()` 里跳过 `diary`，精确报出 `[diary]`；
把次序倒过来，重掷当场崩在 `world.reset()` 上——**次序在这里是真的要紧，
不是排得整齐好看。** 而当初那个 bug 本身钉成了永久自检：脚本里留着「手写四行」
的旧写法，每次跑都得重新抓出 `diary` 和 `leanings` 一次。

### `scripts/upbringing.ts`：正文里不许无条件假定出身

前面那些门禁守的都是**结构**：断不断线、有没有来源、次序对不对。
它们全部绿灯的时候，内容里仍然可以写出这样一天：

```text
父亲在檐下修一把锄头。
你跟着下了地，一上午割了半晌草，手心磨出个泡。
晚饭时{elder}给你多盛了半勺。
```

而这一世的主角是皇子。

**这不是一句文案写错了，是内容层还留着「所有人生默认来自农户」的旧假设。**
结构正确、条件正确、NPC 存在、关系正确、世界状态正确——
可正文把出身那一格当成了默认真相。前面十几支门禁一支也拦不住，
因为它压根不是结构错误。

#### `{elder}` 解决不了这件事

插值只能解决**谁在说话**。`{elder}在檐下修一把锄头` 换到皇室
就是「皇帝在檐下修一把锄头」，还是怪。
要解决的是**他在做什么**——那是生活内容本身，不是称呼。

所以分层不在出身上，在 `living` 上：

|          | 是什么               | 谁决定                             |
| -------- | -------------------- | ---------------------------------- |
| `origin` | 出身——你生在哪一行   | 出生时掷定，此后不动               |
| `living` | 生活——你实际过的日子 | **还活着的抚养人**，没有才落回出身 |

这一格分开之后，「被老乞丐捡去养大的农户孩子」才说得出来：
他的 `origin` 还是 `farm`，`living` 是讨饭的。
**`{ origin: 'farm' }` 这个条件锁不死他读到什么。**

#### 三道判据

一、**七种人家，同一天。** 农户/猎户/商户/官宦/皇室/寺中孤儿/乞丐收养
各起一个人，跑同一个生活节点，看正文里有没有出现不属于这个家庭的生活事实。

```text
    农户 → farm，帮家里干活可抽 9 段
    猎户 → hunt，帮家里干活可抽 5 段
    皇室 → palace，帮家里干活可抽 0 段
    乞丐收养 → begging，帮家里干活可抽 5 段
```

皇室那个 0 是有分量的一格：**「帮家里干活」这句话本身就有前提——这家得有活。**
问的不是营生，是 `living.chore`。宫里不是「不用干活」，
是宫里的孩子跟「干活」隔着一整套人事，那一段该另外写。

二、**全库对账。** 294 个节点逐节算「谁读得到这里」，
再拿一张词表（锄头/下地/割草/场院/米缸/门槛/府衙/宫门/私塾…）去比。

读者集合必须逐节点收窄，不能按卷算——`child:memory` 那一卷入口对谁都开，
底下十个分流节点各自锁着一种出身。按卷算会把十条全判成穿帮。

三、**尺子自检。** 十条正反例证明这把尺子既抓得住也放得过，
外加四条收窄断言**直接把条件喂给 `livingsUnder()` 比对放行集合**——
不是静态断言境况表长什么样，是问系统实际算出来什么。

#### 「下地」在汉语里是两件事

「等你能下地走路」「又躺了些日子才能下地」说的是从炕上下来。
没有 `Fact.unless` 那一格，这道门禁会把每一句病愈都判成穿帮。

**一道乱喊的门禁比没有门禁更坏，因为它会训练人无视它。**
所以例外的边界也钉成了正反例：放行的只有那一句成语，
`'你照旧下地。'` 照样红。

#### 日常和收尾那几卷，一开始整个没查

`readersByNode()` 头一版只从 `lifeEvents` 播种。可入口有三种：
年表挑不出事的时候人回到**日常**（六卷，各归一个人生阶段），天年到了走进**落幕**。
那几卷连同底下每一节都取不到读者集合，于是在全库对账里被整段跳过——
**那不是「查过了没问题」，是压根没查。**

补上播种之后 `routine:youth:worker · 地里` 立刻现形。
所以现在每次都打印「扫到 283 节，走不到因而没查的 0 节」：
**一道悄悄少查了半个库的门禁，看着跟全绿一模一样。**

#### `KNOWN` 是审计结果本身，不是豁免名单

全库还剩 25 处默认了出身的正文，逐条记在 `KNOWN` 里，分两类：

- **卷上问的是出身，可出身锁不死日子**（4 处）。
  `child:memory:farm · 田埂` 这一节问的是 `{ origin: 'farm' }`，
  于是被老乞丐养大的农户孩子也走到了这里，读到「娘把你放在田埂上」。
  他没有田埂。销账办法：这几处问的一直是「过什么日子」，
  换成 `{ living: { is: '…' } }` 就对了。
- **压根没问过出身**（21 处）。这一类才是审计真正要指出来的东西：
  **它们不是条件写错了，是从来没有人想过要写条件。**
  待在家中就「扫了地，喂了鸡」，心念一动就「在门槛上坐着」，
  辍学了就「跟着母亲下地」——写的时候脑子里那个家，
  是个有院子有鸡有门槛有地的农户家。

这张清单是棘轮：**新写一句会红，清单里某一句被修掉了也会红**，
逼着人回来把这一行删掉。清单不是豁免，是待办。

而它咬得住是验过的——把那条农活的 `requires` 拆掉重跑，
第一道立刻对六种非农户人家各报三处，第二道从 25 涨到 29。

### `scripts/living.ts`：日子会变，而变过的每一段都留着

上一节把「你过什么日子」从户籍里拆了出来，可拆完那个答案仍然是**出生那天定死的**：
家里是农户，就一辈子是农户的日子。

削爵那一卷正好是那个例外。皇子在宫墙里长到十几岁，一道旨意下来迁出京城，
此后他过的日子跟宫里再没有关系——**而宫里那些人过的日子一点没变**。
所以变的不是那个家，是他。解析链因此多了最顶上一级：

```text
我现在过什么日子            ← character.livings
    ↓ 没有
抚养我的人现在过什么日子     ┐ 这两级在
    ↓ 也没有                │ household.living
我出生于什么家庭            ┘
```

**顶上那一级空着才是常态。** 一个人绝大多数时候过的就是家里的日子，
那时这个列表一条也没有，问题自然落到下一级去。
出生时就抄一条「我过着农户的日子」进来，它一旦被抄下来就不再跟着家里变了——
姐姐死了、老乞丐没了，`household.living` 那个 computed 自己会变，抄下来的那条不会。

#### 身份和日子是两个维度

这一轮先要答的是个更早的问题：`character.identity` 到底在描述「别人怎么看你」，
还是「你正在过什么日子」？两边各有各的残疾——
`identity` 有 setter、九处在写，可 `Condition` 里读不到；
`living` 有两个读取端，却没有任何人写得进去。

答案是它们不是同一个维度，而这句话在削爵那两卷里正好摆得出交叉证据：

|            | 削爵（`royal:fall`） | 削藩（`royal:demote`） |
| ---------- | -------------------- | ---------------------- |
| `identity` | 庶人                 | 寓公之子               |
| `living`   | fallen               | fallen                 |

**同一种日子，两个身份。** 反过来，`edict` 那道分岔——开门出去的和把门关上的
都是庶人，过的却是 `market` 和 `fallen`：**同一个身份，两种日子。**
这一对交叉就是这两格分开的理由本身，也是第四道判据的头一半。

后一半是第三格：**家里那格的营生。** 他自己走出去做工那一条摆得出另一个对照——

|                | 出去做工的 | 对照：没出去的 |
| -------------- | ---------- | -------------- |
| 他自己过的日子 | market     | farm           |
| 家里那格的营生 | farm       | farm           |

**同一户农家，孩子出门了，家里的营生一格没动。** 削爵那几条验不到这一层：
它们家里那格解析成 `palace`，那**证得出两格分得开，证不出家里那格是对的**——
削爵之后一家人搬出京城，家里还过着宫里的日子，这话本身就站不住。
有对照组的只有这一条。

#### 那道分岔落在一个早就存在的机制上

`market` 有 `chore`（一只箍松了的水桶），`fallen` 没有。
于是「帮家里干活」那个去处——它问的一直是 `living.chore`——
对走出去的那个重新开了，对关上门的那个仍旧关着。
一句正文也没有新写，同一句心念读出来是两样：

```text
开门出去　又是这样一天。天黑下来，把水桶搁回井台上。
把门关上　又是这样一天。天黑下来，把手里的东西放下。
```

#### 五道判据

前四道逐字照着验收写，第五道是这支脚本的另一半。

| 道  | 拦什么                         | 实测                                                 |
| --- | ------------------------------ | ---------------------------------------------------- |
| 一  | 当前生活能发生变化             | 六条人生落在 palace/market/fallen/fallen/market/farm |
| 二  | 变化后旧生活仍可回溯           | `fallen〔18 → 18〕market〔18 → 至今〕`               |
| 三  | 正文能根据当前生活出现不同内容 | 同一道分岔，那个去处一开一关                         |
| 四  | 身份与日子互不覆盖             | 上面那张交叉表                                       |
| 五  | 尺子自检                       | 四种坏实现全被拒绝，覆盖率 4/4                       |

六条人生走的效果**全是从库里原样读出来的**——脚本里只写门牌号
（`royal:fall#edict`、`royal:fall#edict:street`、`royal:demote#open`、
`reunion:apprentice#open:go`），一个效果也没有重写。抄一份进来，这支门禁就成了内容的第二个真相。

#### 判据自己被戳穿过一次

头一版第二道只问「这串日子形状对不对」：至多一段开着口、封口不早于开头、
前一段封在哪年后一段就从哪年起。看着挺全，可尺子自检当场把它戳穿了——
把履历砍成只剩最后一段（那正是「直接覆盖不留历史」的样子），**判据认了**。

因为**一段开着口的履历本身完全合法**，「把门关上」那条人生就长这样。
形状分不出「换过一次」和「换过两次但丢了一次」。分得出的只有一件事：

> 拿他实际走过的那几处效果去对——每一处换日子的效果，在履历里都得留下一段。

而那个期望不是写在脚本里的常量，是从他踩过的门牌号上读出来的。

#### 五个对照组，各红各的

判据写完先问一句：**如果这个机制根本不存在，这条判据还会绿吗？**
五处改动逐个跑过，每一处都红在它该红的地方：

| 把什么弄坏                       | 哪几道红                       |
| -------------------------------- | ------------------------------ |
| 拿掉 `street` 那一行换日子的效果 | 一二三四五**全红**（10 处）    |
| `liveAs` 改成直接覆盖不留历史    | **只有第二道**（2 处）         |
| 条件退回去读 `household.living`  | 第三道（外加对照组的一处）     |
| 让削藩那卷的日子跟着身份走       | 第一道 + 第四道                |
| 别处新写一处换日子的效果         | 第五道：`3 处 → 走到 3` 变 4/3 |

第二行是最要紧的一行：覆盖式的写法**不改变他现在过的日子**，
所以一三四全绿，只有「过去的日子还在不在」这一道会红。
**一道只在该红的时候红的门禁，比一道全红的门禁有用得多。**

#### 顺手修掉一处随机红灯

第三个对照组跑出来时多报了一句「农户的孩子什么也没发生，日子却成了 temple」。
那不是对照组的效果，是这支脚本自己的毛病：出生那一掷里，
任何出身的孩子都可能被寺里的老僧捡去养大，而**那一级会盖掉家里的营生**。

所以五条人生现在都掷到「没被人捡去养」为止再开始走。
掷掉它不是回避——收养是解析链的第二级，`upbringing.ts` 第一道盯的就是它；
这一支问的是最顶上那一级，起点必须是确定的。
**一条随机的对照组量不出任何东西。**

### `scripts/errand.ts`：凡人寻找修士

上一节守的是「一世怎么开始」。这一节守的是这一册里**他第一次自己决定要去哪儿**。

一个已经起了「想弄明白修行」这个念头的人，第一次主动去找。
不给功法、不给灵根、不给境界、不给宗门——**这一章甚至不保证他能成功**。
做的只是一条链：

```text
念头 → 寻找 → 得到线索 → 判断线索 → 再行动
```

七道判据里有五道是这一章的立论，另外两道单独走那条完整的回路。

| 道  | 拦什么                           | 实测                                       |
| --- | -------------------------------- | ------------------------------------------ |
| 一  | 念头真的改变他主动去找什么       | 没念头 0 条路，有念头 4 条                 |
| 二  | 寻访花掉真时间，落点算在回家那天 | 两种写法各 60 趟，都记在回家那一刻         |
| 三  | 找不到是正常结果                 | 静态下界 53%，实测空手而归 81%             |
| 四  | 线索可真可假，而他分不出来       | 记下的 751 条里，65% 错在事实、3% 错在因果 |
| 五  | 找了几年一件也对不上，念头就退了 | 中位数 8 趟白跑，「想弄明白」24 → 17       |
| 六  | 那条完整的回路走得通             | 见下                                       |
| 七  | 走到门口不等于拿到一个修仙系统   | 跑四十趟，境界和身份一动没动               |

**第一道是整章的地基，所以它一次随机数也不掷。** 同一天、同一个村子、
同一个外乡商旅，世界一寸没变，变的只有他心里存不存着那个念头——
而念头落到世界上就是 `leaning:know` 这一个旗标。他多出来的不是运气，是去处。
门槛写在**去处**上不写在事件上：没念过书的看不见「找先生问一句」，
十岁的孩子去不了渡口，可那件事照样发生，他只是无处可去。

**第三道量的是「白跑」。** 没有任何产出通路的落点是可以静态算的，
那是下界；实测比它还高十几个点，因为「问着了人」还要过 `knows` / `tells` 两道闸——
他找着了人，那人不知道，或者知道而不肯说。

**第四道里最要紧的一格是 `someone-who-knows`：那不是别人骗他，是他自己听出来的。**
对方摆摆手说不清楚，而他读出了「他知道，只是不肯说」。同一句话，
把念头旗标切掉再跑三千趟，它出现 0 回。

#### 第六道：南山那一趟，和三年以后

这一道不替系统作弊，全部是跑出来的：循环跑「去镇上找消息」（那一格权重 12/100），
直到他真的撞见茶楼后头那个老人。一次实跑用了 21 趟。

```text
撞见老人 → 记下 the-daoist-in-nanshan（没有 mistaken，老人说的方向本来就是对的）
        → 落 sure-of，认准南山
        → 跑一趟，八天　→　「不是那么回事」：屋里那个道士正在院子里劈柴
        → 「我要是那种人，还用得着自己劈柴？」
        → 这一天进日录，带着「南山」
        → 当天回看：点亮 0 天
        → 三年后回看：点亮 1 天
          「三年后有人说起，早些年南山里真住过那样一个人。不是你见的那个。」
```

**一个字也没有改历史。** 那一趟仍然是白跑的，那八天仍然没有回来，
变的只是他今天怎么看那八天。而当天必须点不亮——
当场就明白的不叫「多年以后」，那只是把延迟发奖做成了机制。

#### 第二道差点是一条测不出任何东西的判据

它本来只跑剧本原样那一份效果：`[{ time }, { errand }]`，
看认知的时间戳是不是等于他回到家那一刻。跑出来 60/0 全对，看着很稳。

**然后尺子自检把 `time` 从上下文相挪进事实相——第二道一声不吭。**

原因是剧本里 `time` 本来就写在前头，**照数组顺序挨个执行，
结果跟两相结算一模一样**。那条判据看着在守两相结算，其实一次也没碰过它。
分相的实质是**顺序不该说了算**，所以现在倒着再跑一份：

```text
剧本原样（先推时间，后落寻访）　抽 60 趟　记在回家那一刻的 60　记在动身那天的 0
倒过来写（先落寻访，后推时间）　抽 60 趟　记在回家那一刻的 60　记在动身那天的 0
```

破掉分相之后，第二行会变成 `0 / 60`。**这是尺子自检的全部价值：
一道永远绿的门禁跟没有这道门禁是一回事，而它看着像在工作。**
七道判据各存心写错一处，全部精确报红。

#### 已知缺口

「认准一处地方跑一趟」那个选项手写着八日，可他认准的那处可能是云台（二十日），
也可能是城隍庙（三日）。**剧本静态写不出他会去哪儿**，而 `follow` 是事实相，
让它自己推时间就破了第二道刚验过的那条不变量。

这一格不判红——它不是这一章引进来的（`seek:crossed` 那十二日早就在），
修它要动远行那一层的分相。门禁把六处地方的实际路程对照着印出来，
**为的是它别在某次改动里悄悄变成一个谁也说不清的数。**

### 写新剧本时

- 正文里的长辈写 `{elder}`
- **`{elder}` 是过渡方案，不是地基。** 它只解决「谁在做这件事」，
  解决不了「他为什么会做这件事」——老乞丐、长姐、寺里的师父、亲爹，
  不可能共享同一套生活内容。「每天傍晚去地里站一会儿」换个主语仍然是错的，
  因为讨饭的人没有地。
- 所以：**只写谁都可能做的事**（`{elder}每天傍晚都会出去一趟`）；
  真要写只有某种人才做的事，就给那一卷加 `requires: [{ bond: { kind: '生父', alive: true } }]`
  把关系锁住，然后正文里放心写「父亲」。

## 不做成开局词条抽卡

「十六岁随机抽一个背景【家破人亡】【家道中落】【获得机缘】」是这类游戏最容易滑进去的坑。
本作反过来做：**玩家不选出身，也看不到有得选。** 引擎幕后按权重掷定，
游戏第一句话就是既成事实——「你生在柳溪村，家里有六亩薄田。」

出身共十一种，权重照着真实的社会结构配：种地的占四成，皇子百里挑一。

**州府和出身是分开掷的。** 从前地名写死在出身里（`'云州 · 临江府 · 柳溪村'`），
于是所有人都挤在同一个府。现在一条大江贯穿四州十府，沿岸设治，
出身只管到街巷村名这一级，两边组合——
一个农家子可能生在江陵府的杏花坞，也可能生在东莱府的下河屯。
一共 **532 种不重样的门牌**（那是三段名字的笛卡尔积，算出来的），
六千世抽到其中 524 种，临江府只占 14.1%。

「沿江设府」不是装饰性的设定，是一条硬约束：碰上修行那一卷（`riverman`）
靠「渡口」和「江面」立住，所以每个府都必须临水。
古时设府本来也多在漕运要冲上，这一条既省事又不假。

> 这句话从前写的是「收尾那一卷」。渡口不再是终点之后，这条约束一点没松——
> 它约束的始终是**那一卷发生在哪儿**，跟那一卷是不是终点无关。
> 真正的收尾（`ending`）用不着水，它发生在人自己的床前。

| 出身 | 占比 | 这一家的孩子会遇到谁                               |
| ---- | ---- | -------------------------------------------------- |
| 农户 | 38%  | 天时、收成、一条可能走完也可能断掉的父债链         |
| 猎户 | 11%  | 从小进山。他比谁都容易在山道上看见路边的人         |
| 匠户 | 10%  | 木头味、刨花、分得出松和杉                         |
| 商户 | 9%   | 铺子里的外乡人。走北路的商旅在檐下说起过修士       |
| 客栈 | 8%   | 南来北往的人。有一夜来了个下雨不湿的客人           |
| 酒楼 | 7%   | 喝多了的人什么都说。有个跑山的说他见过脚不沾地的人 |
| 药铺 | 6%   | 八岁认得三十味药。有一天来了一味谁也认不出的       |
| 镖局 | 5%   | 父亲身上的刀口，和舆图上被朱笔圈掉的那几条道       |
| 官宦 | 3%   | 父亲对着别人弯腰。衙门里有一桩不许记档的案子       |
| 王府 | 2%   | 很高的墙。墙外有孩子在跑，你只听得见               |
| 皇室 | 1%   | 所有人都跪着。而钦天监那道门，你每天经过           |

**稀有出身不是「更好的开局」。** 皇子识字最多、家底最厚，
可他「知道有修士」落在全表最低的那一档，酒楼伙计的儿子是他的三四倍
（`scripts/origins.ts`）。宫墙替他挡住了所有的苦，也替他挡住了所有的机缘。
他不会在山道上救人，不会蹲在货郎摊前翻旧纸。
八品官的儿子和农户的儿子走到那条江上，青衫人看他们的眼神是一样的。

> 这里从前写着两个具体数：26% 和 81%。宫里那一行一千世只掷到六个人——
> **六个人算出来的百分比，一个人就是十七个点**，可它抄进文档之后，
> 看上去跟别处那些几百人算出来的数一模一样。
> `origins.ts` 自己在注释里写着这件事：**稀出身那几行是给人看形状的，
> 不是给人读数的**，所以那一支的门禁一条也没落在百分比上。
> 文档里引它的时候也该守同一条规矩。

「家道中落」也不是一个词条，是连着好几年长出来的一串事：

```text
连年雨水不足 → 收成不佳 → 父亲欠下一笔债 → 父亲为还债离开家乡
→ 死在外地 / 再无音信 / 几年后回来
→ 家里少个劳力 → 你不能再读书 → 你识字一般，但比同龄人壮实
```

每一环都靠上一环留下的旗标才进得来。中间任何一环条件没凑上，这条链就断在那里——
一千次模拟里，它只走完了约四十次。**一个人的一生里，它本来就常常不会走完。**

宗室另有一条：夺嫡、削藩、抄家。约四成的宗室会在十三到十五岁之间失去一切
（`scripts/royal.ts` 把出身钉死各跑三百世，宫里四成出头，王府略低于四成）。
从此他是个什么也不是的人——**哪天他站到江边，身后不再跟着任何人**。
剩下六成不会：他们要是走到那条江上，身边还带着两个随从，
连走上前搭句话都得先想办法把人支开。

「哪天」和「要是」是后补的两个词。这两句从前写的是「他们十六岁那年也在江边」，
因为那时候人人必到渡口。现在碰上修行是**一件得自己走出来的事**——
一辈子没出过村的宗室子弟，跟一辈子没出过村的农户一样，这辈子碰不上它。

## 世界先于玩家存在

世界从第一年就开始跑了，玩家生在第几年是掷出来的——
**两个玩家进入的是同一个世界，只是人生起点不同。**
走查里，玩家出生时这个府平均已经有十六年历史，而那些年跟他毫无关系。

年龄因此不再是 `year - 1`，而是 `year - bornYear`。

### 灾难是连锁，不是戏剧性

世界事件只做一件事：**改条件**。它绝不替玩家决定结果。

```text
少雨 → 减产 → 米价涨 → 有人囤粮 → 官府限价 → 米铺关门
     → 路上不太平 → 商队改道 → 有人往南边逃荒
```

每一环都要**前一环发生过**才轮得到。链条上任何一处没凑上，后面就不会发生。
跑一百年的结果：少雨 6 次、减产 2 次、涨价 3 次、囤粮 2 次、限价 2 次、
盗匪 1 次、改道 1 次、逃荒 0 次——**一路收窄**。

而且 **59/100 年什么也没发生**。这一条是刻意的：世界不该是灾难流水线，
大部分年头平到没人会记进编年史。不是每个人都活在故事的中心。

### 验收：同一场旱灾，长出不同的人生

要看的不是「有多少人遭遇旱灾」，而是同一个「米价涨了」落在不同的家里
会长出什么。走查（`scripts/world.ts`）：

| 出身 | 同一场旱灾里的走向                              |
| ---- | ----------------------------------------------- |
| 农户 | 紧一年 22　**有得选 9**　**饿过 2**　照常开饭 1 |
| 猎户 | 紧一年 12　有得选 1　照常开饭 1                 |
| 商户 | 照常开饭 10　紧一年 2                           |
| 皇室 | 照常开饭 1                                      |

农户是唯一会走到「饿过」那一档的；商户以上根本碰不到。
而「有得选」那一档里，玩家还要自己挑：卖东西、借债、还是让孩子出去做工——
**世界把条件推到这里，然后闭嘴。**

## 玩家怎么看世界

跟观察系统是同一个立场的两面：那边是**别人怎么看你**，
这边是**你怎么看世界**。两边都不给数字，都可能失真，都要玩家自己拼。

> 不是隐藏数值，而是让玩家通过文字建立自己的世界模型。

玩家永远看不到 `grain = 162`。同一场旱灾，七种人看见七样东西：

| 谁             | 他看见什么                                 |
| -------------- | ------------------------------------------ |
| 农户           | 入夏之后没下过透雨。地里裂了缝。           |
| 猎户           | 山泉细了。今年的兽也比往年瘦。             |
| 商户           | 进货的路不好走了。铺子里的货卖一件少一件。 |
| 客栈           | 店里空了。住进来的多是给不出房钱的。       |
| 镖局           | 局里的活多了。走一趟的价钱涨了一倍。       |
| 药铺           | 抓药的人从早排到晚。有几味药早就没了。     |
| 紧巴人家的孩子 | 这阵子的粥稀了。                           |

### 三条性质，缺一不可

1. **不是人人都看得见。** 农户看得出今年雨水不对，城里孩子看不出。
2. **看不全。** 一年只给一两处——给全了，玩家就能反推出精确的世界状态，
   那跟把数值摊开没区别。走查里同一个农户同一年跑四百次，
   每一处的出现率都在 17%–47% 之间，**没有一次能看全**。
3. **可能读错。** 这一条最要紧：

```text
「村口这阵子常有陌生人过。」
  └ 你以为是过路的客商。          ← 寻常人

「村口这阵子常有陌生人过，拖家带口，走得很慢。」
  └ 那是逃荒的。                  ← 心思细的人（insight ≥ 52）
```

同一个事实，两种世界模型。**玩家建立的模型可以是错的**，
而且他多半永远不会知道自己读错了。

### 一个农家孩子记事以来的那些年

```text
 1岁  入夏之后没下过透雨。地里裂了缝。
 2岁  秋后打下来的粮，装不满往年的仓。
 3岁  爹跟人说话时提过两回米价。
        └ 你听见了，但没往心里去。
 4岁  雨水还算匀。地里的活跟往年一样多。
 ……
13岁  今年是个好年景。场院上晒得满满的。
```

他经历了一场旱灾的头三年，然后世道缓过来了。
**他从没听说过「旱灾」这两个字。** 他只是记得有几年粥很稀。

## 玩家主动去问

前一层（感知）是世界给他看的，这一层是他自己去要的。
但要来的**不是正确答案，是那个人的局部世界**。

同一个「今年年景如何」，问四个人：

```text
爹：是贵了些。家里省着点吃。
同村的老人：想了半天，说他也不晓得。
米铺的掌柜：含混地应了一声，没有往下说。
衙门口的差役：本月米价仍在官府限价之内。
  └ 你想起街口那家米铺已经三天没开门了。
```

**四句话都不假，四句话拼不出真相。** 他得自己判断信谁，而且可能判断错。

### 两道闸：知道 ≠ 肯说

拆成两个独立的数，才能表达「他知道，但他不告诉你」——
而那恰恰是玩家最常撞上的情况：

| 谁         | 知道 | 肯说 | 真问出来的 |
| ---------- | ---- | ---- | ---------- |
| 米铺掌柜   | 88   | 22   | **20%**    |
| 家里的大人 | 95   | 40   | 37%        |
| 村里的老人 | 66   | 88   | 59%        |

掌柜知道得最清楚，却最问不出来——那是他的生意，他不会跟一个孩子交底。
而「他含混地应了一声」这句本身就是信息：**他知道，只是不肯说。**

玩家能问出什么还受年纪、关系、见识影响。十岁的孩子问衙门口的差役，
跟十六岁的伙计去问，得到的不是一回事。

### 玩家开始自己提问题

从前的循环是「事件找上门 → 给三个选项 → 挑一个」。
现在是「你看见了什么 → 你自己觉得不对劲 → 你决定去问谁」。

所以打听那一卷永远留着「接着干活去」——**什么都不问也是一种选择。**

## 知道不是一个开关

```text
听说 → 见过 → 猜想 → 确信 → 亲历
```

而且**只能往上走**。亲眼见过修士之后，再听人说一嘴，
不会退回「只是听说」。

同一个条目在不同的档位上，说法完全不同——升档不是补充细节，是**换一句话**：

```text
〔听说〕有人说这世上有能飞的人。多半是编的。
〔见过〕你亲眼见过一个。他站在船头，水面不动。
〔猜想〕他们大概是修行了什么法门。
```

这一层是后面「为什么拿到功法却不会修炼」的地基：
他手里那册书是真的，可他对「炼气」还停在「听说」——
中间那几档没走完，书就只是纸。

## 我今天想做什么

到这一步为止，玩家所有的行为都是**被事件叫出来的**：年表挑中一卷，
他在里面做选择。`day:ordinary` 反过来——没有人叫他，**他自己决定今天干什么。**

一天分三段，每段自己挑一个去处：

```text
【上午】帮家里干活
    今天出的力比往常多。
    晚上躺下的时候，腰是酸的。

【下午】去镇上
    庙前有人摆摊，卖的是针头线脑。
    你蹲着看了一会儿，什么也没买。
    摊主没赶你。

【傍晚】找爹说话
    爹在忙自己的事，没顾上你。
    你在旁边坐了一会儿，起身走了。
```

### 大多数行动没有机缘

这一册最要紧的一条规矩，是它**绝大部分内容都什么也不发生**。

每次行动都给知识、给属性、给新人物、给奖励，那是操作游戏，不是人生。
两千次行动的形状（`scripts/day.ts`）：

| 档   | 占比       | 是什么                           |
| ---- | ---------- | -------------------------------- |
| 无事 | **约 77%** | 什么也没发生                     |
| 处境 | 约 15%     | 手上多个泡、跟谁近了一点         |
| 见闻 | 约 5%      | 问出了什么、看见了什么、认识了谁 |
| 转折 | 约 2%      | 这一天真的改了后面的路           |
| 大事 | 约 0.4%    | 撞上了一件事，这一天整个被它占了 |

一路收窄，而且这**不是配平，是立场**：一生中绝大多数日子本来就什么也没发生，
也正因为如此，真的改变了什么的那些日子才显得要紧。

走查把「越往下越少」做成了硬验收——哪一档翻上去，非零退出。
**空的那一档也要拦**：「大事」占不到半个点，四百次里期望两三次，
三批里有两批是 0.0%——而「一档比一档少」那把尺子对 0 静默放行。
**没抽到和最少的，在那把尺子下长得一模一样。** 现在先查在不在，再查形状。

### 「无事」不是空白

一句「你干了一上午活」是填充物。这一册里的无事必须做到三件事：

**一、具体。** 不是「干活」，是「割了半晌草，手心磨出个泡」。

**二、带着世界。** 同一块地，旱年和丰年不是一件事：

```text
太平年景　30%  你跟着下了地。
旱灾中段　16%  地是干的。锄头下去，土块碎成面。
               {elder}半天没说话。
```

玩家读的每一句「无事」，同时也是在读这一年的光景。

**三、偶尔留个钩子。**

```text
你回来的时候，看见{elder}站在门口跟一个人说话。
你一走近，他们就不说了。
那人你没见过。他走的时候看了你一眼。
```

机制上什么也没变，可玩家知道有事在发生，只是这一天他没碰上。
**这是「过日子」和「空转」的分界线。**

### 能去哪儿，本身就是处境

去处不是一张固定的菜单：

```text
上着私塾、家里有人管的　上午：干活　去私塾　去镇上　山那边　找人玩　待在家　什么也不做
                        傍晚：找娘说话　待在家里　什么也不做
没上过学的　　　　　　　上午：干活　去镇上　山那边　找人玩　待在家　什么也不做
没有人管的　　　　　　　傍晚：待在家里　什么也不做
```

没上私塾的人没有「去私塾」，没人管的孩子没有「找人说话」。
**这不是锁选项，是他本来就没有那个去处。**

### 机缘不是年表发下来的，是他自己走过去的

| 他去了哪儿   | 可能撞上什么           |
| ------------ | ---------------------- |
| 往山那边走走 | 山道上那个人 约 4.4%   |
| 去镇上       | 货郎摊上那册书 约 3.5% |
| 帮家里干活   | 什么也撞不上           |
| 待在家里     | 什么也撞不上           |

撞上了，这一天就整个交给那一卷。于是「机缘」第一次不是从天上掉下来的——
**是他自己抬脚走过去的。**

## 时间过去了，但过去没有消失

一天过完之后，它去了哪里？

如果「无事」读完就消失，那玩家最终只记得那几个转折点，
体验会重新退回「事件集合」。所以有了**日录**——而它跟旁边两格
分工不许混：

```text
日录　我活过什么
认知　我以为那是什么
编年　什么真正成为了人生
```

编年必须稀：一生中值得进去的事不超过几十件。而他活过的日子有几万天，
那些什么也没改变的日子**恰恰是他活过的证据**。

### 光把每天的话存起来，那只是日志

```text
十三岁　今天帮家里收了一下午麦子。
十五岁　今天帮家里收了一下午麦子。
十七岁　今天帮家里收了一下午麦子。
```

单独看一句意义也没有，存三百条还是三百句废话。

真正让一天变成回忆的，是**后来发生的事让它重新有了意义**：

```text
【十岁那年】
    山路上没有人。
    你走到能看见村子的地方就坐下了。
    坐了很久，什么也没想。
    ——这一天什么也没发生。

【十六岁那年，他知道了修士这回事】

再翻回十岁那一天：
    山路上没有人。
    你走到能看见村子的地方就坐下了。
    坐了很久，什么也没想。
    └ 六年后你才知道，那条道上走过的人里，有些不是寻常人。
```

**原文一个字也没改，可这一天已经不是原来那一天了。**

```text
过去的事实　+　现在的新知识　=　新的意义
```

这跟认知系统里「原来那册是写坏的符书」是同一个结构：当年那句话没有变，
变的是他现在怎么看它。所以 `lines` 是当年的原话、永远不改，
后来想明白的只往 `hindsight` 里追加——跟知识条目只往 `history` 里
追加、绝不抹掉旧说法，是同一个立场。

### 两条分寸

**当场就明白的不算。** 每条规则都有 `after`，隔得不够久就不点亮——
这一层的全部价值在于隔了很久。走查里当天知道修士点亮 0 天，
四年后回头看点亮 1 天。

**不是每一天都会被点亮。** 八年的日子塞满所有能拿到的认知，
最后只有 35% 的日子有下文。如果每一条日录最后都被点亮，
那这套东西只是把「发奖」延后了。

### 而某件天天做的事，从某年起再也没有出现过

```text
你十四岁以后，再也没有替家里下过地。
```

这一句是**算出来的，不存**——它的真假取决于回看的那一刻。
存下来的那一刻它就会开始说谎：他明天又去了一趟，这句话就不成立了。

那三百句「今天帮家里收了一下午麦子」，到这里才变成人生。

### 走查（`scripts/diary.ts`）

前五项验引擎能不能做到，第六项验**它在真实人生里真的发生了吗**：

| 观察项                 | 值      |
| ---------------------- | ------- |
| 走到卷终               | 100%    |
| 每世日录条数           | 中位 27 |
| 有过「多年以后才明白」 | 64%     |
| 有过「再也没有」       | 38%     |

第六项抓到过两个只有跑全人生才看得见的问题：

- **「一天」在年表里一辈子只发生一次。** 于是日录里永远只有孤零零一条，
  「多年以后才明白」根本没机会出现。加了 `repeatable` 才解决——
  大多数人生事件一辈子确实只来一次，但「过日子」不是。
- **`day-omen` 设了不清。** 每一段都会重新跳进同一卷机缘，
  玩家的人生卡在同一个货郎摊前，一年一年地重来。
  症状是收尾落点里冒出了 `morning` 和 `interest`——**人生停在了半路上**。

两个都不是单支走查看得见的东西。**能力成立 ≠ 真的会发生。**

### 已知边界：三百年怎么办

眼下每天全文保留。一辈子攒下二十来条（`scripts/diary.ts` 走完一生，中位 26），
完全够用，但一个活三百年的人会攒下十万条——**这是一个已知边界，不是没想到**。

> 这句话从前写的是「凡人这一段（十六年、二十来条）」。人生从十六年拉到六十来年之后，
> **条数一条没多**——因为「一天」那一章的窗口是七到十六岁，后半生根本没有日常之外的日子。
> 二十来条现在是六十年攒出来的，那不是够用，那是**后半生几乎没有日子可记**。
> 同一件事在底下「内容全压在前十六年」那一节还会再出现一次。

`DayEntry` 的形状是照着日后能折叠设计的：折的时候把一段时间里的
若干条压成一条摘要，`tags` 取并集，`hindsight` 照旧追加。
这一轮先把「旧日子能被重新点亮」这个闭环验通，压缩留到后面。

## 人为什么会开始想做某件事

到这一步为止，玩家会感知、会误解、会打听、会行动、会失败，
过去也可以被重新理解。但还缺一样东西：

**他为什么会从「活着」逐渐变成「想做某件事」？**

这件事必须做对，否则修仙最终会变成「十六岁自动开始修仙」——
剧情塞给玩家的主线，而不是他人生里长出来的目标。

### 但绝不做成「勇敢 72 / 好奇 81 / 野心 43」

那样人的内心就变成了一张给玩家看的数据库，
而这跟前面几轮反复守住的立场是冲突的：
**别人怎么看你不给数字，世界什么光景不给数字，
那么你自己是什么人更不该给数字。**

所以念头做成跟日录同构的东西：它不是一个数，是**一串他做过的事**。

```text
第 29 年　晚上又陪着坐了一会儿。
第 30 年　又下了一天地。
第 31 年　他头一回把家里的难处跟你说了。那天以后你就没再当自己是孩子。
第 32 年　在家待了一天。
第 34 年　场院上晒得满满的。你站着看了一会儿。
        ……另有 22 件

16 岁：你想把日子过安稳。
```

最后那一句不是系统贴的标签，是上面那一串攒出来的。
**「我好像总是这样做」得让玩家自己读出来。**

### 三个阶段，而中间那一层是关键

```text
埋着　什么也不显示，只在日录里留下痕迹
反复　带某些标记的日子里，正文多出一句
明白　他自己说出来了
```

念头一冒出来就变成「【任务：成为郎中】」，那是任务系统，不是一个人的一生。
真实的样子是这样的——同一个人到了「反复」这一档：

```text
这一天在【山那边】→ 你在能看见远处的地方站了很久才回来。
这一天在【镇上】　→ 回来的路上你走得很慢。
这一天在【在家】　→ 你在门槛上坐着，看的是村口那条道。
```

**没有新选项，没有任务条，只是他本来就会做的事上多了一句话。**
玩家会先觉得这句话眼熟，很久以后才反应过来自己一直在这么干。

### 验收标准不是「多少人获得了目标」

那是任务系统的问法。要看的是**方向的分布形状**（`scripts/leanings.ts`，1000 世）：

| 一生走完     | 占比      |
| ------------ | --------- |
| 始终没有方向 | **59.1%** |
| 有个说不清的 | 25.4%     |
| 说出来了     | 15.5%     |

绝大多数人一辈子没有明确的方向——好好过日子、养家、把孩子拉扯大、
平平安安走完。**那不是失败路线，那是大多数人。**
如果每个人最后都长出一个「我要改变命运」，凡人生活就失去了真实性，
而后来那一句「我要修仙」也就没有分量了。

分档只说了形状，说不了**哪个念头够得着这道线**。所以还要逐个念头看两列
（一个人可以同时动过好几个，所以每列都不必加到 100%）：

| 心里长出来的               | 动过的 | 说出口的 |
| -------------------------- | ------ | -------- |
| 你想把日子过安稳。         | 18.8%  | 8.3%     |
| 你不想再被人按住。         | 13.1%  | 3.3%     |
| 你想活得久一点。           | 7.2%   | 1.9%     |
| 你想离开这里。             | 4.7%   | 1.3%     |
| 你想弄明白那些说不通的事。 | 2.9%   | 0.6%     |
| 你想让家里过得松快些。     | 1.9%   | 0.3%     |
| 你想学看病。               | 1.3%   | 1.1%     |

**门禁守的是「动过的」那一列，不是「说出口的」那一列。**
最稀的「想学看病」说出口只占八个千分点，要它每批都稳定出现得三千世起步——
而这一支一世要走完一辈子。「动过的」那一列样本厚得多，
而一个念头真够不着线的时候，它这一列也会空。**报出来的数字和守住的底线，
本来就不必是同一个。**

「把日子过安稳」占了说出口的人里的 49%——它是七种之一，而且是真正的方向，
不是「没有目标」的委婉说法。

### 两道门槛是量出来的，不是拍脑袋的

头一版两道门槛是猜的，结果 **86.7% 的人都说出了口**——凡人生活整个塌掉。
第二版把 tag 火种加上 `chance` 之后又矫枉过正到 95% 卡在「说不清」。
第三版才去量：一个人最重的那个念头中位在 14、九十分位 17，
于是「反复」定 15、「明白」定 18。**先量分布再定门槛，才收得住。**

`chance` 那一条是长尾真正的发条：没有它，凡是天天做的事都会稳稳往上加，
于是人人都会长出方向。而真实的样子是——同样去地里干活，
绝大多数时候心里什么也没留下，只有偶尔那一次会。

### 门槛是一把尺子，可它量的东西不在一个量级上

后来加了愿望分岔和「找」那几卷，同一批念头被更多的事推着走，
15 就放过了 57% 的人——「绝大多数人一辈子说不出口」这句话悄悄不成立了。
照新分布重定成 **18 / 21** 的时候，底下那个真问题才露出来：

**七个念头压根不在一个量级上。**

那一次不再看总分布，改成逐个念头量它一辈子最高能长到几分：

| 念头           | 从前的天花板 | 够得着 18 吗   |
| -------------- | ------------ | -------------- |
| 想把日子过安稳 | 二十多       | 够             |
| 想弄明白       | 二十上下     | 够             |
| 想离开这里     | 17           | **不够**       |
| 想让家里松快些 | 12           | **不够**       |
| 不想再被人按住 | 7            | **差得没边儿** |

也就是说，「你不想再被人按住。」和「你想让家里过得松快些。」这两句
**从写下来那天起就说不出口**——不是我把门槛提高才害死的，
15 那一版它们同样够不着。**一条谁也够不着的线，跟没写这条内容是一回事。**

原因不在权重，在火种挂在哪儿：

- 「想过安稳」有三条日常挂在最常见的三个标记上（在家 10.5 次/世、家里的大人 8.4、替家里干活 5.2）
- 「想让家里松快些」唯一那条日常挂在「粥稀了」，而那个标记**只在百分之一的人生里出现过**

**火种挂在什么标记上，比它给几分要紧得多。**

> 这条教训后来又收了一次利息。「出身无假设」那一轮把下地的活分了流之后，
> `替家里下地` 从 5.4 次/世掉到 **0.7**——因为它现在只落在种地的人家身上，
> 而种地的人家占三成八。挂在它上头的两条火种（「场院上晒得满满的」
> 「场院上还剩多少」）就此从常见掉成罕见，`想让家里过得松快些` 那一列
> 也跟着从 5.9% 降到 1.9%。
>
> **这不是回归，是账本第一次记对了。**从前那 5.4 里有八成七是猎户、商户、
> 当差人家的孩子在「下地」——他们家没有地。数字变小是因为假的那部分被删掉了。
> 真正欠着的是另一件事：**那十种人家至今没有属于自己的干活正文**，
> 他们只分得到三段谁家都成立的杂事。这笔账记在 `scripts/upbringing.ts` 的
> `KNOWN` 里，不在这一轮偿还。

补的时候还量出第二件事：**一条日常火种一辈子拢共只攒得下两三分。**
挂满四条也不过十来分，离二十一分那道线差得远——
所以「说出口」那一档实际上是由**一次性的大事**决定的，不是日常攒出来的。
于是每条够不着的线都补了两样：几条挂在常见日子上的日常，
外加一件真发生过的大事（错过的车队、护不住的弟妹）。

眼下七个念头全都够得着：最低的那个（想学看病）有 1.2% 的人生动过它，
0.8% 说得出口。

> 所以门槛改动之后要做的不只是重量分布，**还要逐个念头看它够不够得着这道线。**
> 而逐个看的时候要看「动过的」那一列——「说出口的」最稀处只有八个千分点，
> 一千世里八个人，拿它当门禁会三天两头误报。**判据要落在够厚的那一档上，
> 哪怕报给人看的是另一档。**

### 火种不许自带剧情

38 个火种，它们认的全是**已经发生过的事**：日录标记 19、旗标 10、
知识 8、出身 1。念头必须从人生里长出来，不能是另一套平行的剧本。
权重也都压在 6 以内——**一个人的方向是几十件小事磨出来的，
不是某一天忽然想通的。**

## 念头反过来影响行动，但不替他做决定

念头若只出现在人物面板里，它终究只是一张人物画像。可它一旦直接变成
「【任务：跟商队走】」，这个游戏就换了一种。

正确的位置在中间：**念头改变的是他更容易注意到什么、更愿意试一试什么、
更容易坚持什么——而不是替他做决定。**

### 同一个机会，两个人读到的不一样

```text
【心里什么也没存的人】
    镇上的货栈在招短工，管饭，按天算钱。

【想离开的人】
    镇上的货栈在招短工，管饭，按天算钱。
    你忽然想到，货栈的活是跟着车队走的。
```

同一条告示，**同一组选项**。多出来的那一句不添信息，只添注意力——
「货栈的活是跟着车队走的」是他自己想到的，不是管事的多告诉他的。

### 念头不得创造世界事实

商队本来就要走，短工本来就在招，那条道本来就在那儿。
**世界不因为玩家想要什么而配合他。**

所以机会的入场条件里一个念头也没有（做成了静态门禁）：

| 机会     | 入场条件                         |
| -------- | -------------------------------- |
| hiring   | 年纪 ≥ 12                        |
| caravan  | 年纪 ≥ 13、旗标 `toward-leaving` |
| the-road | 旗标 `saw-the-road`              |

`toward-leaving` 是**玩家自己攒出来的**——他去问过、去做过短工，
管事的才认得他。一个从没动过离乡念头、却恰好来问过两回的人，
到那一天照样会被问一句。**世界认的是脸，不是心思。**

### 四种人生，而「没走成」是大头

`scripts/leaving.ts`，1500 世里 100 世的「想离开」长到过「反复」那一档：

| 人生                       | 占比    |
| -------------------------- | ------- |
| A 越来越主动，最后真的走了 | 3%      |
| **B 一直没动，留在原地**   | **87%** |
| C 念头后来退下去了         | 10%     |
| D 走了一趟，回来改了方向   | 3%      |

**这四个数字读作约数。** 分母是那 100 个动过念头的人，不是 1500——
A 和 D 各只有三个人，多一个少一个就是一个百分点。
1500 世量得住 B 那一档的形状，量不住 A 和 D 的小数位；
要把最稀的一档抬到十来个人得五千世，而这一支一世要走完一辈子。
**门禁要的世数，和一句结论要的世数，本来就不是一回事**——
底下的门禁只查这四档在不在，不查它们各占几成。

B 最要紧：**有一个念头 ≠ 必须实现这个念头。** 否则念头就成了隐藏任务。

### 念头不是一条经验条

八成的人生里，「想离开」被什么东西压下去过。而**压下去的时候，
顶上来的不是空白**：

```text
家里病倒一个人的那阵子，你没有再提过出门的话。
    你想离开这里。 −5 → 你想把日子过安稳。

你留意到他今年比去年瘦。你想的是自己要是不在，谁来管。
    你想离开这里。 −2 → 你想把日子过安稳。

你回来了。路上那两个月，你想起家里的次数比想起别处多。
    你想离开这里。 −8 → 你想把日子过安稳。
```

他没有改主意，他只是走不开——而年复一年地走不开，跟改了主意其实差不多。

这跟认知系统里「解释可以往下掉」是同一个立场：
**玩家对世界的认识会改变，玩家对自己想要什么的认识也会改变。**

为此 `LeaningState` 多了一个 `peak`：念头退回去跟从来没有过是两回事，
**一个想走了三年最后留下来的人，跟一个从没动过这个念头的人不是同一个人。**

### 走查必须模拟人，不能模拟骰子

这一支走查里有一段**刻意不随机**的代码：心里存着「想离开」的人，
读到那句话之后六成半会去点那一条；心里什么也没存的人只有一成半。

这不是作弊——**这套设计的机制本身就是「念头改变他注意到什么，
注意到什么改变他会点哪一条」**。走查若一律随机，就等于假设玩家是一枚骰子，
那念头的价值根本测不出来。头一版就是这么跑的，结果 A 高达 48.9%，
而 B 只有 1.1%。

## 需求、愿望、念头是三样东西

「想吃饭」「想离开」「想活久一点」「我要修仙」——它们不是同一种心理状态。

```text
需求　有对象，有期限，会过去。而且它逼着你做事
      家里有人病重，要救命

愿望　没有对象，也没有方向。它只是一种模糊的想要
      想活久一点

念头　有方向。它改变你注意什么、愿意试什么
      想学看病 / 想弄明白 / 想守着家
```

这个区分是有代价才立起来的。从前「想活久一点」被当成一个念头，
于是它得有 `echoes`——可一个只是**怕死**的人在山上、在镇上、在家里
到底会多做什么？答不上来。**因为它根本不指向任何行动。**

所以愿望**没有 `echoes`**：它不改变他注意什么，它只是攒着，
直到某一天分岔成一个真正有方向的念头。

### 同一个愿望通向五个地方

而**分岔往哪儿走，取决于他手边有什么**：

```text
【给家里抓过药的孩子】
    你开始留意郎中怎么看脉、怎么开方。你说不出为什么。
    → 你想学看病。

【听说过山里那种人的孩子】
    有人说那种人不吃不喝也能活。你想的是「活」那个字。
    → 你想弄明白那些说不通的事。

【家里那个人一直没缓过来】
    家里那个人一直没缓过来。你把能担的都担了。
    → 你想把日子过安稳。

【被那只凉手抓过腕子的孩子】
    左腕那圈疤在阴天会痒。你开始留意谁的身手好。
    → 你不想再被人按住。

【什么也没接触过的孩子】
    你想过这件事很多回，每回都想不出个头绪来。
    → 什么也没通向
```

### 而最常见的结果是哪儿也没去

真实人生里（`scripts/wishes.ts`，1500 世，其中 460 世攒到过分岔门槛）：

| 通向了哪儿           | 占比    |
| -------------------- | ------- |
| **什么也没通向**     | **57%** |
| 想弄明白那些说不通的 | 23%     |
| 想学看病             | 13%     |
| 想把日子过安稳       | 7%      |
| 不想再被人按住       | 0 个人  |

分母是那 460 个攒到门槛的人。最后一档不是一条没写的路——它要求这辈子
被那只凉手抓过腕子，而那件事本身三百世里才八个人，一千五百世也没轮到
一个既撞上它、又在分岔那一掷里选中它的人。

所以走查不报「通向了四个地方」，报的是**「抽到 4 种，一共 5 种」**：
前一个数掉了是抽样的事，后一个数掉了是内容的事。而后一个数是从
`WISHES` 里**数出来**的，跟跑多少世无关。

这张表从前是四百世跑的，中间两档连跑三批落在 19 / 29 / 23 和 19 / 10 / 13——
摆动一倍，读起来像有人改过内容。一千五百世连跑两批，四档的差都在两个点以内。
可**加世数买得到「常见的那几档稳下来」，买不到「罕见的那一档出现」**：
一千五百世那一格照样是零。它的可达性由另一处交代——
走查第三节直接把那个旗标设进去走一遍。

门禁守的不是这几档各占几成，而是「一共通向三个以上的地方」和
「没有哪一条占到七成」。**攒到门槛的人全都分岔了**：
筛人的不是分岔这一步，是它通向哪里，而最常见的去处是哪儿也没去。

**若一个愿望必然通向某一条路，那条路就是系统偷偷安排的主线。**
而这里最常见的结果是：他就是怕，而且一辈子不知道能怎么办。

这一半靠的是分岔时的那一道闸——**手边有路，不等于他找得到**。
同样想活久一点、同样听说过山里那种人，有的人会把两件事连起来，
有的人一辈子也没连上。没有这道闸，凡是听说过修士的人都会必然走上那条路。

### 需求这一层不新建数据结构

「家里有人病重」由旗标和一卷世界事件承载就够了。它真正的价值在于
**它是愿望的来源**，不在于它自己被记住——再加一层存储只会让
三个概念互相打架。

那一卷（`need:illness`）也守着老规矩：**病好不好，跟他守得多勤无关。**
掷一次，六成好了、三成落下病根、一成没熬过去。他的选择改变的是
自己经历了什么，不是把结果掰成对他有利的那一种。

### 「我要修仙」将来在哪一层

在念头那一层再往前长一步。**它不该凭空生成**——

```text
亲人病重　　　→　需求
听说修士寿长　→　愿望：想活久一点
知道确实存在　→　念头：想弄明白修行
开始主动寻找　→　方向：想修仙
```

而上面那张表说明：走到第三步的只有 23%，
走到第四步的会更少。**修仙是人生的一条路，不是所有人的终点。**

## 同一件事，在不同人生里不是同一件事

十六岁往后的某一年，有些人会站到那个渡口上，看见同一条船、同一个穿青衫的人。
可站在那儿的不是同一个人：有的埋过爹，有的等了三年没等到消息，
有的一辈子没出过村，有的家里紧到会先看那身衣裳值多少钱。

**他们看见的不该是同一段话。**

而这件事最容易做错的做法是分支：家里死过人就跳到另一节去。
那样写出来的是两段各写各的内容——落笔时是一件事的两种样子，
改到第三次就是两件事了，**而没有任何地方会吭声**。

所以 `SceneNode` 加的是另一格：

```text
blocks   这件事本来的样子。谁都读得到，一个字不因人而异
seen     同一个节点、同一批选项、同一个去向，只多他自己看见的那一两句
```

```text
【谁都读到的】
    你在江边站了很久。
    江面今日格外安静。
    远处，一叶乌篷船顺流而下。
    船头站着一个穿青衫的人。

【埋过爹的人，多读到一句】
    你想的是他站在那儿，能站多少年。

【见过山那面那条道的人】
    这条江往下走，是你没去过的地方。
```

### 类型上就不可能变成分支

`seen` 里只有 `text`。没有 `effects`，没有 `next`，没有 `choices`——
不是靠纪律拦着，是压根写不出来。**能用类型守住的就别拿门禁去守。**

剩下那半条纪律机器管不了，得作者自己守：**只添注意力，不添信息。**

```text
可以　你想起家里那年也是这样
不行　你认出那是修士
```

后者添的是世界事实，于是没死过人的孩子和死过人的孩子从此读到的是两个世界。
认出修士要靠 `recognize` 那几条选项，各有各的知识门槛——**多看一眼不等于看懂**。

### 跟念头那一层的分工

前面已经有一条几乎一样的通路：`Opening.readings`，想离开的人多读出
「货栈的活是跟着车队走的」。两条看着像，管的不是一回事：

| 这一层             | 由什么驱动 | 回答的问题   |
| ------------------ | ---------- | ------------ |
| `Opening.readings` | 念头       | 他想要什么   |
| `SceneNode.seen`   | 人生事实   | 他经历过什么 |

分工不是靠约定守的：`seen` 的条件是 `Condition[]`，而 `Condition` 里
**根本没有念头那一格**，写不进来。反过来说也成立——经历过丧事的孩子
站在江边，不需要先长出什么念头，才配多看那个人一眼。

### 新开一格声明，就是新开一个不设防的口子

头一版我在渡口那节写了 `left-village` 这个旗标。它不存在，是我编的。
第四道门禁（前置条件）一声没吭——**它没扫 `seen`**。

正文完好、选项照旧、跳转不断，只有那一句永远不会出现。
补上扫描范围之后立刻红了：

```text
旗标〔left-village〕　没有任何地方产出　被要求于：riverman#river · 所见
```

这不是加了一道新门，是让已有的那道看见新的地方。前置条件从 37 种变成 40 种。

### 走查：光验它会红不够，还得验这几句真的因人而异

`scripts/seen.ts` 跑三百世，量的不是「多少人读到了」——那是覆盖率的问法。
这一层要看**分布的形状**：

```text
day:ordinary#morning        300 / 300 世走到

    9.3%   本该指派你的那个人不在家。          father-away
   32.3%   屋里没有人喊你。今天家里没人不舒服。 sat-through-illness
   24.3%   闲着的一天也是一天。这个你算得清。   家境 ≤ 35

   读到的组合共 6 种，白板占 52.0%
```

三条判据：每一句都得有人读到、没有一句是人人都读到的、白板仍是最常见的一种。
最后一条守的是**当所有人都特别，就没有人特别**——多数人都多读出点什么的时候，
这一层就自己把自己稀释掉了。

反例三个，都验过会红：把一句的条件换成 `age ≥ 0`，红成「人人都读到」，
同时白板掉到 0%，第三条一起响；把条件换成 `father-dead` 且 `father-missing`——
两个旗标都合法、都有出处，第四道一句话不会说，可爹不能既死了又失踪，
红成「没人读到」。

> 原先还有第四条判据「组合不能只有一种」。删了：**造不出只让它红的反例。**
> 每句都满足「有人读到、也有人读不到」，就必然至少有两种组合，
> 它被前两条整个盖住。留着一条永远不会独立触发的判据，
> 是在制造「我们检查了」的假象。

#### 而选点错了两次，都是走查抓出来的

这几句头一版写在 `routine:teen#open`，看着最平常，一辈子会读到好几遍。
走查一跑：**三百世只有一世走到那一节**。写在读不到的地方跟没写是一回事，
而四道构建门禁全绿、七道内容门禁全绿，没有任何东西会吭声。

第二次是条件选错：`knew-hunger` 只在荒年最惨那一档设过，命中率 0%。
换成家境刻度——那是个人人都有值的连续量，不是一个几乎没人碰得到的旗标。

> 这道门抓不住什么，也得说清楚：它只判「一世都没有」，不判「几乎没有」。
> `knew-hunger` 后来有一次跑出 0.3%（三百世撞上一个人），于是放行了。
> 设计上它跟死句没区别，可要抓它就得拍一个百分比门槛，而**拍出来的门槛自己会烂**——
> 一支三十批响一次假警报的门禁，比没有门禁更坏，它教人把红灯当噪音。

## 修行的第一关不是学不会，是不知道去哪找

上一节把「想弄明白修行」这个念头造出来了。这一节问的是下一句话：
**然后呢？他能做什么？**

答案是：打听。他没有别的办法。而这一册刻意不碰功法、炼气、灵根、境界——
**那些是门里的事**，这一册讲的是一个人怎么走到门口，
而绝大多数人一辈子也没走到。

### 他听到的东西里，假的占六成

`src/content/leads.ts` 里十条消息，权重摊开来是这个样子：

| 真伪                   | 占比 |
| ---------------------- | ---- |
| **假**                 | 61%  |
| 半真（方向对，细节错） | 19%  |
| 真                     | 20%  |

这不是配平出来的数，是立场。而更要紧的一条是**假的讲得比真的还清楚**：

```text
〔假〕三十年前有位陆真人，在城东白石桥下点化过一个卖炭的。
〔真〕每年三月总有几个外路人往上走。上去的没见下来过。
```

编的人不需要顾忌事实，所以他有名有姓、有地名、有年份，还带一句诗。
而那条真的，说话的樵夫自己都不知道那是什么——**最好的真线索
往往来自一个毫不知情的人。**

写新线索的分寸就在这儿：若假线索写得一看就假，玩家就有了
一个引擎没打算给他的工具。

### 他手里只有两样工具，都要花时间，都可能白花

**一是跑一趟。** 世界怎么回应，只看那地方到底是什么——
去一个不存在的地方就是扑空，其中三成半还会在那儿撞上个等生意的人
（去那种地方的都是他这样的，而那正是骗子挑地方的道理）。

而**真地方也未必看得出来**。它没有牌子，也没有人迎出来，
心思不够细的人会觉得那只是一座山、一间关着的屋，在底下待两天就走了。

**二是听第二个人说同一件事。** 他分不出真假，可他数得清有几个人
指了同一处地方——假消息各说各的，真消息会撞在一起。
这也不是保票：说书人那一段和卖符的那一段照样可能凑巧撞上，
那时候他会满怀把握地跑去一个根本不存在的地方。

### 五种结果，其中最常见的是什么也没找到

`scripts/seeking.ts`，4000 世：

| 结果                          | 占比    |
| ----------------------------- | ------- |
| **C　什么也没找到**           | **93%** |
| E　找到入口，人家没收         | 约 3%   |
| B　找到的全是假的，或者跑空了 | 约 2%   |
| A　找到真线索，并且进了门     | 约 1%   |
| D　找到入口，自己没进         | 约 1%   |

走到门前的一共 5%。而 C 里头约七成人其实**听到过东西**——
他攒了三五件说不清的事，只是没有两件对得上。

> **手里有几句话，跟找到线索是两回事。** 没有两条撞在一起，
> 他就没有任何理由动身。跟一句也没听着的人比，他多的只是几件心事。

### 可是没有人会玩四千世

上面那张表量的是**分布**，而分布不是玩家会经历的东西。
一个人大概玩十世。1% 那一格在四千世里是四十个人，在十世里通常一个也没有——
也就是说，**那件事对绝大多数玩家等于不存在**。

所以走查最后一节把每一格都换算到十世的尺度上，问一个不同的问题：
**玩十世的人，有多大概率见过一次？**

| 结果                          | 十世里至少见过一次 |
| ----------------------------- | ------------------ |
| C　什么也没找到               | 100%               |
| E　找到入口，人家没收         | 约四分之一         |
| B　找到的全是假的，或者跑空了 | 约两成             |
| A　找到真线索，并且进了门     | 约一成             |
| D　找到入口，自己没进         | 约一成             |

**玩十世，站到过一次门前的是四成。** 另外六成的人玩完十世，连门口都没见过。

这张表写的是约数，不是量不准，是**量到这个精度就够了**——
「玩十世大概能撞见一回」和「9% 还是 13%」，对读的人是同一句话。
而这一节从前差点毁在相反的一头：见「[走查会撒的几种谎](#走查会撒的几种谎)」第六条。

而那十世读起来是这样：

```text
 1　〔C〕听着 1 件事，没有两件对得上。哪儿也没去。
 2　〔B〕两条对上了，跑了一趟——不是那么回事。
 3　〔C〕听着 1 件事，没有两件对得上。哪儿也没去。
 4　〔C〕听着 1 件事，没有两件对得上。哪儿也没去。
 5　〔C〕听着 1 件事，没有两件对得上。哪儿也没去。
 6　〔C〕听着 1 件事，没有两件对得上。哪儿也没去。
 7　〔C〕听着 1 件事，没有两件对得上。哪儿也没去。
 8　〔C〕问了几年，一句也没问着。
 9　〔C〕听着 2 件事，没有两件对得上。哪儿也没去。
10　〔C〕问了几年，一句也没问着。
```

十世里多半整整齐齐全是 C。**而那正是这一册要的样子**——
一个人打听了一辈子什么也没打听着，是常态，不是失败。

### 门前那一下，他到死也不知道人家凭什么

走到门前的人，那个人会让他把手伸出来，两根指头搭在腕子上停两息，
然后说一句话。引擎看的是 `root`——**那个数在他出生那一刻就定了**，
跟出身、跟努力、跟他有多想都没有关系。王府的孩子和农户的孩子
在这一掷上平等，而两个人谁也不知道自己那一个数是多少。

```text
〔差得远〕你回去吧。这条路不是人人走得。
〔差一点〕差得不多，可差着就是差着。
```

两句话的分量完全不同，可结果一模一样。**而他连自己是哪一种都不知道。**

灵根排在最后一步不是偶然：先是你为什么想修仙，再是你愿意付出什么，
然后是有没有机会接触，**最后才轮到有没有资格**。
一个天生资质极好、却从没听说过修士的人，这几卷一辈子碰不上。

### 入场只看念头，不看资质

```ts
requires: [{ knowledge: 'cultivators-exist' }, { flag: { key: 'leaning:know' } }]
```

条件里有一个念头，这是合法的——判据是那条老规矩：
**这一卷写的是世界发生了什么，还是他做了什么？** 「他逢人就绕着弯问」
是他自己的行动，当然要看他心里想什么。而「镇上招短工」那种世界发生的事，
条件里一个念头也不许有。

### 走查自己撒的两次谎

**一、把 C 判成了 A。** 头一版把「听着几件事」算作找到线索，于是 A 有 6%。
可那些人哪儿也没去过——**材料不是结果**。改判之后 A 掉到 1.1%，
而那才是真的。

**二、变量偷偷相关了。** 头一版里「他问了几年」和「他到门前进不进」
都从循环下标 `i` 派生，结果问得少的人恰好也是不进门的那一批，
于是 D 那一格永远是空的，看上去像是「没人会走到门前又掉头」。
**走查里的每个变量必须各掷各的。**

> 这两条和后来栽的另外五条一起收在末尾的[走查会撒的几种谎](#走查会撒的几种谎)。

## 他终于找着人了，可他不知道自己找着的是什么

上一册讲的是怎么走到门口。这一册讲的是**门口那个人是谁**。

从前这中间是空的：找着了就摸腕子，摸完就收或者不收。玩家事后连对方姓什么、
多大年纪、穿什么颜色的衣裳都说不出——那个人不是人，是一道门禁。

现在这中间有一段。它同时往两个方向走：

```text
他怎么看你　　拿他的尺子量。量得准不准，他自己也不知道
     ↕
你怎么看他　　你没有尺子。看得见的只有衣裳、年纪、手上有没有茧
```

**两边都会看错，两边都不知道自己看错了。**

### 修士不是一台鉴定机

尺子长在人身上，不长在身份上。`observers.ts` 里那五把尺子谁拿谁用，
而每个人手里那一把决定了他这辈子看得见什么：

```text
山道上那个人（炼气）　悟性、神魂　　　　他这辈子看不见资质
观里那位道人（筑基）　资质、悟性　　　　看得见了，可只有七成准头
```

于是一个 `root` 83 的孩子站在炼气修士跟前，那个人量的是悟性 48 和神魂 58，
量到什么说什么，说完就走了。**他没有说谎，也不是瞧不起谁——他只是没有那双眼睛。**

而这件事的后果是真的，不只是一句台词。他肯不肯多说两句，读的是**他量到的那个数**：

```text
筑基修士肯多说两句　root=5 时 　0/400
　　　　　　　　　　root=95 时 380/400
```

同一段代码换成炼气修士，两组的差别是 **0.2 分**——在噪声里。
他看不见的东西不会影响他的态度，因为他压根没量。

> 底下这些数字都是**某一次四百世跑出来的**，每跑一次浮动几个点。
> 判据从来不是「必须是 51.5%」，是那几行 √ 各自要守的下限。
> 唯独 `0/400` 跟 `380/400` 那一组几乎不动——那不是概率，那是门槛 62
> 撞上一把看不见 `root` 的尺子，量出来的数永远落在中间。

### 「说岔了」不是「偏了几分」

判据是**他说出口的那句话，跟真值本该得到的那句话，是不是同一句**。
真值 62 该说「倒是不错」，他看成 58 也说「倒是不错」——那他没说岔。
分档本来就是一层粗筛，判断力不足的人多半只是在同一档里晃。
**偏差要跨过档位的坎，才变成一句错话。**

炼气修士每次会面说两句。四百次里：

```text
两句都说对　206　51.5%
一对一错　　161　40.3%
两句都说岔　 33　 8.3%
```

中间那四成正是要的东西：

> 「你记性不错。」他说对了。
> 「修行资质寻常。」他说错了。
> **玩家不会知道哪句错。**

那个「哪句错」在代码里是有的（`Remark.astray`），但它**只在引擎里活着，
一个字也不进 store**。玩家若能知道哪句是错的，那就不叫错了。
这一条不能只写在注释里——门禁扫过落进 store 的每一条评说，
确认没有一句带着标记。

### 两把尺子并排放着

同一个孩子，先后让两个人看：

```text
炼气修士（判断力 52）说悟性　一般 252 ／ 尚可 106 ／ 差了些 42
筑基修士（判断力 71）说悟性　不高 348 ／ 尚可  52
```

同一世里先后问两个人，两句悟性**对不上的有 377/400**，
其中恰好一个说岔、另一个说对的有 171/400。

`aspects.claims` 只增不改，所以这两句就并排落在「修行」这一面下：

```text
一名炼气修士：「悟性尚可。」
一名炼气修士：「神魂尚可。」
一名筑基修士：「悟性不高。」
```

「多年以后你终于知道当年那句是错的」那一刻**不需要任何新机制**，
它就是这两行挨在一起。

### 你读他，读出来的多半是错的

修士好歹还有一把量得不准的尺，玩家手里什么也没有。他看得见的每一处都是真的，
而他从每一处读出来的意思分开记着：

```ts
{ sees: '衣裳是旧的，袖口洗得发白。',   // 真的
  reads: '你想，看来也不是什么了不得的人物。', // 错的
  mistaken: '因果' }                     // 错在哪一层
```

合成一句「你看出他是个高人」就完了——那句话既是观察也是结论，
玩家没有出错的余地，而**没有出错余地的观察不叫观察，叫通知**。

四百次会面，读错 400 次。错在因果的 367 次，错在事实的 33 次。
因果那一层更深也更难破：「他六十三岁」撞一回就散了，
「穿得旧所以本事不大」可以跟他一辈子。

还有一条看着反常、其实最像真的：

```text
你有多笃定　确信 279　猜想 121
```

**错得越整齐，他越笃定。**看着年轻、衣裳旧、手上没茧——三处凑到一起，
「不过是个穷道士」这个结论就变得非常结实。而真相是他一样也没看懂。

### 走到这一步，什么也没拿到

没有鉴定灵根，没有赠功法，没有入宗门，没有开修炼。一件物事也不给，
一格属性也不动，境界仍旧是「凡人」，身份仍旧是「孩童」。

他拿到的只有话：两句评说，一条见闻。连那个人姓什么都不知道——
在他心里那个人一直叫「山道上那个人」，而人口册里写着姜不换，六十三岁。

### scripts/meeting.ts：第一次真正接触修士

七道判据，每道跑四百世：

| #   | 验的是                                                   |
| --- | -------------------------------------------------------- |
| 一  | 双向：一次会面，他往你身上落东西，你也往他身上落东西     |
| 二  | 一对一错：同一次会面里既有说对的也有说岔的               |
| 三  | 能力边界：炼气那个看不见资质，所以他一辈子不会提这两个字 |
| 四  | 他怎么待你按他量到的数，不按真值                         |
| 五  | 你也会读错他，而且错得越整齐越笃定                       |
| 六  | 什么也没给：属性、境界、身份、随身物全都没动             |
| 七  | 两把尺子：两个修士说的不是同一回事                       |

**第四道最容易写成空判据。** 「炼气修士的态度跟 `root` 无关」这句话，
在一个 `regard` 恒等于常数的错误实现下同样成立——判据会绿，而机制是死的。
所以那一道拿同一把尺子去量筑基修士，**他那一组必须显著有别**：

```text
√　炼气修士的态度跟资质无关（相差 0.2，在噪声里）
√　筑基修士的态度跟资质大有关系（相差 37.7。对照组：判据不是空的）
```

守「X 不影响结果」这类不变量，必须真的把 X 变一遍，**而且要有一个
「X 应该影响结果」的对照组在旁边站着**，否则那道判据什么也没证明。

自检那一节同理，两头都验：判断力满格的人 800 句里必须说岔 0 句，
判断力为零的人 800 句里必须说岔一大半。只验一头的话，
一个恒返回 `false` 的实现能过上半场，恒返回 `true` 的能过下半场。

### 这一章修掉的一处死枝

`interpretation: wrong.length >= 2 ? '确信' : '猜想'` 头一版是条死枝。
炼气那位当时只有四处形迹，其中三处是错的，而玩家一次留意三处——
`wrong >= 2` 必然成立，`猜想` 那个分支**一次也走不到，
而它看起来跟活的一模一样**。

补了两处「他恰好读对了」的形迹之后那一档才有了呼吸（121/400）。
门禁里现在有一道专门守着它。

### 这一章没做到的

用户举的那个例子是「十六岁某修士说你资质一般，二十八岁另一位重新看你」。
**这件事从"做不到"变成了"还没做"**，而这两种没做到不是一回事。

从前是真的做不到：凡人这一册十六七岁就在渡口收尾，那之后的人生还没写，
一件写在二十二岁的事在当时等于死代码——年表永远抽不到它，
**而它看起来跟活的一模一样**。

人生模拟那一轮把这个约束拆了：一生跑到咽气那年（六十上下），
`riverman` 自己的窗口就开到二十八岁。所以今天写一件二十二岁的事，
年表抽得到它。两次会面之所以还压在十三到十六岁之间，
是因为**没人去把 `meeting` 那一章的窗口往后拉**，不是因为拉不动。

而且要紧的从来不是隔了几年，**是隔着两把尺子**——
两条 claim 并排落在同一面下这件事，跟它们相差一年还是十二年无关。
窗口往后拉是一行数字的事，机制一个字不用动。

## 他为什么愿意教你

上一章验的是两个人互相打量了一回。这一章问的是那之后的事，而题目不是
「玩家遇到了修士，所以得到了功法」——是：

> **这个修士为什么会对这个凡人产生「值得教」的判断？**

主语在他那边。**「能不能修仙」是这个孩子的事，「有没有人愿意教你」是别人的事**，
这两件事必须彻底分开，否则绕一圈还是回到原地：开关只是从 `root >= 72`
换成了 `regard >= 72`，而所有资质好的人仍旧都有人教。

所以这一章做的不是功法系统，是一个很小的闭环：

```text
他观察你 → 心里形成一个数 → 他凭这个数决定拿你怎么办 → 你怎么回应 → 关系动不动
```

### 四种人生必须同时立着

```text
资质很好 · 他没看出来　　　　　　　　　　→ 不教
资质普通 · 他判断很准 · 觉得你适合某事　→ 教一点
资质很好 · 他看出来了 · 可他有自己的事　→ 仍旧不教
资质普通 · 他看错了 · 收下了　　　　　　→ 后来才发现不合适
```

少一种，这一章就塌回「资质决定一切」。三百世实测，四种都跑得出来：

```text
一　root 91 的孩子站在山道那位跟前　　0/300 教　他一句资质的话也说不出来
二　root 41 的孩子走进药庐　　　　　　300/300 教
三　观里那位量到 81.6 分，肯到顶 242/300　　可他教的是 0/300
四　他教的那个孩子背下来了、也自以为懂了，做得一点不差，身上什么也没有
```

第三种最要紧，它需要一份**看得出来却仍旧不教**的数据。起先想拿第一种那份
（root 91 而 will 26）兼着用，不成——那孩子在观里那位的尺子上只量到 69.4，
抬了顶也够不着「教一点」要的 86 分。**那样量的就成了「够不够分」，不是「肯不肯教」**，
两件事又混回一处了。于是分成两份数据：一份证「他没看见」，一份证「他看见了也不教」。

第四种的落点在他自己身上：**他挑人挑得对**——那孩子确实沉得住气；
他错在把「沉得住」连到了「学得会」上，而这两样量的根本不是同一个东西。

### 第一次师承不叫「加入师门」

界面上不会跳出【师父：陶仲】。关系是一格一格长出来的，五档：

```text
不理会 → 搭话 → 使唤 → 带一段 → 教一点
```

四句台词就是这四格：

```text
搭话　　「你若真想学，明日再来。」
使唤　　「这两日替我做件事。」　　　北墙根那几筐药翻一遍，霉的挑出来
带一段　「跟着我走一段。」　　　　　天没亮上后山，一路指了七八样草
教一点　「我教你一个呼吸法。别出去乱说。」
```

**一次最多挪一格。** 哪怕他第一眼就量到九十几分，头一回也只到「搭话」：

```text
第 1 回：量到 93.7　不理会 → 搭话　（他心里肯到「教一点」）
第 2 回：量到 97.0　搭话 → 使唤　（他心里肯到「教一点」）
第 3 回：量到 90.3　使唤 → 带一段　（他心里肯到「教一点」）
第 4 回：量到 91.1　带一段 → 教一点　（他心里肯到「教一点」）
```

右边那一列是这四行的全部意义所在：**他心里肯给的一直高于实际给的**——
挡住的不是分数，是关系还不够长。少了这一列，这四行跟「分数慢慢涨上去」没有区别。

### 那道顶是他自己的事

每个修士有一个 `ceiling`，跟你有多好没关系：

```text
山道上那个　顶在「搭话」　　他没在挑人
观里那位　　顶在「带一段」　二十年前他答应过一个人一件事，那件事到今天还没了
　　　　　　　　　　　　　　他要的是一个能替他把那件事了结的人
药庐里那位　顶在「教一点」　他要一个肯天天守着炉子、不嫌苦、也不问为什么的人
```

三个人里只有一个会教人，而他的顶正好在「教一点」——**顶和肯不肯教是同一件事的两面**。

「观里那位不教」这个结论，在一个 `regard` 恒等于零的坏实现下同样成立。
所以门禁把他的顶临时抬到「教一点」，**同一个孩子必须当场就被教**：
原样 0/300，抬了顶 217/300。卡住他的确实是那道顶。

### 听过 ≠ 记住 ≠ 明白 ≠ 身上有反应

他给的那一点东西，也不是「学会了」这一个开关。而它更不是一条阶梯——
脑子里那几层和身上那几步是两条各走各的轴，下一章单说。这一章只验一件事：
**每一处都真的有人停在那儿。** 四关看的东西各不相同：

```text
背下来　　看 memory　　　　　　练得多真的有用（helps 5）
想明白　　看 insight、memory　　练得多有一点用（helps 3）
碰得着　　看 root、spirit　　　　练一辈子跟练三回一模一样（helps 0）
稳得住　　看 body、will　　　　　练得多没用，练得久才有用（helps 0）
```

少一处有人停，这几关就是同一关换了几个名字。实测四份数据各卡一处：
记性极差的停在「听过」；背得下来却想不通的停在「记住」；
都懂就是碰不着的想到了「明白」，身上还在「照着做」；碰着了的才到「摸着了」。

而这几关看的东西彼此不沾：**身上那条看的 root/spirit/body/will，
跟脑子里那条一样也不碰**；碰得着和稳得住看的也不是同一样东西。

最后那两行是这一节的重点：**有些事努力管用，有些事努力不管用，
而这个人分不出自己碰上的是哪一种**——他只知道自己又练了一夜。

```text
根骨不够的：练 3 回身上在「照着做」，练 80 回还在「照着做」
记性差的：　练 1 回想到「听过」，练 40 回想到「记住」（对照组：这一关磨得过去）
```

对照组不能省。「练多少回都没用」这句话，在一个门槛高到谁也过不去的实现下
同样成立——所以旁边站着一个「练得多真的过得去」的人，还有一次尺子自检：
把 `helps` 临时改成 9，那个碰不着的孩子必须当场碰得着
（原样一辈子停在「照着做」，改了之后停在「摸着了」）。

### 中间那一层，他自己看不见

「明白」这一关过没过，玩家读到的是同一段话：

```text
你把那几句在心里过了一遍。
「不是气，是那个地方。」
你想，这话说得也没什么难懂的。
```

上面这段是真懂了那个读到的。没懂那个读到的一字不差。

**「你想，这话说得也没什么难懂的」——这句话在两种情况下都是真的。**
一个真懂了，一个自以为懂了，而他们心里的感觉完全一样。

前后两关是看得见的：背不下来他知道自己背不下来，碰着那一下身子会告诉他。
唯独中间这一关不给回音——门禁里有一道专门守着它，
还有两条对照组守着「记住」和「摸着了」必须看得出来，
否则一个「所有关卡都不给反馈」的实现也能过。

> 下一章把这条纪律又用了一次，而且用得更狠：不是同一关的成败共用一段话，
> 是**两个完全不同的状态**共用一段话。

### 走到最后，什么也没多

一格属性没动，境界还是「凡人」，身份还是「孩童」，行囊里一件东西也没有。
他拿到的是一条见闻：接触档「亲历」，而理解档**得分两次问**。
人口册里，那位老人跟他的关系是——没有关系。

```text
他听见那一刻　　未理解　　他听见了，他不懂
他想通之后　　　确信　　　而这只是他自己的笃定，不是世界盖的章
```

那一格是会动的，所以门禁在教完那一刻取一次，练完再取一次。
只问一次的话，两种写法都能让它绿。

练过几回是记着的，可它记在旗标里，不在玩家读得到的地方。
**他到底过没过那一关，也一个字都没漏进见闻里。**

### `scripts/tutelage.ts`：八道判据

| #   | 验的是                                                      |
| --- | ----------------------------------------------------------- |
| 一  | 四象限：四种人生真的都跑得出来，不是理论可能                |
| 二  | 两件事：资质高低跟「有没有人教」无关                        |
| 三  | 一次一格：第一眼就量到满分，头一回也只到「搭话」            |
| 四  | 硬顶：卡住观里那位的是他自己的事，不是你不够好              |
| 五  | 几关：听过 ≠ 记住 ≠ 明白 ≠ 身上有反应，每一处都有人停在那儿 |
| 六  | 补不了：碰得着那一关，练三回和练八十回一模一样              |
| 七  | 看不见：「明白」那一关的成败，玩家读到的是同一段话          |
| 八  | 什么也没多：属性、境界、身份、随身物全没动，也没有谁认了师  |

第二道最容易写成空判据。「药庐那位教不教跟 `root` 无关」这句话，
在一个 `footing` 恒等于「不理会」的死实现下同样成立。所以那一道有三层：

```text
root 12 / 94 两组，其余六项完全相同　　教 300/300 : 300/300　相差 0.0%
will 24 / 94 两组　　　　　　　　　　　教 0/300 : 300/300　　相差 100%（对照组）
同一份数据换观里那位（他看得见资质）　搭上话 0/300 : 300/300（资质没有断线）
```

**教授率顶到 100% 会掩盖小效应**——真有人给 `root` 塞了一分权重，
两边仍旧是 300/300。所以还量了一把更细的尺子：他心里那个数。
三百世的均值标准误只剩 0.4 分，`root` 那一组差 0.2（噪声），
`will` 那一组差 25.5。一样东西只要沾上一点权重，就会在这个数上露出来。

### 一份「他应该会教」的样本，一半的世里没被教

这一支写完头一遍，六道红。根子在一处算错的账：**样本是按真值配的。**

`blur()` 的第一件事不是加噪声，是**往中间拉**：

```text
ignorance = 1 - acuity / 100
pulled    = value + (50 - value) * ignorance * 0.6　　← 高分往下压
jitter    = ±34 × ignorance
```

那个孩子起先写的是 will 88 / body 76。药庐那位准头 88，把 84.4 拉到 81.9；
另一把准头只有 71，把 77.2 拉到 72.5。合起来 77.2，而「教一点」要 82——
**每回叩门约六分之一都不到的概率够得着，九次机会累计四成上下**，
实测 45.7%，跟预测对得上。

也就是说：**照真值算他早该被教了，照他实际看到的数算，他多半不会被教。**
那正是这一整套东西想说的话，只是当时说到了不该说的地方——
后面五道判据全跟着塌。样本要按他看到的数来配，不是按真值。

### 一句躺在门禁里的空话

第八道原本有一行 `people.personOf(那位老人)?.bond`——**`Person` 上根本没有
`bond` 这个字段**。它恒等于 `undefined`，于是那一行永远绿：
就算哪天顺手认了个师父，它照样打勾。

`vite-node` 不做类型检查，门禁就这么绿着跑了一路，直到 `vue-tsc` 才把它揪出来。
关系不在人身上，在边上，得问 `bondsWith`。现在那一行末尾站着一段尺子自检：
存心认一个师父，这条判据必须当场看得见。

> 这跟上面第八道结构门禁是同一件事的两个面：**没有检查地躺着的东西不会出错，
> 它只会一直是对的。** 一句永远为真的判据比没有判据更坏——它占着位子，
> 还让人以为那件事有人看着。

### 这一章刻意不做的

没有完整功法系统，没有宗门。

「教一点」那一格是可以反复去的，可他第二次教的不比第一次多——
现在靠的是 `footing` 一格一格往上挪，不是「他记得上回教过你什么」。
后者要等功法系统，前者已经够用了。

还有一件在代码里是**没有东西**的：山道上那位看错了而没收下的那个孩子，
永远不会被纠正——那一头压根没有任何后续。这种「不存在」验不了，只能靠人读。

## 师父教了你，和你真的会了

上一章验的是他愿不愿意教。这一章验的是教完之后：那五句话进了耳朵，然后呢。

要回答的只有一个问题——**「师父教了你」与「你真正会了」之间，到底隔着什么？**
让一门具体的功法自己说话，答案是两样，而**两样都不在属性表里**：

```text
你走的是不是那件事　　他能给你的只有话。而那件事不在话里
你身上有没有那个东西　这一样练一辈子也补不了
```

**这两样当事人都分不出来。** 他只知道自己又练了一夜。

### 上一版的四层是命名出来的，不是这门功法长出来的

原先四层排成一列：听过 → 记住 → 明白 → 转得动。排得整整齐齐，
整齐得可疑——「转得动」根本不是「明白」的下一级，它是另一条轴上的事。
一个人完全可能背得滚瓜烂熟、每一句都讲得出道理，身上一丝反应也没有；
也完全可能身上早有反应了，却说不出那是怎么回事。

证据就躺在文本里：现在「摸着了」那三行，是从旧的 `转得动.passed`
**原封搬过来的，一个字没改**——

```text
数到第三下的时候，脐下那一处忽然凉了一下。
很轻，一瞬就没了。你不敢动，坐着等它再来。
它没有再来。可你知道你没有想错。
```

这段描述的从来就不是「掌握」，是「碰着了一次」。**文本一直是对的，
错的是它上头那个名字。** 所以这一版拆成两条各走各的轴：

```text
脑子里　听过 → 记住 → 明白　　　　　　　　　Grasp
身　上　没上手 ─┬→ 照着做 ─→ 摸着了 ─→ 拿得住　Hold
                └→ 走岔了 ─┘
```

四种组合都跑得出来，实测：`明白/摸着了`、`明白/照着做`、`记住/摸着了`、
`记住/走岔了`。**而这四个孩子在他挑人量的那两样上一模一样**（body/will = 86/94）。
少一种，这两条轴就是一条轴换了两个名字。

### 那个分叉：他以为他在教，他其实在挡路

第二条轴中间那个分叉是这一章全部的新东西。

`Rite` 上多了一格 `asks`——**这样东西得靠哪一种教法才教得进去**。
它跟「师父有多用心」没有关系，说的是这件事本身的性质。
`Cultivator` 上对应多了一格 `way`。四种教法没有高下，只有对不对得上：

```text
说给你听　　念一遍口诀，讲一遍道理。你听着
做给你看　　他做一遍，你在旁边看着
按着你做　　他上手扳你的肩、按你的背。你身上有他的手印
让你自己找　他把你放在那儿，什么也不说。这也是一种教
```

这一格不是先想到「应该有个教法维度」再去填内容的。**是先有了陶仲**——
后山认草那一段写着「说了名字，说完就走，不管你记没记住」，
门槛上那一段写着念完五句就起身收拾去了。他的教法早就在内容里了，
只是从来没有被命名过。

而守一要的是「让你自己找」，这一格也是那五句话逼出来的：第二句说「走到脐下三寸」，
可脐下三寸是你身体里面的一个地方，**他没有办法指给你看**；
第五句他自己都说了，你要找的不是气，是那个地方。

```text
陶仲会的　　说给你听
守一要的　　让你自己找　　　永远对不上
```

于是那五句话给了你一个错的方向感：你以为你知道该往哪儿使劲了，
你很认真地往那儿使劲，而那不是那件事。这就是「走岔了」。

**一个从没人教、自己瞎坐的人反倒不会走岔**——他知道自己什么都不知道。
认真教反而害了他，这是这一章最不像游戏的一句话。而这不是「他教得不好」：
他教得很认真，他只是不知道这样东西教不了。**他这辈子也不会知道**，
他只会觉得是自己讲得不够细。

### 不是所有认真学的人都学得会

这是这一章的反例要求，也是它最要紧的一道。两个孩子，
**根骨一项不差**，师父同一个，教的同一样东西：

```text
药铺的孩子　悟性 30　出身药铺　　→　想到「明白」，身上「摸着了」
官宦的孩子　悟性 40　出身官宦　　→　想到「记住」，身上「走岔了」
其余六项：memory=58 body=86 will=94 fortune=50 root=72 spirit=66（两人相同）
```

**学不会的那个悟性更高。** 他悟性高、根骨够、师父认真教，
而他一辈子在岔上。这一条少了「六项钉死」的对齐就白写了——
不然「他学不会」永远可以解释成「他资质差一点」。

分野在 `handsKnow()`：**你手上有没有那一份不靠话的经验。**
认草的人闻一下就知道是哪一味，说不清凭什么；下套的人看一眼草压得对不对，
也说不清凭什么。这样的人听见一句说不通的话，不会硬往话上凑——
他知道话到不了那儿。

而它不是出身决定论。第三份样本是个**匠户**的孩子，悟性同样 30，
小时候在后院认过药（`herb-lore` 是一条见闻，不是出身）——他也学会了。

所以决定这件事的不是「人 + 悟性」，是
**「人 + 所学之物 + 教法 + 他手上有没有那份经验 + 练习 + 日子」**。
悟性没有变成学习成功率。

### 「照着做」和「走岔了」，写的是同一段话

上一章那条纪律（「明白」这一关成败同文）在这里又用了一次，而且更狠：
不是同一关的成败共用一段话，是**两个完全不同的状态**共用一段话。

```text
你照着那五句做了一遍。
气进来，往下走，数三下，放出去。你做得一点不差。
坐到腿麻了才起来。胸口有点发闷，你想大概是坐久了。
```

方向对但还没碰着的人，和方向根本错了的人，看见的是同一件事。
往后每一夜也一样：「还是那样。做得越认真，胸口那股闷越明显。」

`scripts/mastery.ts` 逐字比对这两格，不一样就红。

### 走岔了只有一条出路，而他不知道自己走出来过

出路只有一条：**你自己把那五句想明白。** 那五句既是让他走岔的原因，
也是他唯一能走出来的凭据——而多数人读不懂那张地图。

```text
第一夜：没上手 → 走岔了　（脑子里 听过 → 记住）
第二夜：走岔了 → 照着做　（脑子里 记住 → 明白）
```

注意第二夜落在「照着做」，不是「摸着了」——**走出来不等于走到了**，
他回到起点，重走一遍。而这两夜他读到的正文一字不差。

两条轴全书只在一处交叉，就在这里（`graspTries`）：走岔的人天天在做一件错事，
那件错事天天给他一个「我这不是做得挺对的吗」的回音，
于是**他在错路上练八十回，对于想明白那五句，等于一回也没练**
（实测：在岔上练 80 回仍停在「记住」；同一个人不在岔上，练 2 回就到「明白」）。

而这一处交叉只归「明白」那一关。**背五句照样背得下来**——
门禁里站着一个记性只有 26 的孩子，从第一夜起就在岔上，
那五句照样背了下来。背诵跟你坐得对不对没有关系。

### 练得多没用，练得久才有用

最后那一关（`steadying`）是 `helps: 0` 加一个 `settles: 540`：

```text
一口气练 60 回，一天也没让它过去　　身上「摸着了」——有时候有，有时候没有
让 540 天过去，再坐一回　　　　　　 身上「拿得住」
```

一个月里练二十回，和两年里练二十回，不是一回事。
所以 `settles` 挂在 `Rite` 上而不是塞进 `Gate`——前三关都不看日子，只有这一关看。

### 走完全程，什么也没多

属性表一格没动，境界还是「凡人」，身份还是「孩童」，一件东西也没拿到。
他多出来的只有一样：那条见闻的理解档从「未理解」改成了「确信」。

**而「确信」只是他自己的笃定，不是世界盖的章。** 走岔的那个练了八十回，
那条见闻上一辈子写着「未理解」——认知层老老实实记着他没懂，
**而他自己完全不知道**。

落进见闻里的那一条也看不出他走的是哪条路：里面没有「走岔」两个字，
也没有 `hold` 这个字段。

### `scripts/mastery.ts`：七道判据

| #   | 验的是                                               |
| --- | ---------------------------------------------------- |
| 一  | 四种组合：脑子里和身上真的各走各的，四种都跑得出来   |
| 二  | 换个教法：同一个孩子同一个师父，教法一改，命就不同   |
| 三  | 反例：悟性更高的那个学不会，悟性平常的那个学会了     |
| 四  | 看不见：「照着做」和「走岔了」，玩家读到的是同一段话 |
| 五  | 出路：走岔了只有一条出路，而他不知道自己走出来过     |
| 六  | 日子：练得多没用，练得久才有用                       |
| 七  | 什么也没多：属性一格没动；他只是确信自己懂了那五句   |

两把尺子自检站在最前面，改坏了必须当场红：

```text
把 QUIET_BREATH.asks 改成「说给你听」　那个在岔上练了二十回的孩子必须当场学会
把 QUIET_BREATH.settles 改成 0　　　　 那个练了六十回的孩子必须当场「拿得住」
```

原样：前者从头到尾在岔上（记住/走岔了），改完是明白/摸着了；
后者练六十回也只是「摸着了」，改完就「拿得住」。
挡住他们的确实是那两样东西，不是分数配歪了。

### `MasteryStage` 长成了两个类型，而不是一条阶梯

这一章原本准备设计的那个东西，叫 `MasteryStage`。一开始最顺手的写法是
`heard / seen / understood / practiced / mastered` 五档一条阶梯——
而让一门具体功法先跑一遍之后，它长成的是两个正交的类型
（`Grasp` 三格、`Hold` 五格带一个分叉），中间只交叉一次。

那条阶梯里的 `practiced` 和 `mastered` 在这儿根本不是同一条轴上的东西，
而「走岔了」这一格在那条阶梯里**压根没有位置**。

### 这一章没验到的

- **「聋子听不见那五句，瞎子看不见他的动作」**——`Constitution` 里有这两样，
  而 `handsKnow()` 一点也不看它们。这是有意留的缺口：把它们塞进那个函数，
  等于绕过「他听不见那句话」这个更要紧的问题，反倒去领一份好处。
- **「没人教、自己瞎坐的人不会走岔」**——`goesAstray` 第一条就是它，
  可这条路此刻跑不出来：`practise` 要 `grasp` 非空，而只有 `teach` 会写它。
  手动往旗标里塞一个「没人教却在练」的人是伪造状态，验不了真东西。
- **「能持续，但效果很弱」那一档没做**——它要「修炼产出」，一做就滑向完整功法系统，
  而这一章的范围是一门功法、一个师父、一次教学。
- **「以后可能忘掉」没做**——那是另一个状态问题，不提前造。

还有一件是内容层的老实话：「拿得住」在这一册里多半走不到。
`settles` 要一年半，而那个事件的窗口只有十四到十六岁，每来一回推二十天。
不为这个把窗口拉长——**成年之后那一段人生还没写**，
拉长了就是往一个不存在的年纪里塞事。

## 时间是唯一真正稀缺的东西

年龄不是点「下一年」加上去的，它就是时序本身（`age = year - 1`）。
时间随人生行为推进：读书消耗数月，赶一趟远路十几日，生一场病过去半个月，
在私塾念一年就是一年。选项右侧常驻「耗 一年」「耗 半月」——**账要在落笔之前就看见。**

## 机缘不是幸运抽奖

> 机会出现在你面前，但你是否能够发现、理解、抓住它，是另外一回事。

山道上躺着一个人。他是猎户、江湖武人、宗门弟子、修士、邪修，还是已经死了——
在你抬头之前，`roll` 就已经把它掷定并写进旗标了。你的选择改变的是自己撞上什么，
**不是把他变成对你有利的那一种。** 玩家永远看不到这一掷。

而心思不够细、也不常在山里走的人，正文里根本不会提有人躺着。他这一生都不会知道错过了什么。

### 五个可以断的节点

这一场不是「注意 → 选择 → 既定结果」，是五节，每一节都断得掉：

```text
注意 → 理解 → 兴趣 → 行动 → 世界回应
```

#### 注意那一节从前是一行阈值，而它量出来是个满格

```ts
insight >= 34 || body >= 52 // → 看见了
```

读起来像「机会摆在面前，看不看得见是另一回事」，实测三百世里
**三百个人全都看见了**。十一种出身里只有农户两项都够不着，
可童年那些事——下地、跟车、认药——到十岁之前就把属性推过了线。
这一关被童年系统提前替他解决了。

**一个满格的过关率读起来像「这一关很宽」，其实是「这一关不存在」。**

修法不是把线抬高。抬高只换来另一句话：聪明孩子看见，笨孩子看不见——
那是能力检测，不是人生。要问的不是他聪不聪明，是

> **当时的他，有没有把注意力放在那里。**

这两件事不一样。心思很细的孩子，在挨过一顿骂、满脑子想着家里那个
还没退烧的人的下午，一样什么也看不见；而笨手笨脚的猎户家孩子，
在他走了十几年的那条山路上，眼角一扫就知道草丛被压过。

所以 `attend()` 的分数由三样合起来定，`insight` 只占一份，而且不设阈值：

```text
心思细不细　+　那天他心里装着什么　+　路上是什么天
```

后两样全都来自他这一生真发生过的事：家里有人病着（−11）、欠着账（−6）、
走了大半日（−6）、下雨或起风（−8）、常年在山里走（+10）、
上回也走过这么一段（+8）、心里正想弄明白些什么（+6）。
**每一条都指名道姓说得出为什么，没有一条是「运气不好」。**

于是「没看见」不再是一格，是三格——它们在人生意义上完全不同：

| 落点                  | 他那天                           | 400 世 |
| --------------------- | -------------------------------- | ------ |
| `unseen`              | 没有注意到                       | 约 24% |
| `noticed-but-ignored` | 看见了，但没放在心上             | 约 22% |
| `misread`             | 看见了，理解成另一回事，绕开走了 | 约 11% |
| `interest`            | 停了下来，于是有得选             | 约 43% |

而最要紧的一节是**同一个人不同的一天**——属性一分不差，只换当天状态：

```text
十岁那年　　刚挨过骂，心里想着家里，起着风　　看进去 10%　瞥一眼 22%　没看见 68%
十五岁那年　一个人在山里走惯了，晴天　　　　　看进去 75%　瞥一眼 20%　没看见  5%
```

**「错过机缘」于是成了人生的一部分，而不是属性不足。**

那件压着他的事会印进正文，**三条路上都印**。所以哪怕他什么也没看见，
读到的也不是一片空白，而是「你心里想着家里那个人」——
他知道自己那天心不在焉，只是永远不会知道自己错过了什么。

> 这一层的代价是明知故犯的：它把「这辈子拿到过那册书」从 8.3% 压到 3.9%，
> 「多年以后有人点破」从 2.7% 压到 1.8%。那一关从前不存在，
> 而「机会摆在面前，看不看得见是另一回事」这句话，得有人真的看不见才算数。
> 分布归 `scripts/attention.ts`，漏斗归 `scripts/probe.ts`（一千二百世）。

**理解那一节可以错，而且错得讲得通。** `glance()` 不是随机发错答案——
判断从见识里长出来：见过血的人读成「伤了」，镇上长大的孩子读成「喝多了」，
心思细的人看出「他衣裳料子太好，腰上挂的东西没见过式样」。
读出「不对劲」不需要听说过修士——**「不对劲」和「那是修士」是两回事**，
听说过只是让这条路更好走。

**兴趣那一节由玩家自己决定，引擎不掷。** 没有悟性检定，没有气运加成。
四个选项摆在那里：扶起来、走近看看、跑回村里叫人、不关自己的事。

**世界回应那一节刻意不看 `fortune`。** 用气运决定机缘成不成，机缘就还是抽奖。
`resolve()` 看的是这个动作、这个人伤得多沉、你这具身子骨、你花了多少时间。
于是会出现：body 70 的人扶不动一个修士——那件事根本不取决于力气；
而「跑回村里叫人」是最稳的一条路，却要走大半天，等你带人回来，
能走的都已经走了。**每条路都有它自己会输的地方。**

`scripts/wounded.ts` 拿这六种人生当验收（4000 次）：

| 人生                               | 占比   | 它证明的事         |
| ---------------------------------- | ------ | ------------------ |
| A 判断对 → 行动 → 成功             | 约 15% | 机缘抓得住         |
| B 判断错 → 行动 → 才发现自己错了   | 约 40% | **理解可以错**     |
| C 判断错 → 没兴趣 → 一生不知道真相 | 约 21% | **机会不等于命运** |
| D 判断对 → 行动 → 但没做成         | 约 5%  | **行动不保证结果** |
| E 判断对 → 没兴趣 → 走开           | 约 9%  | 看穿了也可以不管   |
| F 判断错 → 行动 → 回应完全超出预期 | 约 9%  | 世界不按你的剧本走 |

这张表从前写的是「300 次」和一串小数——**那个精度不存在**。
D 占五个点，三百次里十一二个人，连跑三批报 3.3 / 5.0 / 5.7。
四千次跑完七秒，换来的是这张表说的话跟它印出来的位数对得上。

同一支走查还钉着两条铁律：把 body 和 will 按住只让气运变，
气运 20 / 50 / 80 三档的成功率**差 0 个百分点**；
而 body 30 → 70 对猎户、武人、弟子都是 0% → 100%，对修士始终 100%——
**力气有用，但不是对所有人都有用，而玩家做决定时并不知道躺着的是谁。**

> 头一版按气运分桶跑，差了 20 个百分点，看着像气运在插手。
> 其实是混杂：`fortune` 和 `body` 都来自出身，气运低的多是农户猎户，
> 而他们身板硬朗扶得动人。量的根本不是气运。**走查本身也会说谎。**

真相与认知分开写进存档（`wounded-man` 是世界事实，`wounded-reading` 是玩家认知），
所以多年以后可以有一次「原来那天遇见的是修士」——
**而如果你一辈子没走过去，这一句就永远不会出现。** 你到死都以为那是个醉汉。

## 多年以后才明白当年发生过什么

山道那一场的误读，伸手就被戳破：你以为是醉汉，他睁开眼，你当场知道自己错了。
庙前货郎那一册书走的是**相反的路**——

```text
看见书 → 判断这是什么 → 是否在意 → 是否取得 → 揣十年 → 后来重新理解
```

### 抓住机会 ≠ 当场获得答案

你翻了两页，心里有了个判断。那判断从你的见识里长出来，
而**出身直接决定它的形状**：同一册符书，走查里——

| 谁                   | 他看见的是                                       |
| -------------------- | ------------------------------------------------ |
| 药铺的孩子           | 药方 34%　废纸 18%　值钱的 15%　古怪的字 15%     |
| 商户的孩子           | 账册 32%　废纸 20%　古怪的字 18%　值钱的 14%     |
| 农家的孩子（认字）   | 古怪的字 23%　废纸 23%　账册 17%　值钱的 16%     |
| 农家的孩子（不认字） | 废纸 45%　值钱的 35%　不该看的 21%               |
| 心思很细的孩子       | 古怪的字 36%　不该看的 19%　值钱的 14%　账册 14% |

药铺的孩子从小认药，看见手抄本第一反应是方子；成天见账的人家，一行一行的就是账；
不认字的人根本走不到「这些字很怪」那一层——**他这一生都不会知道自己错过了什么。**

然后你决定要不要在意。`interest` 那一节的四个选项**一个条件也不带**：
把它当废纸的人照样可以买下，看出「不该声张」的人照样可以怕惹事走开。
兴趣是玩家的事，引擎在这里不掷骰、不做判定（这一条做成了走查里的静态检查）。

### 错误会跟着你走十年

买下之后，行囊里那件东西用的是**你自己给的名字**，不是它真正的名字。
往后每隔一阵拿出来翻一次，一次也没看懂，于是最初那个判断一年比一年结实：

```text
〔猜想〕像是哪家铺子的旧账本。      ← 十岁那年
〔确信〕就是哪家铺子的旧账本。      ← 揣了几年之后
```

**这一步只加固，不修正。** 引擎在这里只升 `grasp`，`mistaken` 一个字不碰——
他更确信了，但他没有更接近真相。直到哪一年江上有人扫了一眼：

- 山道上那个濒死的人塞给你的那册 → 「炼气法门。」
- 庙前几文钱买的那册 → 掷出来的六种真相各说一句：
  「符书。写坏的。」／「账。北边的号，早没了。」／「方子。抄漏了。」／
  「废纸。谁家的旧簿子。」／「收起来。别叫人看见。」／「……哪来的。」

六种收梢的余味完全不同：写坏的符书是白揣了几年，残卷是从此有了一件要追下去的事，
禁书是背上了一样甩不掉的东西。`reveal` 改名时把旧名字留在 `formerName` 里不删——
**那些年是真的，不该被新知识抹掉。**

### 走查（`scripts/book.ts`，2000 次）

买下并揣着的人里 **七到九成揣的是一个错的理解**（六种真相各不相同，
最容易读错的是药方 88%，最不容易的是残卷 70%）；其中约六成在渡口那天被纠正，
其余的带着它走完了这一卷。一共长出 **13 种不同的认知历史**：

```text
24.3%  走开了，一生不知道
11.8%  揣了多年，后来知道那是废纸
10.0%  揣了多年，后来知道那是符书
 7.8%  揣了多年，后来知道那是账册
 6.3%  揣了一辈子，始终以为是「上面的字笔画清楚」
 ……
```

这张表从前标着「300 次」。三百次下表尾那几行是二十来个人，
σ 一个半百分点，而它写到了小数位——**这一支跑两千次要六秒，
跑三百次要五秒**：省下的那一秒买不到任何东西，赔进去的是这张表说话的资格。

#### 那个「六成」不是玩家会看到的六成

这一支是把人**送到渡口上**去量的：它要问的是「一个错的理解揣得住也醒得来吗」，
所以它得先保证有人站在那儿。而真实人生里碰上修行是三个点上下的事
（`scripts/simulate.ts`），绝大多数人**这辈子没有那一天**——
他们买下的那册书，直到咽气都还叫着自己给的名字。

「构造走查量出来的比例，不是玩家会看到的比例」这件事在这一支上无害，
因为它问的本来就不是频率。可同一支脚本要是拿这个六成去说
「大多数误解最终会被纠正」，那就是拿一把为别的事校准过的尺子去量频率。

还有一条：**问错了问题，会把你领到别处去。** 你以为那是账册，
就会去问「这是哪家铺子的账」——货郎说他不识字，倒说出这叠纸是从西头
一户破屋里收的，那家男人是外路来的。你没问出书的来历，问出了一户人家。

## 认知有三根轴，不是一道坡

「知道」从前是一道单一的坡：听说 → 见过 → 猜想 → 确信 → 亲历。
可那道梯子**混了两个不同的轴**——听说、见过、亲历说的是他跟这件事离得多近；
猜想、确信说的是他形成了什么样的解释。两者根本不在一条线上。

最直接的证据：一个亲眼看见修士踩水而过的孩子，在老梯子上的档位
竟然比一个坐在家里瞎猜的人还低。而他真实的状态是——**离得最近，却什么也没弄明白。**

拆开之后是三根各自独立的轴：

```text
接触　听说 → 见过 → 亲历　　只能往上
解释　未理解 → 猜想 → 确信　可以往下
对错　对 / 错　　　　　　　　跟前两根都正交
```

一正一反两条规则，缺一不可：

- **接触只能往上。** 听人说一嘴，推翻不了亲眼见过。
- **解释可以往下。** 一句「不是那么回事」就能让一个确信多年的人重新不敢肯定。

九格乘对错十八种，**全部合法**：

| 　       | 未理解                       | 猜想    | 确信        |
| -------- | ---------------------------- | ------- | ----------- |
| **听说** | 只听过这个名字               | 对 / 错 | 对 / 错     |
| **见过** | **他看见了，可他不明白**     | 对 / 错 | 对 / 错     |
| **亲历** | 他就在场，至今说不出那是什么 | 对 / 错 | **对 / 错** |

「亲历」不是真相保票——世上最难劝的正是那种「我亲眼见过」的人。

### 被人说动之后有三种样子

只做「纠正」的话，NPC 一开口玩家的世界模型就被改对，那还是百科系统。
现实里的认知变化至少有三种，而且对玩家的体验完全不同：

```text
① 动摇　　　　「你这么一说……我也不敢肯定了。」
              解释退一档，说法一个字没改，错也还是错的。

② 有了别的说法「也可能不是修士，是某种江湖把式。」
              新说法跟原说法并排放着，不覆盖。他从此心里有两个版本。

③ 明确纠正　　「原来那天见到的确实是修士。」
              只有这一步才抹掉错误标记。
```

### 认知历史本身就是内容

每一次变化都往 `history` 里追加一条，旧的绝不删：

```text
〔初识〕　　　　听说 · 确信　　修士就是江湖上很厉害的人。
〔有了别的说法〕听说 · 猜想　　修士就是江湖上很厉害的人。
                              另有一说：走北路的商旅说，他们不是江湖人。
〔加深〕　　　　听说 · 确信　　修士是另一种江湖人吧。
```

注意最后那一步：**他采信了商旅的话，却把它塞回了自己原来那个框里。**
一条一路被改到「对」的知识条目，跟一个人真实的理解过程毫无关系。

### 拆分时揪出的两个真 bug

都是「档位越高越接近真相」这条隐含规则的产物：

- **升档会静默抹掉 `mistaken`。** 于是「更确信自己那个错的」在引擎里做不到——
  而那恰恰是人最常干的事。
- **同档位的纠正进不来。** 他确信那是账册，有人当面告诉他那是符书，
  引擎当成「已经知道了」，脑子里那条纹丝不动。

现在「他变得更确信了」和「他终于弄明白了」是两次不同的调用：
不传 `mistaken` 就不动对错，传 `null` 才是明确纠正。
整套钉在 `scripts/grasp.ts` 里，失败非零退出。

## 一个人的理解，是另一个人的局部世界

前两支机缘验的是玩家跟**世界**打交道。山道上躺着的虽然是个人，
可对玩家而言他跟一册书没有区别：不会争辩，不会含糊其辞，不会自己就理解错了。

走北路那个商旅不一样。他会来很多次，会记得你，也会老。
而最要紧的是——**他对世界的理解，可能本身就是错的，而他不知道。**

### 从世界真相到玩家脑子里那句话，隔着三道关口

```text
世界真相
  ↓  ① 商旅自己怎么理解的（他可能就错了，而他不知道）
他心里那句
  ↓  ② 他肯说多少、说得多明白（他多半说得很含糊）
他嘴里那句
  ↓  ③ 玩家怎么听的（他会往自己已有的框里塞）
玩家脑子里那句
```

于是有了这一支最要紧的一种结果：**他说的是真话，玩家还是理解错了。**

```text
玩家确信：修士就是江湖上很厉害的人。
商旅想说：不是江湖人。
他只说了：不是一路人。
玩家听成：哦，那就是不同门派的意思吧。
```

没有人撒谎，没有人失误，而玩家的世界模型**更自信了，也更错了**。

### 一个 NPC 的四种状态

| 状态                 | 他说的那句                             |
| -------------------- | -------------------------------------- |
| 知道但今天不想说     | 走远道的事，说了你也不懂。             |
| 真不知道             | 我走了半辈子北路，没撞见过。           |
| 知道且愿意说         | 有一年在渡口，我见过一个人……           |
| **自己错了而不自知** | 北边有个姓卓的，一个人挡过十几号马贼。 |

最后一种最要紧：**他说得最生动**——有名有姓，有地方有年份，
比那个真见过修士的人讲得还实在。他不是骗子，他只是把见过的东西归错了类。

### 越笃定越听不进去

同一个亲眼见过修士的商旅，同一句「不是一路人」：

| 心思 | 他还在猜的时候   | 他已经确信的时候               |
| ---- | ---------------- | ------------------------------ |
| 45   | 有了别的说法 71% | **加深 81%**（更确信那个错的） |
| 60   | 弄明白了 100%    | 有了别的说法 75%　弄明白了 16% |
| 75   | 弄明白了 100%    | 弄明白了 89%                   |

心思 60 的人，只因为原来已经确信，听懂的比例从 100% 掉到 16%。
**这一条才是「越问越错」真正的发条。**

### 关键指标：多谈几次，他离真相更近了吗

三夜谈下来（`scripts/merchant.ts`，2000 次）：

| 结局     | 占比   |
| -------- | ------ |
| **更错** | 约 28% |
| 更对     | 约 27% |
| 没变     | 约 24% |
| 一无所获 | 约 21% |

```text
更错：〔猜想〕修士就是江湖上很厉害的那种人。
     → 〔确信〕修士就是江湖上很厉害的那种人。
```

**更错比更对还多。** 这一条是这支机缘真正要证明的东西：
认知不是越问越对的，而 `mistaken` 也就此从一次剧情判定
变成了人物认知系统的一部分。

> 上表是跑四千次量的。**这个结论比它看上去脆弱**——更错只比更对多 2.2 个点，
> 而走查日常只跑三百次，那个量级下两者会来回翻转。
> 所以走查的门禁押的不是「更错多于更对」，而是「两种都得跑得出来」：
> 一个都没有，才说明多问几次必然更接近真相。
> **门禁要的世数，和一句结论要的世数，本来就不是一回事。**

## 三层信息结构

界面把「玩家知道什么」分成三层，各有各的位置，互不越界：

| 层       | 位置                          | 内容                                     |
| -------- | ----------------------------- | ---------------------------------------- |
| 当前经历 | 中段正文                      | 地点、时间、叙事、对话、行为、结果       |
| 当前状态 | 状态栏 + 人物面板             | 姓名、年龄、所在、身份、家世、他人之言   |
| 世界认知 | 知识 / 人际 / 编年 / 世界面板 | 你听说过什么、见过谁、经历过什么、到过哪 |

## 核心机制：玩家知道什么 ≠ 世界真实存在什么

引擎内部确实有 `Attributes`（根骨、悟性、体魄、心性、气运，0–100），
家境有 `standing` / `debt`，关系有好感度。**但界面永远不显示它们，一个都不显示。**

十六岁的少年凭什么知道自己的「悟性」是多少？他只能知道别人对他说过什么。
一个孩子对家境的全部认识，也只是饭桌上有没有肉——所以人物面板上写的是
「不宽裕，但过得去」，不是「家产 43」。

于是人物面板显示的是 `Aspect`：

```ts
interface Aspect {
  self: string | null // 你自己的认识。多数时候是 null
  claims: AspectClaim[] // 别人说过的话，只增不改，各带时间戳
}
```

先生说「你这孩子，记性比旁人好些」，这句话就永久留在「学识」一栏下，
底下跟一行楷体的疑问：「你不知道这算不算一句夸奖。」

多年以后宗门若说「这种资质……也只能算中下」，那句话会**并列追加**在旁边，
而不是覆盖前一句。玩家自己去发现，当初那个「不错」根本不是自己理解的意思。

为了让数值没有办法再爬回界面，`src/engine/describe.ts` 里
物理删除了 `ATTRIBUTE_LABELS` / `ATTRIBUTE_ORDER` / `describeLevel` —— 没有渲染函数，就渲染不出来。

## 先生说的「聪明」，和修士说的「悟性」不是一回事

评价不是写死的台词，是**算出来的**。链条上每一步都可能失真：

```text
真实属性 → 观察能力 → 观察结果 → 语言表达 → 玩家理解
```

关键在于**一把尺子量的东西不等于任何单个属性**。先生量的「读书快慢」里
记性占七成，修士说的「悟性」才是单独那一样。于是同一个人：

| 谁           | 他说什么                      |
| ------------ | ----------------------------- |
| 周先生       | 记性比旁人好些 / 读书倒是不慢 |
| 坐堂的郎中   | 底子还算不错                  |
| 走镖的把式   | 身子骨还行                    |
| 一名炼气修士 | 悟性一般 / 神魂尚可           |
| 一名筑基修士 | 资质倒是不错 / 悟性不高       |
| 宗门长老     | 资质不错 / 悟性普通           |

六个人都没说谎，量的是不同的东西。

再叠一层判断力（`acuity`）：它不是随机乱猜，而是**往中间拉**——
判断力低的人看不出天才也看不出废物，这正是外行的样子。
走查里炼气修士（判断力 52）看同一个悟性 48 的人一百次，说过三种话：
「一般」53 次、「尚可」33 次、「差了些」14 次。
**他有三分之一概率看走眼，而玩家永远不会知道。**

### 一条铁律：评价不写回属性

修士说「悟性一般」，`insight` 一分不动。评价也永不作为任何 `Condition` 的判据。

那「别人怎么看你」还能影响人生吗？能——**但只经玩家的手，不经引擎的手**：
修士说「资质一般，别浪费时间」，玩家因此放弃，这是真实的人生影响，要它发生。
但那条路始终开着，他可以不信、可以再找人看。

> 世界不因评价而改变，玩家因评价而改变。

## 人是人，不是事件触发器

「父亲」不是插在家庭位置上的一块牌子，是沈怀山这个人——
有名有姓、有年纪、有脾气，比玩家早出生二十几年，
而且**玩家不在场的时候他照样活着**。

父亲离家做工不是 `father = dead`，是这个人换了地方谋生
（`{ place: 邻县·河堤工地, doing: 修河堤的工 }`）。他在那儿老去、生病。
走查里 171 个「父亲离过家」的人生，**0 个父亲从世界上消失**。

那 171 个是这一轮才凑齐的。从前的判据是 `hasFlag('father-away')`，
可 `hasFlag` 的语义是「存在且不为 false」，而**父亲回来那一卷会把这面旗子按回
`false`**——于是「他几年后回来了」的那六成人生，在铁律眼里等于从没离过家。
真被查的只剩死在外面和杳无音信的两档，而那两档本来就会写进册子，
**最不需要担心的恰恰是唯一被查的**。改用他走出村口那一刻必掷的 `father-fate`
之后，归、亡、杳三个出口一个不漏，样本从 27 个涨到 171 个。

关系是**边**不是槽位。做成 `fatherId / guardianId` 的话，
「姐姐当了家」没处放——她既是姐又是抚养人，一个槽装不下两样。
做成边就全免费，而且玩家自己也只是图里的一个节点（`me`），
所以「成年后自己成家」不需要任何新机制。

断了的边不删，只封口：**老乞丐养过你这件事，不因为他死了就没发生过。**

十种出生境况：父母健在 / 有兄姐 / 母亲难产而亡 / 父亲早亡 /
与长姐相依为命 / 跟着兄长 / 叔父收养 / 庙门口的弃儿 /
老乞丐捡回来的 / 战乱失散。弃儿的生父生母不是「未知」这个值，
是那两条边**根本不存在**——跟「爹死了」是完全不同的两件事。

## 体质不是 debuff，是人生的形状

跛脚的孩子下不了地、走不了山道，可他常年在屋里，摸到书的机会比谁都多
（`body -26`，但 `memory +10 / insight +6 / will +10`）。
没有一种体质是净减的。

而 `root`（修行资质）与 `spirit`（神魂）一律不碰——
**一个瞎子可能是天生的修行胚子。**

这也是「哪个开局最强」的堵法：不给苦出身发补偿，
而是让决定你能走多远的那样东西跟出生境况完全无关。
走查里有血亲的人 `root` 中位 51，一个血亲也没有的中位 50——差 1 分。

## 选择的三种状态

| 状态 | 写法                                  | 表现                                                        |
| ---- | ------------------------------------- | ----------------------------------------------------------- |
| 可用 | 无 `requires`，或条件已满足           | 墨色，`○` 前缀，可点                                        |
| 锁定 | `requires` 不满足 + 写了 `lockedHint` | 淡墨，`aria-disabled`，右侧灰字写明「三枚铜钱换不来一句话」 |
| 隐去 | `requires` 不满足 + 没写 `lockedHint` | 整条不渲染                                                  |

写不写 `lockedHint` 是设计决策：**够不到但该让人看见的门**要写，
**看见就等于剧透的路**不写。渡口那一卷里，「你想起有人跟你说过这样的船」
对没听过修士的人整条隐去——他连这里有一条路都不该看见。

锁定项用 `aria-disabled` 而不是 `disabled`，键盘用户仍然能聚焦读到提示。

## 走查

门禁只能证明代码编译得过，证明不了「一生走得通」。`scripts/simulate.ts`
把引擎当纯函数用，随机替玩家落笔跑一千世。当前数字：

| 观察项                     | 值                                        |
| -------------------------- | ----------------------------------------- |
| 走到卷终（不卡死、不空转） | 100%                                      |
| 进过私塾                   | 八成半上下（农户约七成，城里人家近 100%） |
| 咽气的岁数                 | 四十出头到八十，中位六十出头              |
| 父债链走到父亲死           | 四个点上下                                |
| 认出了修士                 | 三个点上下                                |
| 身上有东西被人点破         | 两三个点                                  |

### 底下两行从前是「约 16%」，而且写着「收尾年龄 16–17」

那不是抽样在晃，是**同一个机制被拆掉了**。旧结构里渡口是 `lifeFinale`，
权重 1000、窗口封到 99 岁——十六岁之后年表一次也抽不空，**人人必到渡口**，
于是「认出修士」和「东西被点破」这两格量的其实是「你带没带着东西去」。

现在渡口跟别的事一样去争年表，还多了一道 `fortune` 门槛：一辈子没出过村的人
过不了那道坎。走到那条江上的是一成上下（`scripts/lifelong.ts`），
而这张表里的三个点是**走到了并且看懂了眼前是什么**——
两个数之差正是那些站在江边、什么也没认出来的人。

同一件事把「收尾年龄」那一行整个废掉了：人生不再由十六岁那道检测收尾，
每个人都活到自己的天年。

一千世要跑将近两分钟，是全套里最慢的一支。慢有慢的道理：
它是唯一一支真把一辈子走完的，而世数不是拍脑袋定的，
是照最稀那一格——**「身上有东西被点破」只占两三个点，两百世里是五六个人，
量出来的小数位纯属虚张声势**。

这几个数是调出来的，不是碰巧。下面每一条都是只有跑起来才暴露的问题
（这份名单只会加长，所以开头不写「三处」——它已经错过一次了）：

- 最初一版里农户七岁时家境中位数只有 19，够不到私塾门槛——
  **占人口一半的农家子在出生时就被结构性地关死了读书这条路**。
  补上「好年景」这一卷之后中位数回到 45。
- **而那一手补过头了，过了很久才看出来。** 中位数回到 45 之后，
  `scripts/origins.ts` 印出来的是十一种出身读过书全是 100%——
  一个连赤贫都不存在的世界。于是「供不起」那一节（`school:threshold#cannot`
  和它底下两条岔路）**写在库里，一千世无人读到，而它看起来跟活的一模一样**。
  病根不在家境的数上，在**次序**上：欠债那条链从前从七岁起步，
  跟入学同岁，压下去的那几分永远赶不上那道门。把它提到五岁，
  农户那一行掉到六成六，那一节第一次有人读到（详见 `content/life/chapters.ts`
  的 `hardship` 一章）。
- 加完宗室，加压走查发现**一个被削爵的王爷会掉进农户剧本**——
  「父亲每天傍晚去地里站一会儿」，可他家没有地。
  父债链的入场条件原本只看家境不看出身，破产的商户、官宦一样会掉进去。
  现在这条链限定农户，别的出身破落下去该有别的样子。
- 宗室的坠落原本 100% 发生，等于剧本而非命运。
  改成七岁开蒙那天掷一次「court-fate」，四成会塌，六成不会。
- 改 `omen:wounded` 时删掉六个旧结局节点，连带删掉了挂在上面的 `thin-book`
  和 `touched-by-wicked`。前三道门禁都查不出来——边是通的，断的是前置条件。
  现在这类东西由结算函数携带（`Outcome.grants` / `Outcome.marks`），
  不再散落在场景数据里，第四道门禁盯着它。

**总量走查看不出这些。** 王府在一千世里只掷出二十来次，
所以 `scripts/royal.ts` 绕开权重把出身钉死，各跑三百世。

### 走查会撒的几种谎

它跑出来的数字有小数点，看上去就像真的。这些是真栽过的：

**一、量的是另一个变量。** 机缘那一支按气运分桶跑，成功率差了 20 个百分点，
看着像气运在插手机缘。实际是 `fortune` 和 `body` 都来自出身，
气运低的多是农户猎户，而他们身板硬朗扶得动人。把 body 按住只让气运变，差距降到 0。

**二、把材料判成了结果。** 「听着几件事」被算作找到线索，于是 A 有 6%。
可那些人哪儿也没去过——**材料不是结果**。改判之后 A 掉到 1.1%。

**三、变量偷偷相关了。** 「他问了几年」和「他到门前进不进」都从循环下标 `i`
派生，于是问得少的人恰好也是不进门的那一批，D 那一格永远是空的。
**走查里的每个变量必须各掷各的。**

**四、孤儿分母。** 一次批量下调世数，改了循环上界却漏了十一处写死的分母——
除以 2000，实际只跑了 300。数字照样打印，只是全错。
**凡是从常量推算出来的数，都得跟着那个常量自己走，一处也不许抄。**
同类的还有：走查里写 `peakOf('leave') >= 15`，把门槛的值抄了一份，
门槛后来提到 18，这一行就跟别处对不上，报出「1500 世里没有一个人动过念头」。

**五、读的是文字，不是方向。** 反向火种把念头压下去时往往顶上来另一个，
而引擎给这两笔用的是**同一个 moment 对象**——于是被顶上来的那个念头，
它的记录里也留着同一段话。走查只比对文字，就报出「『你想把日子过安稳』
被压过 80.9%」，可反向火种里压根没有一条压它的。
**那个数字是把「因为它被顶上来」整个读成了「它被压下去」。**

**六、把样本量砍成了报出来的尺度。** 「没有人会玩八千世」这句话是对的，
可它说的是**报什么**，不是**量多少**。`seeking.ts` 一并把世数从八千砍到四百，
理由是「四百世够看清形状了」——不够。A、D、E 各占一个点上下，
四百世里各是四五个人，抽多抽少差出一倍，于是「玩十世能见到 A 一次」
连跑两批，一次报 5%，一次报 14%。**砍样本量毁掉的，
恰恰是那张要给玩家看的表。** 换算到玩家尺度，和把数量准，是两件事。

**七、规矩写在文档里，然后文档自己犯了它。** 上面那句「总量走查看不出这些，
王府一千世里只掷出二十来次」是这份 README 自己写的。可往上翻二十行，
「皇子知道有修士的比例是全表最低的」——**那句话读的正是总量走查里
皇室那一行，n=6**。真跑 `royal.ts` 把出身钉死三百世，是 26%：
比农户的 16%、药铺的 21% 都高。写规矩的和引数字的隔着二十行，
就已经互相不认识了。**文档里的断言和代码里的断言一样会烂，
而它没有门禁。**（这一条现在也还是没有门禁，只能靠每轮回头核。）

**八、满格的过关率，读起来像「这一关很宽」。** 山道那支漏斗有三格常年印着
100%，看上去是「这几关不筛人」。翻开来是两回事：

```text
saw-wounded-man / fled-wounded-man / saved-a-man   源码里一面旗子也没有
insight >= 34 || body >= 52                        三百世三百个人全都过
```

前者是判据认错了东西——「看见了人」实际量的是「被邪修抓过」，七个人，
而下一格「拿到书」是十六个，**过关率印出来 229%**。
一个漏斗报出后一关比前一关宽，这本身就是它坏了的证据，
可它印了很多遍，因为**那一支从前一道门禁也没有**。

后者更难看见，因为它印出来的数字是对的：那一行阈值确实人人都过。
可它宣称自己在问「机会摆在面前，看不看得见是另一回事」——
**而一个从不筛人的关卡，和一个不存在的关卡，印出来一模一样。**

于是多了两条规矩：漏斗必须自己查「后一关不许宽过前一关」，
以及**任何一格印出 0% 或 100%，都要当成它可能根本没在量东西**。

### 世数按最稀的那一格定

「跑几世」这个数不是越大越好——它是从最里头那一层反推出来的。

`leaving.ts` 统计的是条件概率，分母是「动过『想离开』这个念头的人生」。
照总世数拍必然出错，可照合格样本拍也不够：一千五百世里合格的九十九世，
而「真的走出去过」只占这九十九世的 5%——**五个人**。
若照「三十个合格样本就够了」去拍，四百世筛出三十几个，最稀那一格期望不到一，
一多半的批次里它根本不出现，走查于是报「这几种人生跑不出来」，
看上去像是功能坏了。

**三个数一层套一层——总世数 → 合格样本 → 最稀那一格。拍板要拍在最里头那一层。**

而当最稀那一格稀到加世数也不划算时（这一支已经是全套里最慢的），
该回头问这一格在测什么。A（走了）和 D（走了又回来）是同一条路上的两种后续，
门禁于是改成问路通不通：**走出去过的人必须存在。**
A 与 D 各自的比例照报不误，只是不再拿它们卡门禁——
**报出来的数字和守住的底线，本来就不必是同一个。**

> 另有一条报数字的规矩：分布既要报原始值，也要报 `1 - (1-p)^10`——
> **一个玩十世的人实际会看见什么。** 没人会去刷两千遍。
> 但这是一条关于**报什么**的规矩，不是关于**跑几世**的：
> 换算出来的那张表，精度是原始那张表给的。上面晃，它跟着晃。

#### 最稀的那一格未必是最显眼的那一格

`portrait.ts` 跑全套时红了，而它跟当轮改动一点关系没有——**它本来就每五次红一次。**

这一支要看的三件事里，最显眼的是「资质其实很好，却一辈子没人告诉过他」——
那一格是它存在的理由。可它三成上下，从来不缺样本。真正稀的是另一格：

```text
听过修士评价      1.3%      肯开口的修士本来就是稀客
```

而它守的三条判据里有两条挂在这一格上。三百世期望三个人，落空率 5%；
第一节另起一个一百五十世的循环去捞同一种人，落空率 22%。两处叠起来，
**三成的批次会红**，而每一次红都长得跟真的坏了一模一样。

修的时候顺手撞见另外两件事：

**一、那个用来推算世数的比例，本身就是噪音。** 三百世那批报的是 1.0%，
照它推「七百世该有七个」。真跑七百世，报 0.4%。跑一千二百世，两批都是 1.3%。
**拿三个人量出来的比例去推该跑几世，推出来的数带着三倍的误差。**

**二、第一节那个循环整个是多余的。** 它另跑一百五十世只为捞一个展示样本，
而统计那一轮已经跑了三百世、见过更多的人。同一批人生跑两遍，第二遍还跑得更少。
现在从统计那一轮里顺手留下头一个符合的人，**一世也不多跑，样本反而大了四倍**。

更要紧的是它判红这件事：「捞不到样本」和底下「一个人也没听过修行方面的评价」
判的是同一件事，只是用了个更小的样本。**同一件事判两遍，先响的一定是粗的那一遍。**
取样是取样，判据是判据——捞不到样本只该少印一段，不该红。

于是这一支成了全套里最慢的，一千二百世将近两分钟。换掉的是那三成假警报。
**一支五批响一次的门禁，比没有门禁更坏——它教人把红灯当噪音。**

## 视觉约定

设计令牌都在 `src/styles/main.css` 的 `@theme` 里。颜色直接参与信息层级：

- 浓墨 `#23201c` —— 标题、关键信息
- 墨色 `#3d3934` —— 正文
- 淡墨 `#6f6860` —— 次要信息（对比度 4.6:1，达 WCAG AA）
- 极淡 `#a89f92` —— 框线陪衬、树状连接符，不承载文义
- 朱砂 `#9d2f26` —— 关键、危险、当前所在、未读

排版走古籍：宣纸底、双栏框线、印章收尾、`└─` 树状子条目。
但状态栏、面板栏、选项区都有明确边界和状态反馈 —— 它得看起来像个界面，不是一篇散文。

不用角色立绘、地图、装备图标、技能图标。`prefers-reduced-motion` 下所有动画降级。

## 已知边界

### 后半生薄，而这是明写的缺口

一生现在从出生跑到咽气，可**十七岁之后年表几乎是空的**——七十二件事件里
绝大多数封顶在十六岁。成年、壮年、老年那三卷日常眼下独自撑着人生后半段
（六千世里一共停了上万回）。人生的形状在，血肉还不够。

反过来，启蒙和少年那两档日常几乎没人停得到（六千世里各只有十来世）：
七到十六岁那几年年表塞得太满，候选池难得空一次。**两头的稀薄是同一件事
的两面——内容全压在前十六年。**

第三个佐证在日录上：一辈子六十来年，日录只攒下二十来条
（`scripts/diary.ts` 中位 26）——**跟人生还停在十六岁那会儿一条不差**。
「一天」那一章的窗口也是七到十六岁，后半生连一天都记不下来。
这个数不是没在长，是根本没有东西可长。

### 别的路还只有一条

世界里当然不止修行一条超凡的路：武道、医术、术士、方技、机关、炼器、
阵法、道门、佛门、民间秘术，都还没写。

**但不会先造一个「超凡体系框架」再往里填。** 那样第一个填进去的东西
会被框架的形状扭一遍。等第二条路真写出来了，再看它和渡口共用什么。
`scripts/lifelong.ts` 那份修行卷名的名单眼下只有一行，届时加一行，
判据一个字不用改。

同理**不会做成职业系统**：不会出现「请选择：剑修 / 法修 / 武修 / 医修」。
道路是人生自己长出来的——识字的人才有替人写算那一条，身子骨结实的人
才走得动远路，听说过修行的人才会接着打听。**一个没读过书、没出过村、
没听人提过修士的人，打开成年那一卷只有守着地和出门做工两条，
那正是他这一生挣来的选项数。**

### 内容层还欠着系统层

架构已经允许「弃儿、长姐当家、老乞丐养大」，但**内容层的世界观还停在传统家庭上**。
`{elder}` 把硬编码的称呼抽掉了，可那些正文的**内容**仍是照着有爹娘的人生写的——
老乞丐不会「每天傍晚去地里站一会儿」。

真正的解法是给不同抚养结构写专属剧本，那是内容量的问题，不是架构问题。
在那之前，`scripts/verify.ts` 至少保证不会穿帮。

### 刻意不做的事

- **不做 NPC 全人生模拟。** 现在已经有时代、区域、家庭、NPC、关系、认知、
  观察者、事件八层，再给每个 NPC 加日程、职业、收入、消费、情绪、目标，
  很快就会变成一个 NPC 社会模拟器——那不是这个游戏要解决的问题。
  NPC 目前只需满足一条：**他是一个持续存在的人，不是一次性剧情变量。**
  他每天几点吃饭，以后再说。
- **不做早夭概率。** 天年在出生那一刻掷定，此后只由具体的一卷用
  `{ type: 'lifespan' }` 削（老年那一卷的「再走一趟远路」扣两年）。
  哪天写出一场真正凶险的病或荒，由那一卷自己把天年削到当年——
  **不靠年表随手抽一件「你死了」。**

### 下一步：让玩家也能改变世界

世界已经会自己发生事情了（`worldclock`），但目前只有一个方向：

```text
大旱 → 粮价上涨 → 家里紧起来 → 你被送去做工 → 书念不成了      ✅ 已经跑通
玩家成为修士 → 回乡 → 解决水源 → 农业恢复 → 别人的人生改变    ⬜ 还没有
```

### 别的

- 碰上修行之后就没有后续了。炼气、宗门、师承、丹器都还没有——
  渡口那一卷演完，人接着过他的日子。
- 「说亲」那一卷（相看、议聘、退婚）没写，所以成年那一卷里配偶的姓
  暂时写死一个「秦」。那个姓本该由那一卷自己掷。
- **只有农户有完整的破落链。** 猎户、匠户、商户、客栈这些家道中落该长什么样，
  还没写。它们现在只有各自的行当机缘。
- 性别只在两处真正分岔：宗室封号，以及「本朝女子不应举」。
  别处一律不分——不是因为古代女子的人生和男子一样，而是因为写一半比不写更糟。
- `Condition` 只有 AND，没有 OR 和否定。需要「非」时得靠 `branches` 兜底分支，
  或者反过来在正向路径上留一个旗标（`riverman` 的「支开跟着的人」就是这么绕的）。
- `chronology.ts` 的链优先是「只要链上有候选，散事件全无机会」，等于链上那件事必然发生。
  所以父亲的生死、宫墙塌不塌，都改成提前用 `roll` 掷定——这是绕过去的，不是解决掉的。
- 没有单元测试。`scripts/` 下那四十一支可执行脚本顶了大部分回归的活，
  但它们查得出「跑不通」和「比例不对」，查不出「某一句话写错了」。
